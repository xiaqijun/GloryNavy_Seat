# EVE Sentry 接入：GloryNavy_Seat 侧方案

状态：2026-10-01。第一阶段“本站侧密钥申请”和 EVE Sentry 远端专用密钥投影端点已实现并配置生产，包含私有迁移、一次性明文、哈希存储、吊销状态、审计、账号合并参与方和受保护页面/API。114 上的 EVE Sentry、`seat.kisectool.com` HTTPS 集成反代和 Seat 服务端令牌已通过无令牌 401 与带凭据参数校验。exchange Goose 58 已加入时间额度预留/结算/释放/退款底座；Sentry 时间授权、投递/消费游标、状态映射和 River 对账 worker 已实现，正式价格通过生产环境变量提供，但 `SENTRY_ALERT_CONSUMPTION_ENABLED` 默认关闭，隔离生产账号和真实币账现场验收未执行。对应的 EVE Sentry 草案位于另一仓库的 `docs/seat-integration-plan.md`。

已与 EVE Sentry 项目会话核对现状：当前虽有持久状态游标和内部波次 ID，但 SSE 没有可直接收费的稳定时间使用证据；现有 `ack_alert` 是人工确认报告，不是客户端使用回执。Presence/OCR 的客户端身份尚未可靠绑定平台 `key_id`，预警质量也缺独立真值和可归因的修订链。因此本方案的时间计费、质量加成和平台密钥均属于**待开发接口**，不能直接接现有日志上线。

## 目标与边界

本站作为成员身份、密钥生命周期与果壳币结算的管理端；EVE Sentry 服务端负责密钥实际验证、监控/预警状态、预警质量评估和服务端使用证据。**提供有效监控可获基础果壳币；独立核验通过的新敌情波次可另获事件奖励；使用预警消耗果壳币。**本站不接收截图、OCR 原文、敌情或 EVE SSO 令牌，不重算实时预警，也不由浏览器提交使用秒数、质量分或币额。接入不增加 ESI scope。旧 Sentry 密钥在迁移期按其原系统规则运行，不自动认领本站账号、不计入新收益或收费，也不补发历史币。

交付分四步，允许独立停用：①密钥管理；②监控质量与预警事件记录只读对账；③监控奖励；④按有效预警使用时间扣费。前两步可上线而不启用结算。同一密钥可拥有一项或两项权限，但具备监控权限不自动得币，具备预警权限也不自动扣币；两项结算均以实际服务端证据和已启用政策为准。

## 密钥管理与跨服务操作

本站已实现的第一阶段 API：`GET/POST /api/v1/sentry/keys`、`DELETE /api/v1/sentry/keys/{id}`、`POST /api/v1/sentry/alert-grants`、`DELETE /api/v1/sentry/alert-grants/{id}`，以及本人只读的 `GET /api/v1/sentry/alert-usage`、`GET /api/v1/sentry/alert-consumptions`。密钥创建请求包含名称、`monitor|alert` 权限集合和 UUID `request_key` 幂等键；预警授权请求只提交密钥、秒数和请求键，费率由服务端冻结配置提供，先在 exchange 预留果壳币再投影到 Sentry。管理员或成员均只能通过本站会话访问自己的密钥和授权。收益、管理员配置及完整使用证据仍待协议冻结后实现；当前已提供投递/消费游标对账端点及 Seat 侧状态映射 worker。

本站在服务端生成高熵随机明文和不可变 `key_id`，只持久化哈希、前缀、权限、账号归属、状态、操作 UUID 与远端版本。明文只在确认远端已创建后的一次 `no-store` 响应中返回；前端只保存在当前页面内存，不写浏览器存储、URL 或日志。若响应遗失，不能找回明文：使用相同 `request_key` 直接重试远端幂等创建，确认孤儿密钥后再吊销并重新创建。远端操作先在本站持久登记，再在数据库事务外发起；重试不能因相同操作创建第二个密钥，不在数据库事务中等待网络。

第一阶段的远端投影协议为后端到后端调用：`POST {SENTRY_INTEGRATION_URL}/api/v1/integrations/seat/keys` 和 `DELETE .../keys/{key_id}`，使用服务端专用 Bearer 凭据、`Idempotency-Key` 与 JSON 请求。本站发送 `operation_id`、`key_id`、`account_id`、`key_hash`、前缀、用途与版本，不发送明文；Sentry 只保存哈希并按 `operation_id` 幂等投影，返回 `key_id` 和协议版本后本站才把状态置为 `active`。配置要求是 HTTPS origin（本机开发可用 localhost HTTP）和至少 32 字符的服务凭据，均只在服务端环境文件中配置。生产入口使用 `https://seat.kisectool.com`，仅将该路径反代至 114；真实成员创建、超时重试、吊销和错误契约仍待现场联调。

状态为 `creating → active → revoking → revoked`，结果不明保留明确的待同步状态，不伪装成功。吊销先在本站停止新收益资格，再要求 Sentry 禁用密钥并断开其 SSE；失败持续重试及对账，历史使用/收益记录不删除。远端 `key_id`、版本和操作结果需回传，不接受仅靠前缀匹配。内网集成使用独立轮换服务凭据、受限来源、签名/时间窗/nonce 或等效防重放；服务凭据只由后端从权限受限文件读取，绝不下发浏览器或放进 River 载荷。

密钥认证可用性与收益资格分别定义：Sentry 的本地验钥和平台失联时的认证租约属于 Sentry 契约；本站证据水位过期或对账异常时**暂停新收益结算**，不能因停发币擅自宣称监控已停止。正常联通时吊销应立即拒绝新请求、断开 SSE；网络分区时只能承诺协议约定的最长延迟。两仓验收须分别覆盖这两种情况，不把“立即吊销”写成无条件保证。

## 使用证据、归属和同步

仅接受 Sentry 服务端签发的按 `key_id + 用途 + UTC 分钟` 记录的秒级区间或 60 位位图，包含单调游标、分钟修订版本和服务端时间。本站保存原始版本/游标以及派生的账号级有效秒数；不接收客户端上报的累计时长。监控按账号对重叠密钥/设备逐秒去重；零敌对的有效监控仍可计时。普通 Web、机器人和非 alert 消费者的 SSE 不计付费预警使用。Sentry 必须提供明确的用途证明，不能仅把 SSE 写出成功等同于真人阅读或消费成功。

**质量判断放在预警侧。** Sentry 拟新增带版本的服务端质量证据：监控覆盖及连续性、数据新鲜度、识别结果的可核验反馈、异常标志，以及质量分形成依据。本站只接收聚合指标、分数、证据 ID、归属监控密钥与政策版本；不接收原始画面。现有预警事件的 `primary_client_id` 不足以证明贡献密钥；须先把 Presence/OCR 客户端身份与认证 `key_id` 绑定，再形成波次到监控贡献的归因链。漏报/误报须有独立、可审核的标注来源，不能由奖励领取人单方评价。没有敌情、没有足够反馈的时段不按“零质量”处罚，也不按原始 OCR 命中数、打开窗口数或制造预警数加奖；归因或真值不可靠时仅按基础有效覆盖时长给基础奖励，质量加成和事件奖励保持关闭。对于同账号重叠秒，只取一个有证据的贡献及其对应质量，不叠加多开分数。具体质量指标、权重、最低样本量、复核周期与迟到纠错在两仓协议中版本化。

共享 River 周期任务从受限远端按游标分页读取，建议每分钟；任务载荷仅含本地 ID/水位，不含密钥。远端时间区间保留期、分页上限、完整性标记及断点重放须写入双方契约；游标必须指向已提交且连续的区间前缀，不能以可能回滚留洞的数据库序列直接判断缺口。一次平台事务内更新区间/质量版本、游标、受影响 UTC 日的账号并集和来源权益；失败不推进游标。重复区间无额外发币或扣费，版本倒退、序号缺口、超过远端保留期或来源不完整时暂停该批并显示对账异常，不把缺失当作零秒。迟到的质量修订重算受影响日，向 exchange 提交奖励差额，已消费的冲正沿用欠额规则。预警使用的时间证据、最终结算与退款也必须有唯一服务端引用，不能凭本地页面访问记录计费。

## 两端对账协议

两项目不共享数据库，也没有跨库事务。Sentry 是**密钥实际状态、监控区间、质量修订、预警投递与收件确认**的事实源；本站是**账号归属、费率/单价版本、果壳币预留与流水**的事实源。本站每次只在本地事务内提交“镜像证据版本＋游标＋应得/应扣差额＋ exchange 流水”，对 Sentry 的授权/吊销通过持久操作 UUID 异步投影。两端接口均按专用服务身份鉴权，事件带不可变 ID 和修订号；重试可以重放，不能再次结算。

| 对账对象 | 共同核对键 | 正常一致条件 | 不一致时 |
| --- | --- | --- | --- |
| 密钥 | `operation_id/key_id/version` | 本站期望权限、归属与状态等于 Sentry 实际验钥投影；吊销以远端确认版本为准 | 重试同一操作，保持待同步；过租约后拒绝未知/已吊销密钥，不凭本站 UI 状态宣称远端已停用 |
| 监控覆盖奖励 | `key_id + UTC 分钟 + revision`、质量证据 ID、权益引用 | Sentry 已提交区间/质量版本完整；本站逐秒去重、按政策版本重算的累计加权单位等于 exchange 对同一权益引用的累计单位和差额流水 | 停止受影响日新发放，补读/重算后只记差额；缺口、版本倒退或超出远端保留期转人工核验 |
| 监控事件奖励 | `wave_id + policy_version + account_id`、贡献证据 ID | 同波次奖励池固定；本站去重账号后计算的份额之和不超过池额，exchange 按稳定引用留痕；预警接收者数量不改变奖励 | 归因、独立复核或波次版本不完整时暂不发；误报撤销按原引用冲正，不改写旧流水 |
| 预警时间扣费 | `grant_id + account_id + interval_id`、`delivery_id` | 每个有效区间有有效授权、服务端时间证据和客户端使用确认；本站按冻结的时间单位与价格结算秒数。每个授权的原预留金额 = 净时间扣费 + 尚占用金额 + 已释放/退还金额 | 有确认无扣费时按原引用幂等补结；有扣费无证据时先冻结该引用并核实远端提交水位，不能因暂时没拉到记录就退款；无效区间按原引用冲正 |

增量拉取使用 Sentry 返回的 `committed_watermark`、`earliest_available_watermark`、分页游标和结束标记。本站仅在完整消费一个已提交前缀后推进自己的水位；窗口未闭合或仍可能有迟到修订时显示“待对账”，不把当前零条当作最终零条。建议每分钟增量同步、每 15 分钟按授权及最近日期重算差异、每日复核最近 48 小时；这些是实施期压测后确定的目标节奏，并非现有定时任务。Sentry 另提供按 UTC 日/授权的记录数、最高修订和规范化证据摘要，供本站与已镜像明细交叉核对；摘要不代替明细和原始游标。

后台保留每次对账的两端水位、差异类型、首次/最近出现时间、重试次数与处理人。自动修复仅限可证明的漏拉、幂等重放和按原引用差额/退款；身份归属冲突、不可恢复的历史缺口、服务端 ACK 与币账互相矛盾时停止相关账号或授权的新结算并人工处理，不重写或删除历史流水。余额、预留、消费与退款仍以 exchange 为准；Sentry 只知道获授权的时间额度，不持有或回算本站币余额。

账号合并使用数据库确认时间为分界：**分界前**的监控证据保留原账号归属和已发权益，不追溯重算或收回双方重叠时段；**分界后**的证据按目标账号跨所有密钥取并集。跨界分钟按服务端秒级时间拆分。迟到事件按发生时有效的归属分段，入账前锁活跃目标账号并复核合并映射；不得依密钥“当前归属”改写历史秒数。日上限在合并后计入双方当日已获有效秒数，超出上限的既得历史不冲正，但合并后不再增加。权益引用使用分配一次的不可变 ID，不由当前账号 UUID 拼接，以免合并后键碰撞。合并预览包含密钥、待同步操作、证据、奖励权益和未结预警预留指纹；未结预留须先结算或退款，合并预览/提交在此期间拒绝，避免同时转移额度和重复扣费。迁移原始归属与币账仍由各自模块完成，不重新发币或扣费。合并提交后的远端归属投影由持久操作异步同步，失败显示待同步。

## 果壳币奖励、预警扣费与精度

监控基础奖励使用固定来源 `sentry_monitor`，默认**关闭发放**。以秒级去重贡献及预警侧可归因质量构成加权权益。建议质量用 `0–10000` 的整数权重表示，每日各政策版本累计 `有效秒 × 质量权重` 后，计算 `floor(加权值 × 每小时奖励最小单位 / 36,000,000)`，币最小单位为 0.01，避免逐分钟舍入；基础质量门槛与加成范围在政策中明确，避免没有可评价事件就无法获得任何奖励。先按 UTC 日取账号级并集和日上限，再按发生时生效的政策版本分段。只读灰度期和旧密钥历史不补发。质量修订可产生正负差额，既有权益不随管理员改比例而重算。

事件奖励另用固定来源 `sentry_monitor_event` 和独立开关。一个经独立证据或人工复核确认的新敌情波次形成**固定的总奖励池**，不是每个监控设备或每个预警接收者各发一份。Sentry 提供波次 ID、核验版本、贡献监控 `key_id`、首次有效发现时间与质量证据；本站按发生时账号归属去重，同账号多开只占一个贡献名额，再按版本化贡献规则分配池额，所有账号份额总和不得超过池额。分配可参考及时性和识别质量，但不能仅以“抢先报一帧”获奖；不能独立核验或不能可信归因的波次暂不发事件奖。成员是否购买或收到预警不影响监控者获奖，同一账号自行接收也不增加奖励。每个账号用 `wave_id + 奖励政策版本 + 原归属账号 ID` 形成稳定权益引用；误报/归因修订按原引用差额冲正。事件池额度、分配规则与每日账号上限由管理员配置，默认关闭。

现有 `exchange.EditSource` 不允许把 `minor_per_unit` 设为 0；灰度使用 sentry 发放开关。现有 `ReconcileTx` 在来源引用**首次实际兑换时**取当前比例；旧时段迟到可能套用新比例。正式发币前 exchange 必须提供受信任来源可引用的费率版本/快照契约，分别校验覆盖加权单位与事件池份额的比例尺及总池额；sentry 不能传任意币额或直接写币账。每次重算用稳定权益引用和前后累计单位提交差额，旧引用沿用冻结费率；手动兑换入口不得绕过生效时间、质量条件或上限。

**预警属于币消费，不能复用兑换订单，也不能伪装成负奖励。** 当前 exchange 余额的 `Spent` 只统计已完成兑换订单，账本 kind 也没有通用服务扣费；实施前要在 exchange 内新增仅供受信任 sentry 服务调用的预留、结算、释放/退款契约及唯一业务引用，余额、可用额和流水同时纳入预警消费。预留与其它兑换共用余额锁和非负可用额校验。监控奖励只在已提交入账后可用于预警，不能按尚未同步的质量分预支。

已确认**按有效预警使用时间扣费**，不是按事件数量或订阅期。Sentry 输出带 `interval_id` 的有效 UTC 秒级区间，区间包含服务端规则版本、授权 `key_id`、连接/交付证据和客户端使用确认；同一账号多密钥、多设备、重连重放及重叠区间先逐秒去重，再按冻结的 `unit_seconds + unit_price_minor` 结算。当前部分规则只在客户端本地生效，须先统一到服务端或把相同规则版本作为可核验的使用条件；仅有 SSE 写出、worker 本地缓存或人工 `ack_alert` 均不算可收费时间。客户端确认仍非真人阅读证明，须与服务端时间证据共同校验。无效、撤销或无法归因的区间按原引用冲正退款，保留原扣费和修订链。区间边界、迟到确认、UTC 跨日和账号归属变动规则须在两仓契约中冻结。

收费资格分四关，均由 Sentry 输出带规则版本的证据，本站只核对并结算：①**来源有效**，监控密钥仍有效、采集正常、上报时间新鲜且位于允许的监控范围；客户端自称在线不算。②**识别可信**，敌对识别通过可配置置信阈值，且由连续有效采样或独立证据复核；单帧噪声、缺失/异常画面和无法归因的秒数先不收费。③**时间有效**，该秒位于服务端形成的有效预警区间，未被静音、过滤、去重或撤销；重放和同一秒的多路副本不重复收费。④**确实由软件使用**，有服务端交付记录和客户端 UI 处理后的幂等使用确认，且对应账号有未过期的预付时长额度。四关缺一则不得最终扣费；“识别可信”也不等于已证明游戏世界的客观真相，成员可申诉，复核误报后按原区间退款。置信阈值、连续采样间隔、独立复核渠道和申诉时限待业务确认并版本化，不在客户端自行决定。

为避免等复核时错过敌情，Sentry 可先推送明确标记为**免费、待确认**的候选提示。候选提示不能事后追扣；四关达到收费资格后，须形成明确标记为收费的有效时间区间并取得其独立 UI 使用确认。区间修订链建议为 `candidate → pending_review → eligible → delivered → confirmed`，误报/撤销进入 `revoked`；本站只对 `confirmed` 且仍有效的秒数结算。

**Sentry 先取得账号级有限时长额度、有限有效期的已付授权，再允许收费预警运行**，不能靠每分钟异步拉取后无限追欠。本站按配置的 `unit_seconds + unit_price_minor` 预留最多 N 秒的币额；Sentry 在形成收费区间前原子占用对应秒数并记录 `interval_id + account_id`，同账号另一连接的重叠秒复用原额度，不能并发超额。未确认的区间释放其秒数和对应币额；确认后本站按实际去重秒数结算。额度用尽就暂停付费预警，续期需本站再次成功预留。断网时已有授权仅运行至到期或额度耗尽，不继续新增额度。授权结束后未使用额度释放；余额不足时暂停付费预警，监控和已赚余额不受影响。若断联使区间确认与结算状态不明，预留保持占用并进入对账，不先退款再允许重复消费。价格修改只影响新授权，授权及区间冻结当时的时间单位与价格。具体单价、时长、有效期和使用确认超时待业务确认，均不预设为生产默认值。

使用证据只能证明密钥客户端与服务端交互，不能证明真人始终看屏幕或画面真实。生产首次奖励采用低额日上限、已绑定 EVE 角色门禁和异常并发审计；预警扣费则先在测试账号与有限预付额度灰度。质量评分和价格都要展示所用政策版本，不能因后续编辑追改已结算账目。

## 建议数据与 UI

拟定模块私有表：`sentry_keys`、`sentry_key_operations`、`sentry_usage_events`、`sentry_usage_cursor`、`sentry_quality_evidence`、`sentry_entitlements`、`sentry_alert_grants`、`sentry_policy_versions`、`sentry_audit`。具体列与约束实施时定稿；密钥哈希/前缀、原始归属、服务器事件/质量版本、账号归属分界、权益引用、预警授权引用、发放/收费开关及操作幂等必须持久化。币余额、预留、扣费、退款和流水留在 exchange 私有表，不复制到 sentry。

当前 `/sentry` 只实现一张密钥卡片；后续监控收益与预警消费按下述只读方案扩展，不把旧版“创建弹窗/密钥列表”描述当成现状。页面沿用现有后台规范；管理员配置留在本页，不塞进 PAP 设置。手机单列、桌面按内容分区，固定文案使用 `msg` 中英文词表，日期使用当前 locale；具体排版见 `docs/ui/sentry.md`。

### 预警消费展示方案（2026-10-01，第一期只读账单已实现）

**用户支付的是果壳币，时间仅是计价依据。** `/sentry` 不展示“总授权额度”或把授权秒数做成第二种钱包。主摘要展示当前果壳币可用余额、预警暂占果壳币、累计预警净消费、累计预警退款；兑换占用与兑换消费在 `/exchange` 单独标明，不混入“预警”指标。每笔有效预警记录再给出起止时间、持续秒数、授权时冻结的每 `unit_seconds` 秒单价、该笔果壳币金额和状态。金额统一使用 exchange 的 0.01 币最小单位，时长不得从浏览器推算为应扣金额。

授权是后台为防止透支所做的有限时长预付占用：创建时 exchange 记一笔 `alert_reserve` 币流水，已确认区间从暂占转为已消费，结算时不再记第二笔负数流水；未用金额释放或无效消费退款时记正数流水。因此预警账单从 `exchange_alert_grants` 与 `exchange_alert_charges` 的当前状态读取，不能只把 `exchange_coin_ledger` 的负数求和当成实际消费。页面区分“暂占”“已结算”“已释放”“已退款”，累计净消费仅统计仍处于 `settled` 的区间，退款单列展示，不把历史退款再计入消费。每个授权显示价格版本与到期时间，秒数及内部授权 ID 放在记录详情而非主指标。跨多个授权的汇总以同一数据库快照查询，避免余额与明细短暂互相矛盾。

新增受保护的本人只读 `GET /api/v1/sentry/alert-usage` 与游标分页 `GET /api/v1/sentry/alert-consumptions`，并已接入 `/sentry` 的摘要、筛选、详情和游标翻页；由宿主向 sentry 注入 exchange 只读服务，不导入其私有 store。服务端从当前会话确定账号，不接受浏览器传入的账号或币额；将来管理员跨成员读取须逐次校验当前站点管理员身份、目标账号存在及归属。列表支持状态和时间范围筛选，默认按发生时间倒序，稳定游标包含排序键与记录 ID。返回币额均为整数 minor，区间时间使用 UTC；响应标明采集时间。即使收费开关关闭，已发布迁移后的历史记录仍可只读查看；无记录时显示空态，不生成虚构余额或消费。

首期从 exchange 的本地授权、区间和币账读取可核对的金额、时间及状态；未进入区间的授权余额到期/吊销后释放时，作为授权级资金记录展示，不能误称为一次“预警消费”。Sentry 的 `delivery_id`、ACK、事件规则/质量和撤销证据目前仅供服务间游标对账，尚未形成可供成员安全读取的本地镜像；首期账单不声称显示这些详情。若要展示“客户端已确认”、事件/星系及退款依据，先增加 sentry 私有证据投影与必要迁移，按稳定引用关联 exchange 区间并校验版本、水位与账号归属，再开放详情；远端临时不可用时仍显示本地账单并标注证据待同步。对账滞后只在异常时提示，管理员异常列表另行实现。

`/exchange` 的果壳币流水现已识别 `alert_reserve`、`alert_release`、`alert_refund` 并提供到 `/sentry` 的入口；结算状态由预警账单呈现，不能为了凑一条“扣费流水”重复写负币。兑换与预警金额仍按流水类型分项展示。管理员跨成员读取与更完整的关联详情继续留在后续权限范围内。

交付顺序：① 已完成 Goose 58–60、只读 API、`/sentry` 摘要/分页账单、`/exchange` 流水标签和币额一致性测试；② 已完成新客户端 ACK 和服务端证据镜像联调；③ 因无隔离生产账号，真实账号/释放退款现场验收暂缺；④ 正式价格由生产环境变量提供，是否开启收费灰度需另行接受未完成实账验收的风险。收费开关在风险未明确接受前保持关闭。

## 分期交付与验收

1. **契约与密钥管理**：先冻结 Sentry 的端点权限表、签名、幂等、状态/租约和错误契约；本站新增模块、合并参与方、受限配置、密钥页面及审计。旧密钥不自动迁入。验证本人/管理员对象范围、重复创建、响应遗失、吊销与远端断联。
2. **只读证据**：Sentry 先补认证 `key_id` 到 Presence/OCR 的归因、稳定波次计费 ID、UI 处理后的收件回执、已提交连续游标与质量修订；本站上线持久同步、账号级并集和异常页面，至少完整观察一晚。验证零敌对、双设备/多窗口、SSE 正常重连、UTC 跨日、质量反馈归因、迟到更正、缺口/保留期及账号合并；此阶段不写果壳币。
3. **监控奖励**：先实现 exchange 费率版本契约与 `sentry_monitor` 基础来源，测试账号启用低额政策；事件来源 `sentry_monitor_event` 待独立归因/核验和奖励池约束通过后另开开关。验证权重/比例变更、无可评价事件、同波次多贡献者、旧时段迟到、重复事件、误报冲正、上限和合并，再分别开启生产奖励。不对灰度前数据补币。
4. **预警时间扣费**：exchange 服务的时间预留/结算/释放/退款、Sentry 有限时长授权与投递游标对账 worker 已实现并由 `SENTRY_ALERT_CONSUMPTION_ENABLED` 门控；价格和授权参数由生产环境变量提供，ACK/使用证据已完成，余额不足、并发兑换、未确认区间、多端重叠、重连、断网、部分时长释放、无效区间冲正、账号合并阻塞及到期停用已有代码回归，但没有隔离生产账号可做现场实账验收。未明确接受该风险前不得开启付费预警。

每期需要模块私有 SQL/Goose、River 生命周期、OpenAPI、中英文接入说明、UI 页面记录及自动化测试同步交付。迁移前备份；一旦出现新密钥、使用事件或币流水，不可回退到不识别新数据和来源的旧程序。停用发放不删除历史账目，停用 UI 仍保留合并和旧任务兼容。
