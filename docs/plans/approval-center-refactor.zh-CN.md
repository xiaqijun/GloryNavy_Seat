# 审批中心统一读模型重构方案

状态：P1 已发布生产（2026-10-09）；索引列表已启用，来源读取回退保留。P2 双读诊断已实现并持久化但默认关闭，P3 已提供账号白名单开关，列表路径已加入 5 秒授权范围缓存（共享相同适配器，独立 `IndexAccess` 隔离），待管理员真实会话比对后再进入灰度。

目标：让补损、成长福利、奖励兑换、贷款以及后续审批流都进入同一个审批中心列表，同时保留各业务模块对规则、状态、合同和账务的最终所有权。

## 结论

需要重构审批中心的读取路径，但不把福利、兑换或贷款的完整业务数据搬进审批模块。

当前审批中心已经统一了页面入口，却仍是运行时聚合器：每次列表请求都会分别调用各来源的授权、范围、查询、计数和名称投影，再在内存中排序分页。来源越多，首屏耗时和部分来源失败的概率越高；新增来源还会继续增加 `Source` 条件、来源级异常和特殊展示逻辑。

重构后采用“审批索引 + 来源详情”的结构：审批模块拥有轻量、可检索的列表读模型；来源模块仍拥有原始单据、审批状态、业务规则和写操作。列表只查审批索引，详情和决定再回到来源模块，并重新做对象级授权。

## 当前问题

当前 `internal/modules/approval.Service.List` 的调用链是：

1. 并行调用每个来源的 `Access`。
2. 对允许的来源执行来源私有 SQL，并同时计算分类计数。
3. 合并各来源的第一页结果，在审批模块内存排序和生成跨来源游标。
4. 调用账号名称服务补全申请人。
5. 前端再读取批次、详情和名称增强数据。

当前实现有四个结构性问题：

- 列表读取成本随来源数量线性增长，任一来源慢都会增加首屏等待。
- 每次分页都重复执行授权范围、来源计数和名称投影；完整计数尤其容易扫描大集合。
- 来源不可用只能在请求结束后标记，中心无法区分“没有数据”和“来源暂时没有响应”。
- 新审批流需要修改来源注册、类型标签、状态映射、详情分支和错误映射，扩展点不是真正的注册式接口。

最近的按需加载和刷新降频只能缓解请求数量，不能消除运行时 fan-out 的基本成本。

## 目标边界

### 审批中心拥有

- 统一列表索引和分页游标。
- 来源标识、审批类型、摘要标题、申请人账号、军团、金额、状态桶和时间。
- 列表级搜索、筛选、排序和计数。
- 来源同步状态、最后成功时间和可重试错误。
- 统一的列表展示协议和扩展能力声明。

### 业务来源拥有

- 原始申请、订单、贷款案件及其完整 payload。
- 审批规则、资格、额度、合同、物品快照和币账。
- 批准、驳回、取消、发放、担保、抵押等写操作。
- 详情读取时的最终对象级授权和版本校验。

审批索引不是第二套审批状态。索引中的状态是列表投影，来源状态永远是决定依据；索引落后时，详情和写操作必须以来源最新状态为准。

## 目标架构

```text
业务来源（welfare / exchange / loan / future source）
        │
        ├─ 原业务事务提交
        ├─ 来源事件或变更通知
        └─ 周期性对账 / 回填
                │
                ▼
      Approval Projector（审批索引写入器）
                │
                ▼
      approval_items（轻量列表读模型）
                │
                ▼
      /api/v1/approval/items（统一列表）
                │
                ├─ /items/{source}/{id} → 来源详情
                └─ decide → 来源写服务并重新鉴权
```

来源模块不导入审批模块的私有 store。宿主通过接口注入投影器；同步、重建和对账由 approval 模块自己的服务和 River 作业负责。

## 列表读模型

建议新增 approval 模块私有表 `approval_items`。第一版只保留列表需要的字段：

| 字段 | 作用 |
| --- | --- |
| `id` | 审批索引主键 |
| `source`、`source_id` | 来源和来源单据 ID，建立唯一约束 |
| `source_version` | 来源版本，防止旧事件覆盖新投影 |
| `account_id` | 申请人本站账号 |
| `corporation_id` | 列表筛选和授权范围 |
| `kind` | 福利、兑换、贷款或扩展类型 |
| `bucket` | pending / fulfillment / exceptions / history |
| `state`、`status` | 当前展示状态 |
| `history`、`processed_by` | 保留历史页与“我的审批”过滤语义 |
| `title`、`reference`、`recipient` | 搜索和摘要展示 |
| `amount_minor`、`unit` | 金额摘要，不保存账务明细 |
| `occurred_at`、`processed_at` | 申请和处理时间 |
| `actions` | 当前投影可展示的动作提示，最终动作仍由来源复核 |
| `summary` | 小型 JSON 摘要，不放完整奖励、合同或审计记录 |
| `projection_state`、`projection_error`、`projected_at` | 同步观测和故障恢复 |

索引不保存奖励物品全集、合同明细、贷款分期、抵押证据或完整审计。用户打开详情时才读取这些数据。

建议索引：

- `UNIQUE(source, source_id)`；
- `(bucket, occurred_at, id)`；
- `(bucket, processed_at, id)`；
- `(corporation_id, bucket, occurred_at, id)`；
- `(account_id, bucket, occurred_at, id)`；
- `(source, state, occurred_at, id)`。

搜索先支持编号、标题、接收角色和申请人账号的结构化条件；模糊全文搜索另行评估，第一版不在每次请求中对完整 JSON 做 `lower/strpos` 扫描。

## 来源扩展接口

审批中心不再为每个来源添加条件分支，而是注册统一适配器：

```go
type ApprovalSource interface {
    ID() string
    Capabilities() Capabilities
    Access(ctx context.Context, user string, filter Filter) (Access, error)
    Detail(ctx context.Context, user string, id string) (Detail, error)
    Decide(ctx context.Context, user string, command Command) error
}

type ApprovalProjector interface {
    Upsert(ctx context.Context, event ProjectionEvent) error
    Remove(ctx context.Context, source, sourceID string, version int64) error
}
```

来源适配器只负责把自己的业务对象转换为摘要和详情；审批中心负责索引、分页和统一响应。新审批流只需注册适配器、声明能力、提供摘要转换和来源决定方法，不修改审批中心主流程。

能力声明至少包括：

- 是否支持批准、驳回、取消审核、发放或批量结算；
- 是否支持军团筛选、申请人筛选和金额展示；
- 详情组件类型；
- 状态到统一 bucket 的映射版本；
- 需要的权限能力。

## 同步和一致性

采用“事件通知 + 周期性对账”的混合方式：

1. 来源事务成功后发布 `created`、`updated`、`decided`、`cancelled`、`fulfilled` 或 `deleted` 事件。
2. 事件包含 `source`、`source_id`、`source_version` 和最小摘要，不包含令牌、合同完整内容或币账。
3. 投影器只接受比当前 `source_version` 更新的事件，旧事件直接丢弃并记录计数。
4. River 周期作业按来源和时间窗口对账，修复丢失、重复或失败投影。
5. 来源暂停时保留上一份摘要并标记 `projection_state=stale`，列表仍明确显示来源状态；不把索引缺失当成“没有审批”。
6. 详情和决定操作不信任索引状态，始终回源做权限、对象存在、版本和自审校验。

第一阶段不要求跨模块事务直接写 approval 表，避免来源模块导入 approval store。事件可以先走宿主注入的投影接口；如果需要严格不丢事件，再为各来源增加私有 outbox，并由 River 重试投影。

## API 和前端调整

保留现有 `/api/v1/approval/items` 和详情 URL，先替换服务端读取实现，避免前端和外部链接同时迁移。响应字段保持兼容，新增可选字段：

- `source_status`：来源当前可用、陈旧或同步中；
- `summary_version`：摘要版本；
- `detail_kind`：详情组件能力；
- `stale`：是否可能落后于来源。

前端调整为：

- 列表只读取一次审批索引；
- 详情按 `source + id` 懒加载；
- 来源详情组件通过注册表懒加载，不在主表组件中堆叠来源判断；
- 计数和列表使用同一索引筛选条件；
- 只在索引同步异常时显示来源状态，不把业务“零条记录”显示成错误；
- 保留现有 320 / 375 / 1440px 响应式表格、弹窗和键盘焦点规范。

## 迁移步骤

### P0：契约冻结和观测

- 固定统一摘要字段、状态桶和动作能力。
- 为现有福利、兑换、贷款记录增加来源查询耗时、计数耗时、名称投影耗时日志。
- 明确每个来源的版本字段和可重建时间范围。
- 不改生产读取路径。

验收：能够按来源拆出 p50/p95、数据库耗时、名称服务耗时和失败率。

### P1：审批索引和投影器

- 新增 approval 私有 Goose 迁移和 store 查询。
- 实现 upsert、删除、版本保护、批量回填和投影失败重试。
- 为每个来源实现摘要转换器。
- 建立全量回填命令和 River 对账作业。

验收：索引与来源记录数量、状态、金额和时间在测试库一致；重复事件不产生重复行，旧事件不能覆盖新状态。

### P2：双读比对

- 列表请求同时读取旧聚合结果和新索引，但只返回旧结果。
- 异步比较排序、分页、计数、权限过滤和来源不可用状态。
- 对差异按来源、字段和版本记录，不在用户页面暴露内部诊断。

验收：代表性数据量下连续比对无未解释差异；来源故障、权限撤销、取消待审和历史记录均有覆盖。

### P3：灰度切换列表

- 管理员按账号或配置开关逐步切换新列表读取。
- 保留旧聚合只作为短期回退，不再作为正常请求的并行依赖。
- 详情和决定继续走来源模块。

验收指标：审批列表 p95 降低至少 50%，首屏接口请求数减少，来源故障不再阻塞其他来源列表；无越权、漏单和重复单。

### P4：移除运行时 fan-out

- 删除正常列表路径中的来源逐一查询、重复名称投影和全量计数。
- 保留来源适配器的详情和决定接口。
- 删除只服务旧聚合的临时条件分支，更新 API、UI 和双语文档。

验收：新增一个模拟审批来源只需注册适配器和投影器，不修改审批中心主查询；回退开关仍能恢复到索引上一版本。

### P5：扩展模板

- 提供新审批流注册模板、摘要转换模板、事件样例、权限清单和测试夹具。
- 新来源必须通过统一的分页、状态、权限、自审和来源故障契约测试。

## 风险与回退

- **索引落后**：列表标记陈旧，详情回源确认；River 对账修复。
- **事件丢失**：来源 outbox 或时间窗口对账补齐；不能靠前端刷新解决。
- **状态映射错误**：双读期间比较 bucket、state、action 和计数；灰度开关按来源回退。
- **权限变更滞后**：列表索引只作为候选，详情和决定再次执行来源权限；权限变更后主动清理相关缓存。
- **新来源注册错误**：来源能力校验和启动时注册检查失败，不能静默出现在列表中。

回退顺序：先关闭新列表读取开关，再停止投影作业，保留索引和事件数据，最后恢复旧聚合读取。禁止回退数据库迁移或删除索引表，避免丢失比对证据。

## 不纳入本次重构

- 不把审批决定迁入中心。
- 不把账务、合同、奖励物品、贷款分期复制到中心。
- 不在中心增加自动批准或多级会签规则。
- 不用全局缓存绕过来源权限。
- 不因新增来源提前开放未完成权限或菜单。

## 当前实现进度（2026-10-09）

- 已新增 `approval_items` 与 `approval_projection_runs` 私有迁移，并通过后续迁移补充 `processed_by`、`history`，支持来源版本保护、来源状态和统一列表索引。
- 福利、兑换、贷款已提供来源私有快照适配器；审批投影器启动时回填，之后按 2 分钟周期对账。单个来源失败会保留其他来源的投影并记录错误。
- `/api/v1/approval/items` 已具备索引读取路径，申请人名称和来源动作在返回页按需补全；详情、决定和对象级权限仍回源。
- 已加入可控双读诊断：索引返回后可在后台运行旧聚合，对比来源集合、计数、下一页游标、分页行的权限字段、状态、处理人、金额、动作和时间，并把筛选、字段原因、来源和版本写入 `approval_dual_read_diffs`，不改变用户响应。统一索引列表的兑换行只读取冻结快照，不再逐行调用 SDE 名称服务。
- 审批上下文与列表已输出不含账号和 payload 的整页及来源级阶段耗时；来源级记录覆盖授权、成员选项、旧查询、索引查询和名称投影，可据此拆分 p50/p95 与失败率。
- 索引存储通过内部接口注入，双读异步比较现在有内存替身契约测试，覆盖索引返回、旧聚合漂移和差异记录；后台比较并发上限为 4，旧聚合失败记录 `legacy_error`；生产组合仍使用 PostgreSQL 索引。
- P1 已在生产启用；当前 `APPROVAL_DUAL_READ=false`，`APPROVAL_INDEX_ACCOUNTS` 为空时全量走索引，非空时按账号回退旧聚合。来源能力声明和启动校验已加入，统一上下文可返回能力元数据；列表响应携带投影状态、摘要版本和详情组件类型，前端通过注册表加载详情，未知来源回退通用摘要。`IndexOnly` 来源可先接入索引投影而不实现旧聚合查询，旧回退会将其标记为不可用并避免空函数调用。仍需用管理员真实会话覆盖各来源、权限撤销、取消待审和历史分页后，才可打开双读并实施 P3 灰度。索引与来源的详情、决定和对象级复核边界保持不变。
