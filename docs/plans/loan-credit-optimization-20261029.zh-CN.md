# 贷款额度优化实施方案（2026-10-29）

## 已确认目标

- 保留一个个人额度；超出剩余额度的部分才需要担保或抵押，抵押按物品估值八折计入。
- 排除同一本站账号有效绑定角色之间的转账；保留外部交易及既有钱包显示口径。
- 消费不直接提升个人额度，按收入及个人资产计算；分别核对证据来源的新鲜度。
- 担保和抵押默认填入剩余缺口，也允许拆分；未接受、未批准或未交付的保障不得计入审批覆盖。
- 审批时根据实际还款期限展示还款能力风险；有风险时由管理员决定，不能因提醒替代实际审批。
- 管理员可配置单人贷款上限，默认不额外限制；已批准贷款和历史审核证据不重写。

## 工程边界

评估由后台生成并保留版本与证据；旧版本快照不能冒充新规则评估。写入仍在账号额度锁、池锁及案件锁保护下重新校验，旧客户端的预期金额与并发冲突语义不改变。抵押选择、物品估价、合同核验和八折下取整继续由服务端裁定。配置调整及审批审计记录均须保存。

上述能力已在本地实现；隔离 PostgreSQL 的竞态及并发测试、Go vet、前端构建和中英文桌面及窄屏交互测试已通过。已发布生产；尚未进行真实游戏合同验收。外部转账仍属于收入，识别范围仅限当前同一账号有效绑定角色之间的直接转账。
