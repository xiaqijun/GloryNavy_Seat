# 意见反馈页面

管理员页头右侧操作组按“提交反馈、奖励设置”排列，480px 以下另起一行并右对齐。奖励配置仅管理员可用。详情参照旗舰补贴审批页：顶部类型图标、标题和状态；两列展示提交人、采纳奖励、提交时间、更新时间，未采纳奖励显示“—”，不推算配置金额。摘要后为编号进度，详细描述与截图保持可见，“处理记录”默认折叠。专用操作固定在共享弹窗底部：管理员采纳/不采纳、开始处理、提交完成；提交人确认完成或填写原因退回。已完成可重开，已关闭可重提。取消任意状态下拉；下方不再设置独立“处理回复”表单；管理员与提交人统一使用“补充说明”次要入口，默认收起，展开后填写文字或截图，按钮为“提交补充”，不改变状态。展开按钮带 aria-expanded/aria-controls，支持键盘；收起保留草稿，成功收起并清空，失败保留输入。每个操作先展开说明输入，确认/取消固定在底部；需要原因时按钮保持禁用直到填写。补充说明展开时底部只提供补充入口与提交补充，避免同时出现两组办理表单。出错保留输入，处理中阻止重复提交。

进度沿用旗舰详情的圆形编号与文字，桌面五列、540px 以下两列，当前项带文字及 aria-current=step，不靠颜色区分，也不替历史记录推断未发生的步骤。当前状态最近一次原因/结果有正文时在内容区单独显示，避免收起历史后隐藏待确认结果或退回原因。无权角色不显示操作；待确认时管理员只读等待。中英文、375px 手机保持按钮可见和无横向溢出，奖励仍只在首次采纳发放。

入口 `/feedback` 为登录后的独立导航项，复用工作台、Corporate Clean 与统一中英文词表。一个主标题与“提交反馈”按钮；工具栏仅放范围（管理员）、类型、状态、刷新。列表采用整行对齐的类型、标题/作者/时间、状态，不放重复说明或统计空卡片。

宽屏行布局为 110px 类型列、可伸缩标题列与状态列，24px 水平内边距；700px 以下类型和状态同排、标题与元数据下一排，内边距 16px。列表使用全部可用主内容宽度；筛选自然换行，按钮操作区至少 44px。标题与连续长文本完整换行。

提交和详情使用共享 Modal。提交只包含类型、标题、详细描述，BUG 提示页面/操作/问题，功能提示期望功能。详情先显示原文与状态，在可折叠的“处理记录”内按时间统一展示补充说明和状态事件，底部保留按需展开的补充入口；补充成功后展开处理记录显示新内容。普通用户没有全量范围和处理状态控件；服务端仍独立鉴权。

按 ID 稳定分页，每页 30 条；详情链接 `?ticket=<id>`。查询键包含账号/筛选，关闭详情回到列表。提交成功打开新记录；写请求使用 UUID 防重，冲突/错误保留输入、可刷新重试。加载、空、失败和权限拒绝各有明确状态。文本不解析 HTML，不将用户标题作为 HTML 属性执行。

验收覆盖中英文、1280/375/320px 的提交、补充、管理员处理和版本冲突；截图与结果按[项目状态](../project-status.md)记录。

## 截图

提交表单与回复区增加紧凑“添加截图”按钮，可从文件选择或在表单内粘贴；支持 PNG/JPG，每次最多 3 张，文件大小不设固定上限。数量在有图片时显示，不增加常驻说明小字；格式/数量错误就地提示。草稿缩略图为 128×96px、自动换行，移除按钮 44px；详情和回复按原顺序展示缩略图，点开新标签页查看鉴权原图。使用 File/Blob URL 预览并在移除/关闭时释放；提交中阻止图片增删；错误保留草稿，成功清空。详情不公开图片 URL 的访问权，后台每次核对当前归属/管理员。中英文同步。

反馈详情使用与旗舰相同的 640px 标准表单弹窗；只滚动内容区，标题与操作区固定。长正文、截图和展开的历史不会挤走按钮；移动端允许底部操作换行，阅读和键盘顺序保持一致。加载、错误和正常内容共享同一弹窗实例，保留焦点返回与忙碌期间关闭保护。
