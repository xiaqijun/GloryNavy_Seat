## 开发约定

游戏名称与本站界面文案分开维护。ESI 枚举的官方来源只证明代码和值合法，不证明项目手写的中英文标签是游戏客户端原文；未经核验不得标注为官方译名。物品/技能/船型/星系与已有分类继续使用 SDE 原名；其他游戏术语应记录客户端或官方本地化来源及版本。修正前的问题见[历史术语检查](game-terminology-audit-2026-09-20.md)，当前来源和更新流程见[术语指南](../integrations/eve-terminology.zh-CN.md)；测试通过不等于译名正确。

`web/src/lib/i18n.ts` 提供 `msg("中文源文", ...values)`、`getLocale()`；词表位于 `web/src/lib/locales/en.ts`。中文源文是稳定键，变量使用 `{0}`、`{1}` 等占位符，完整句子优先，避免用多个中文片段拼出英文语序。英文词条可以为空字符串（仅用于没有独立英文意义的语法片段），缺失键才回退源文。

新增固定界面文案同步加入词表，包含 aria-label、placeholder、错误提示与图表可访问文本。不能翻译 API 参数、状态码、权限键、ESI 枚举值或用户输入后再提交；业务判断使用稳定数据值。APIError 只翻译已登记的固定消息，未知消息保留原文。

组件级 `msg` 调用不改 DOM 所有权；语言采用整页重新加载，所以模块级标签对象与懒加载模块不会出现切换后的旧语言缓存。新增实时无刷新切换时必须一并重构这类模块常量，不能只重新渲染外壳。

验证入口：`web/src/lib/i18n.test.ts`（占位符、偏好、存储受限、原文与大 ID），`web/e2e/wallet.spec.ts`（中英往返、登录页、钱包详情、原始备注和窄屏）。当前验证结果见[项目状态](../project-status.md)。

## 服务端语言与证据边界

业务 API 统一经 `apiFetch` 发送界面语言；服务端使用 `internal/platform/locale` 请求上下文，后台任务默认中文。语言只改变展示，不传给 ESI 抓取或共享缓存键。新增名称消费者经注入 StaticDataService 批量读取并保留 context。固定消息加入前端词表后运行 `node scripts/backend-messages.mjs`，用 `--check` 校验 Go 消息子集；仅对服务端固定文案使用 Message，不翻译用户输入。技能/舰船的 group_english 来自同一官方 SDE 构建，由参考目录生成脚本维护。

福利列表/详情只投影已授权快照中的类型、星系名称及固定核价提示；数据库证据和审计不改写，未知字段与精确数值保留，名称查询失败则保留原名。业务规则仍使用稳定 ID/代码，不使用翻译后的名称判断资格。
