## 2026-09-23 自动兑换（已发布）

联盟 `alliance_pap` 现支持管理员选择手动/自动，独立比例不变；升级不改已有模式。每个角色每月首次观察或首次有效绑定作为基线，不补兑已有积分；之后成功完整同步的新增分自动兑币。历史基线可由管理员按月预览后手动兑换。自动与手动共用来源引用和币账，不能重复兑换。

角色累计分按 0.01 PAP 保存；不足 0.01 币的进度也保存，后续累计达到最小单位再入账。比例按该角色该月首次实际兑换冻结，更正按原比例差额冲正。下降扣减已兑增量，完整快照中消失的角色冲回该月已兑币；重复/失败/不完整/错误月份快照不发币。首次新月份重新建基线，不追补上月。

发布前获取当前有效绑定与活跃账号锁，再锁同步版本和币账；旧请求不能覆盖新快照。解绑/换账号不迁走历史归属，不为无有效绑定角色增加币；显式账号合并迁移快照与币账并纳入合并预览指纹。同步快照与发币同一事务，任何失败整体回滚。当前完整月度上游无活动 ID，因此只做累计增量，不伪造逐次活动记录。

状态整理：2026-09-23。[English](winterco-pap.en.md)。已部署当前月快照同步、服务器差量落库、报告与管理员手动兑换；**自动兑换已发布，既有 manual 配置保持不变**。当前版本见[项目状态](../project-status.md)，相关待办为 [PAP-01](../backlog.md)。

## 生产数据路径

独立 seat-pap 服务 → 后端内网 HTTP → attendance River 队列 → 本站 PostgreSQL → 联盟 PAP 页面 / 工作台。前端不直连上游，不携带 Token 或 WinterCo Cookie；本机 DOM 工具不是生产数据源。

- 独立服务工作目录 `/root/seat_pap`，监听端口 `18770`。服务端负责上游会话和完整当前月快照；本站只读取已授权 API。
- 本站配置 `WINTERCO_PAP_URL` 和 `WINTERCO_PAP_AUTH_FILE`。同机示例 URL 为 `http://127.0.0.1:18770`；认证文件优先取受限 `read_token`，兼容 `api_token` 回退。实际文件只部署到受保护目录，不提交内容。
- Goose 45 引入本站联盟快照；River 每 30 分钟读取完整当前月。上游没有差量接口，网络仍读全量快照，数据库事务只改变化行；完整成功后清理本月已从上游消失的角色。失败、不完整、错误月份不覆盖旧快照，不把失败当零分。
- 独立服务也有自己的 30 分钟采集时钟，两层缓存/调度不保证游戏数据变更后 30 分钟内必然展示。界面以实际同步时间判断新鲜度。
- 当前来源是按角色的月累计十进制 PAP，不含逐次活动 ID/日期。本站支持 0.01 PAP 精度，按当前有效绑定映射账号；角色明细只向有权限的本人/管理范围展示。

## 独立采集主机迁移

可把现有独立服务迁到香港主机，后端经 ZeroTier 内网读取。使用 [seat-pap.service](../../deploy/seat-pap.service) 常驻运行；配置文件 `config.json` 的 `bind` 必须设为该主机的私网地址，`port` 保持 `18770`，不得为此新增公网反向代理。程序、`web/`、配置、授权及完整 `data/` 通过受信 SSH 直接传输；目录仅 root 可读，密钥和 Cookie 不进入 Git、输出或命令参数。迁移不修改采集解析、月份规则、兑换模式或币账。

先在目标主机单次运行原有 `CLIENT.monthly()`，只输出月份、完整性、行数、总分和耗时；不能以首页可达或健康响应代替完整 PAP 验证。目标服务启动后，还需从应用主机携带已有受限令牌请求 `/api/pap/monthly`，确认完整响应能在本站 25 秒预算内返回，并验证匿名访问被拒绝。`GET /api/pap/monthly` 会即时采集上游，不只是读取磁盘快照；后台定时采集和接口请求共用串行锁。

验证通过后备份应用环境文件，停用旧 `seat-pap.service`，只将 `WINTERCO_PAP_URL` 改为 `http://<HK_PRIVATE_IP>:18770`；保持原 `WINTERCO_PAP_AUTH_FILE` 与既有令牌，重启当前应用版本加载配置。让正式 River 任务完成同步并检查数据库成功时间、完整月份及成员投影；不得使用缺少宿主兑币回调的临时程序导入。两台采集器只在迁移验证时短暂并存，切换后旧实例必须停止并取消开机启动。

失败时先停止目标实例，将其最新 Cookie 经受信 SSH 回传到原服务的受保护数据目录，再恢复环境备份、原采集器和应用服务；保留两端完整快照和原程序作为恢复证据，不清空 PAP 或币账。迁移后的跨时段稳定性、自动续期和月界仍需继续验证。

## 查看与兑换

`/attendance?view=alliance-pap` 显示当前月总分、默认每人 3 PAP 目标、环形进度、已映射角色明细及同步状态。管理员可在明细下打开“兑换联盟 PAP”，从仍有待兑换余额的历史月份中选择月份后补兑；当前月和历史月份均按保存的完整快照结算。工作台读取同一报告。军团 PAP 来自本站点名，独立统计、无月门槛，不能用于抵联盟要求。

- `GET /api/v1/attendance/alliance-pap`：已鉴权账号的联盟报告；不在请求时抓外站。
- `GET /api/v1/attendance/alliance-pap/members?month=YYYY-MM`：当前站点管理员按成员查看所选完整月份的联盟 PAP；多角色按本站账号合计，返回前复核当前绑定，过期或未绑定行不展示。省略 `month` 时读取当前月。
- `GET/POST /api/v1/attendance/pap-requirement`：读取/配置联盟月目标；写入仅当前站点管理员，版本与审计保护。
- `GET /api/v1/attendance/alliance-pap/conversions`：管理员读取仍有待兑换余额的完整历史月份及各月预览摘要。
- `GET/POST /api/v1/attendance/alliance-pap/conversion`：管理员预览/提交指定 `month=YYYY-MM` 的完整快照兑换；省略月份时兼容当前月。使用独立 `alliance_pap` 比例与来源幂等记录；重复提交不重复发币。
- 联盟快照不会混写军团活动 PAP 流水。exchange 独占币账，attendance 经宿主注入事务服务结算，不能直接修改别的模块 store。
- 本地新版 `alliance_pap` 接受 manual/automatic，独立于军团 `pap`；升级不改变既有模式。自动模式首次角色/月快照建立基线，随后完整同步只兑换增量，并处理下降更正。生产部署验收见 PAP-01。

## 授权与失败处理

独立服务的受限 `read_token` 已验证可读健康状态、会话摘要和当前月快照，历史 CSV、Cookie 更新及续会话管理操作要求管理 Token。不要为读取需要把管理 Token 下发给前端。任务载荷和日志不携带凭据。

临时网络/5xx 在任务预算内重试；失败保留上一份完整快照及错误状态。过期会话在独立服务恢复，不能用手工提交数字替代可信采集。停用模块和账号合并遵循[考勤](attendance.zh-CN.md)及[兑换](exchange.zh-CN.md)规则，不能清空币账或重复兑现历史月份。

## 暂停的本机浏览器工具

保留 `npm run pap:browser -- --mode login --character <角色ID>` 与 `--mode inspect` 工具供历史排查，依赖本地 Playwright 和 Edge/Chrome。使用专用 `.local/winterco-browser/`，不复制日常浏览器 Cookie。首次登录与二次验证由用户完成。

该方案因上游登录错误暂停，采集输出 `complete=false` / `importable=false` / `awaiting_adapter`，不能导入或发币；生产不使用这条路径。不要把恢复 DOM 工具列为运行生产服务的必要步骤。
