## 1. 核验依据

固定参考 `eveseat/web` 提交 `cd11287006bddbf00c48cf13fd1fa704b0ea25d6`，不将旧注释中的 group 模型当作当前实现。

- [User 模型](https://github.com/eveseat/web/blob/cd11287006bddbf00c48cf13fd1fa704b0ea25d6/src/Models/User.php)：用户有 `main_character_id`，通过 refresh tokens 关联多个角色；本站角色与用户关联。
- [SSO 控制器](https://github.com/eveseat/web/blob/cd11287006bddbf00c48cf13fd1fa704b0ea25d6/src/Http/Controllers/Auth/SsoController.php)：未登录时按角色及 owner hash 查找用户；已登录时关联当前用户，也可能迁移该角色原有 token 归属。新用户以首次角色作为主角色；绑定时优先沿用主角色 token 的 scopes。
- [个人资料控制器](https://github.com/eveseat/web/blob/cd11287006bddbf00c48cf13fd1fa704b0ea25d6/src/Http/Controllers/Profile/ProfileController.php)：主角色只能从自己的关联角色选择，更新主角色和用户显示名；解绑删除该用户对应角色的 token 关联。更换主角色还有重复名称账号检查。这不等于合并两个用户的全部角色和权限。
- [Token observer](https://github.com/eveseat/web/blob/cd11287006bddbf00c48cf13fd1fa704b0ea25d6/src/Observers/RefreshTokenObserver.php)：token 创建或恢复触发角色更新，删除触发授权角色过滤数据更新。

以下为适配 Go 模块边界的本站实现，不是对 SeAT 全部行为的照搬。

## 2. 成员、主角色与小号

一个本站用户代表一名成员，可绑定来自多个 EVE 游戏账号的角色。用户逐个完成角色 SSO；本阶段不建立 EVE 游戏账号分组，也不推断未授权角色。

| 对象 | 规则 |
| --- | --- |
| 本站用户 | 稳定 UUID；QQ/KOOK 资料、社区确认、手工授予的本站角色归用户所有 |
| 主角色 | 每个有角色的用户选一个；首次登录角色默认成为主角色，用于显示名、头像和默认查看对象 |
| 其他角色（小号） | 与主角色属于同一用户，各自保存军团、职务、ESI 授权和同步状态；不建立层层从属关系 |
| 登录角色 | 本次通过 SSO 证明身份的角色；任一有效绑定角色登录均进入同一用户 |
| 当前查看角色 | 页面选择的数据对象；切换查看不改变主角色、不改写登录身份、不扩大权限 |

主角色标记不授予管理员权限，也不限制小号自己的游戏职务生效。权限仍按有效角色事实、目标军团及本站授权判断，详见[授权规则](seat-authorization.zh-CN.md)。

## 3. 操作规则

| 操作 | 本站已实现行为 |
| --- | --- |
| 普通登录 | 已绑定角色返回所属用户，新角色创建用户并设为主角色；现有浏览器会话不触发绑定 |
| 添加角色 | 当前用户主动发起，服务端保存 `link` 意图、目标用户、原会话和请求 scopes；回调必须再次核验 |
| 重复添加本人角色 | 返回已有绑定，不创建重复用户或绑定，不擅自改主角色 |
| 添加其他用户的角色 | 返回归属冲突；不迁移 token、不合并用户、不转移社区资料或本站权限 |
| 更新授权 | 保存 `reauthorize` 意图和预期角色；SSO 选错角色时拒绝，不变成添加角色 |
| 设为主角色 | 只接受当前用户已绑定且身份有效的角色；更新默认展示，用户 UUID 和本站授权保持稳定 |
| 解绑小号 | 撤销该角色产生的会话、移除有效凭据和授权事实，再解除绑定；不触及其他角色凭据 |
| 解绑主角色 | 先选择另一个有效绑定角色作为主角色；最后一个可登录角色不能通过常规解绑移除 |

添加角色和更新授权使用本站当前的 [当前 scope profile](seat-login-scopes.zh-CN.md)（基线 57，启用 fittings 时 58），并把实际请求范围存入 flow；不从可能已过期或缺项的主角色凭据复制范围。每个角色独立同意、独立校验、独立刷新。

授权撤销与身份转移分开：ESI 授权失效保留绑定与主角色标记，显示需要重新授权，失效职务立即退出权限判断；owner hash 不匹配则进入归属异常处理并撤销该角色会话，不自动交给另一个用户。主角色失效不应阻止其他有效绑定角色登录。

重复本站用户可走已实现的显式账号合并；角色出售后的恢复、管理员代解绑是其他流程，尚未开放。普通绑定不隐式合并；合并保留首次归属与原审计，详见账号合并指南。

## 4. 实施边界

迁移 `00007_identity_characters.sql` 增加用户主角色复合外键、SSO 意图及 `identity_character_events` 审计。升级自动将已有单角色用户回填为主角色；若已有用户关联多个角色则拒绝迁移，不随意挑选。此类非标准数据需先备份并人工制定回填迁移，不应通过删除角色绕过检查。空用户不产生会话。

- identity 的 `Complete` 在一个事务内核验角色、用户、原会话，保存身份、凭据及登录会话；普通 `SignIn` 调用 login 意图。绑定与重新授权保留原会话角色和到期时间。
- eve 保存一次性 flow 意图、目标用户、预期角色和请求 scopes。SSO 网络交换在数据库事务外；flow 消费后不能重试同一回调，失败需重新发起授权。
- 宿主注入 `SaveTx` 和 `RemoveCharacterTx`，跨模块只使用业务接口。绑定/变更按角色锁、用户锁、会话锁、凭据锁排序；用户锁同时串行化主角色、解绑和登录会话数量变更。
- access 每次按当前有效绑定和目标读取角色事实，不因为更换主角色扩大权限。解绑删除本地凭据及快照，撤销该角色产生的会话和该用户尚未消费的绑定/重授权 flow；这不是向 CCP 发送远程撤权请求。
- 角色关系与凭据生命周期分离。ESI 撤权保留关系；owner hash 异常隔离身份。审计保留原用户 ID、角色 ID、动作和时间，不随解绑删除或转移。
- community 已实现[账号级手填资料与完整度门禁](community-profile.zh-CN.md)，各角色共用；机器人与外部确认入口仍待实现。

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/identity/characters` | 列出自己的角色，包括身份异常项，主角色优先 |
| `POST /api/v1/identity/characters/{id}/main` | 设置自己的有效主角色 |
| `DELETE /api/v1/identity/characters/{id}` | 受保护解绑；主角色/最后一个有效角色返回 409 |
| `POST /api/v1/eve/characters/link` | 创建绑定 flow，返回 CCP URL |
| `POST /api/v1/eve/characters/{id}/reauthorize` | 创建预期角色固定的授权 flow，返回 CCP URL |

写接口需要本站会话、同源 Origin 和 `X-CSRF-Token`。`/identity/session` 的 `character` 是认证角色，新增 `main_character` 用于默认显示。绑定/重新授权成功回到 `/account`，失败按需显示固定错误码；缺失/失效 state 回到 `/login`。完整响应见 [OpenAPI](../../api/openapi.yaml)。

角色页默认查看主角色，可点击头像卡切换查看；按钮有禁用、等待和失败反馈。解绑对话框支持键盘取消和失败重试，解绑本次登录角色后清空浏览器查询缓存并返回登录页。其他解绑/主角色变更刷新身份和权限查询。

## 5. 验收条件

1. 两个不同游戏账号的角色逐个授权后归同一用户，任一角色登录得到同一用户 ID。
2. 首个角色默认主角色；更换主角色、切换查看与使用小号登录互不混淆，社区资料和本站授权不变。
3. 取消、过期、重放、原会话失效、选错预期角色及并发冲突均不留下错误归属或凭据。
4. 已属其他用户的角色绑定失败，原用户角色、会话、社区资料和授权不被迁移。
5. 小号撤权只移除其有效 ESI 权限；A 军团职务不能用于 B 军团，主角色标记不提升权限。
6. 解绑移除关联会话及数据访问；主角色和最后一个登录角色保护在后端执行，并记录可追溯审计。

2026-09-14 阶段已通过完整 Go/隔离 PostgreSQL 测试、Go vet、前端 lint、13 项单元测试与生产构建，14 项桌面/手机登录、授权及多角色浏览器测试。另有跨军团权限集成测试。当次自动化使用模拟 SSO 和测试角色，未验证真实 CCP 授权；这项历史结论不代表后续仍未接入 EVE，当前证据见项目状态。
