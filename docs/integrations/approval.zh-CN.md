## 入口与权限

启用 MODULES 中的 approval，并保持所需 welfare / exchange 来源启用。入口 /approvals 位于工作台之后。仅有当前可管理来源的账号显示菜单；普通成员访问列表/详情被拒绝。approval.self 是宿主会话鉴权能力，不是可分配的管理权限，不加入 ManageableCatalog；进入页面不会获得业务权限。

福利沿用 corporation.welfare 的军团范围及当前有效成员集合；兑换沿用站点管理员检查，并只聚合接收角色仍有效绑定到订单账号的订单。每次列表、计数和详情重新授权。本站超级管理员也不能审批本人申请或审核本人取消；兑换原 DecideOrder 服务已补齐同一限制，直接调用旧 API 也不能绕过。人员筛选按本站账号和主角色展示，多开与账号合并沿用源单规则。

## 视图

- 列表“金额与物品”从来源单据的冻结快照展示：福利中的 ISK、果壳币与舰船/物品摘要分行呈现，兑换显示币花费及奖品快照。最多列出两项实物名称与数量，剩余项显示计数；不把估价当作实际发放金额，也不把不同货币合计。
- 待审批：福利申请、待联盟结论的兼容旧单和福利/兑换取消申请；待补充单独筛选，不计入即时待审批角标。同一单不会以申请和取消重复计数。
- 待发放：已批准/核对中的福利和正常兑换。等待合同同步、明细或成员接取属于正常进度；历史纯币成长单保留显式发币操作。
- 异常：金额/物品不符、多个候选、合同被占用、发放人未核实、证据不可读或奖励快照缺失。
- 已处理：每张单据一行，展示最近处理动作和当前状态；详情保留完整原审计。批准后仍可同时出现在待发放与已处理，不能将批准当作完成。“我处理的”只查当前操作者的人工处理动作，自动合同完成标为系统核验。

批量结算最多接收 100 条记录，并按请求键幂等创建批次。一个批次只能包含同一本站账号组的记录，同组下的多个 EVE 角色可以一起合并；跨账号选择会被前后端拒绝。新批次冻结聚合 ISK/物品快照并生成 `BATCH-YYYYMMDD-UUID` 编号，管理员可据此为该账号主角色创建一份游戏合同，River 只按当前主角色的 ID 自动核验接收角色、发放方、整数金额、物品多重集合和完成状态，再一次性更新批次明细。历史批次即使保存了多个角色 ID，也在结算时重新读取当前主角色，不扫描或发放给小号。含果壳币记录暂不进入聚合合同；旧批次保持逐笔兼容。合同尚未同步、尚未接取或物品明细缺失时，批次保持等待状态并继续重试，不提前计入完成数；合同已同步且仅等待主角色接取时返回 `delivery_status=awaiting_acceptance`，并在审批中心“已处理”显示等待领取状态。该能力已随 `v0.1.0-contract-batch-merged-20260930` 基础版及 `v0.1.0-contract-batch-approval-history-20261003` 修复版发布；真实游戏合同交付仍需现场验收。

本人单据不进入可操作待办/计数；授权管理者仍可在已处理或直接详情中只读查看。正常兑换不新增申请审批。自动合同核验、真实游戏发放及幂等入账仍由原模块负责，中心不新增强制完成、跳过证据或自动批准。

## 原页面

启用 approval 时，福利页移除补损/成长/旗舰的管理记录选择及审核、发放操作；保留个人记录、撤回、补充、取消申请和配置。主动发币及其管理记录/冲正、历史领取登记仍留原入口。兑换页只查询本人订单，移除全部兑换及管理员取消处理、合同交付入口，提供授权后的中心详情链接。源单据、历史资格、合同证据和流水不删除。

中心与原页复用 CaseView、取消表单、合同复制区和原写 API；处理成功失效 approval / welfare / exchange 缓存。详情 URL 为 /approvals?source=welfare&id=123 或 source=exchange；关闭详情保留筛选/游标。来源被停用、权限撤销或目标不再有效时明确拒绝。

如果不启用 approval，旧管理入口继续可用，避免配置切换导致无人可处理；禁止自审的服务端校验始终生效。启用中心需前后端配套更新，不需要新 ESI scope，不清理会话。

## 查询与边界

只读 API：GET /api/v1/approval/context、GET /api/v1/approval/items、GET /api/v1/approval/items/{source}/{id}。`/context` 默认返回权限、来源和军团选项；需要申请人筛选选项时使用 `?include_people=true`，服务端再读取人员名称投影。原审批/取消请求仍发到 welfare/commands 或 exchange/rewards/orders/{id}，继续检查 CSRF、当前权限、版本、幂等键及原事务锁。

context 返回 allowed、sources、capabilities、corporations、people、unavailable；`capabilities` 按来源声明批准、驳回、取消审核、发放、批量结算、筛选能力和 `detail_kind`，仅用于列表与详情注册表，不授予写权限。items 接受 view、sort、kind、corporation、account、q、status、from、until、mine、cursor。响应还返回 `source_status`，以及每条记录的 `summary_version`、`detail_kind`、`source_status`、`stale`；来源投影陈旧时仍显示索引数据并明确状态。`sort` 当前支持 `time_asc`/`time_desc`（申请/处理时间）和 `id_asc`/`id_desc`（编号），省略时待处理视图默认申请时间最早、已处理视图默认处理时间最新。时间使用 RFC3339，前端日期筛选明确 UTC，起始包含、截止不含。搜索单号、结算编号、接收角色和标题；主角色按人员选择筛选。兑换没有历史军团归属，选择军团时不混入兑换订单。

各来源私有 SQL 先按授权集合和筛选读取，单来源最多 31 条；平台 reviewqueue 仅提供无表名的投影/过滤/游标工具，approval 不访问其他模块 store。宿主注入 Source 与身份主角色名称服务。当前页最多 30 条，活动视图使用申请时间，已处理视图使用处理时间；两者均可升降序，编号也可升降序。全局键按所选列、来源和单号构成，游标绑定账号、筛选和排序方向。两个来源使用同一排序边界，因此不需要拼接各自第一页，也不会漏掉稳定记录。实时状态变化可能移动单据，刷新首页获取最新结果，不承诺跨请求数据库快照。

分类计数来自各来源完整授权集合，同一来源的计数和列表使用一个 SQL 语句快照。所有查询仅读本地存储，不触发 ESI。来源失败返回 unavailable，页面标明计数不完整，不以 0 代替；来源标签按 `welfare`、`exchange`、`loan` 分别显示军团福利、奖励兑换和贷款，未知来源保留原始标识；部分列表仍可查看，但暂停后续翻页，防止越过恢复中的来源。可见标签约 30 秒刷新，后台不轮询；不创建第二套审批状态、付款或币账。

兑换订单的奖励物品名称属于展示增强。统一索引列表只读取订单冻结快照中的已有名称、类型 ID、数量和兑换金额，不逐行调用 SDE 名称服务；SDE 暂时不可用不会拖慢列表，也不会将名称解析失败误报为来源不可用。详情和来源页面仍可在需要时补全名称。

申请人主角色昵称和福利成员主角色名称同样属于展示增强；名称投影查询失败时保留待办、计数和接收角色，不把列表误报为不可用。来源权限或业务查询本身失败时，服务端会记录具体来源和阶段，前端继续标记对应来源计数不完整。

审批上下文和列表接口记录不含账号、查询词或 payload 的 `duration_ms` 观测日志，并标注是否走索引、是否加载申请人筛选；来源级日志进一步记录 `access`、`people`、`query`、`index` 和 `names` 阶段、来源、成功/失败、允许状态和行数。可按发布前后的同一视图和数据集计算 p50/p95，不把单次请求当作性能结论。

上下文与索引列表之间会对同一本站账号和来源复用 5 秒权限范围快照，减少首屏连续请求的重复成员/绑定查询；来源显式提供独立 `IndexAccess` 时才按索引路径隔离缓存键。详情和所有写操作不使用该缓存，仍由来源模块实时复核对象权限、版本和自审规则。

统一索引路径还会保存来源授权所需的当前有效成员账号范围；福利补损专员的可见范围因此同时受军团和成员归属限制。P2 验收可将 `APPROVAL_DUAL_READ=true` 临时打开，后台按相同授权、筛选和游标运行旧聚合并记录差异；后台比较最多同时运行 4 个，超出时跳过并记录原因，旧聚合失败也会记录 `legacy_error`。完成验收后关闭。

## 验证与限制

数据库回归覆盖授权军团/成员、本人待办排除、兑换自审拒绝、重复取消幂等、历史批准仍待发放及真实 SQL 分类；聚合测试覆盖相同时间跨来源多页无漏重、筛选绑定游标、来源故障和未知来源。浏览器回归覆盖统一表单、取消确认、普通成员无入口、分页/详情返回、入口收敛、中英文及 320/375/1440px。

未执行真实成员申请审核、退款或游戏合同发放；本地实现不等于生产已发布。自动合同真实闭环的原有联调限制见[福利指南](welfare.zh-CN.md)和[兑换指南](exchange.zh-CN.md)。不含批量审批、多级会签、自动批准或消息通知。
