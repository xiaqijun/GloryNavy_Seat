# 官方 QQ 机器人

官方 QQ 建筑群提醒与旧 OneBot 提醒独立，使用群 OpenID 和独立回执，迁移默认关闭；群主动消息权限须在开放平台及目标群均可用。生产状态、配置与回退边界见[提醒指南](reminder.zh-CN.md)。

站内“提醒”页面的建筑群配置及发送记录已在本地实现，发布状态见[项目状态](../project-status.md)。

> 2026-10-29 已发布的 WebSocket 改造：事件改为 WebSocket 接收，旧官方 HTTP 回调返回 410；默认仍停用，保留原密钥和身份历史。开放平台需切换 WebSocket 接收并允许服务器出口 IP。数据库会话锁限制单实例，断线在同一进程内尝试恢复；进程重启或平台拒绝恢复可能遗漏离线事件，群申请可使用原同步入口补查。默认订阅群与单聊事件（intents 1<<25）；仅在平台授予群成员事件权限后，设置服务器 `QQ_BOT_WS_MEMBER_EVENTS=true` 并重启服务以额外订阅 1<<24。真实验证码绑定和回复已验证；入群审批仍需联调。

更新：2026-10-28。[English](qq-official.en.md)。用户要求从 NapCat 切回官方 Bot。本轮已发布，官方机器人默认停用；生产状态以[项目状态](../project-status.md)为准。

## 管理员配置

`/community` 维护 AppID、API 地址、App Secret、启用状态和回调地址。正式 API 为 `https://api.bot.qq.com`，沙箱/API 权限以开放平台应用为准。App Secret 只写，服务端加密保存，不在响应或日志中返回。留空只在 AppID 相同的情况下保留旧密钥；更换 AppID 需要重新填写密钥才能启用。停用不清除已保存密钥。

回调地址为 `https://<SITE_HOST>/api/v1/community/qq/official/webhook`，页面按当前域名显示。开放平台选择需要的事件；普通群消息绑定需要应用已获准且订阅 `GROUP_MESSAGE_CREATE`，否则使用群 @ 事件或单聊。签名握手和接收事件不代表已获准发送主动消息或 Markdown。

每次保存必须携带读取到的 revision；冲突返回 409，页面保留输入，点击“重新读取”后再修改。更换 AppID 会失效旧 QQ 确认、未用验证码并移除当前官方 OpenID 映射，保留历史事件/确认记录及旧 OneBot 证据；需要重新绑定。群 OpenID 是应用范围标识，不能填写或转换数字群号。群入群审批接口保留历史能力，只有实际应用获得对应权限/事件时才能联调使用。

## 成员绑定

在个人账户填写 QQ 号并生成一次性验证码，10 分钟内发送给官方机器人；已开通普通群消息事件时可直接发群，无需 @。只接受完整的八位验证码；普通群聊不提取验证码、不落库或回复。原有“@机器人 绑定 验证码”和单聊绑定兼容。

官方回调提供的是 OpenID，不提供数字 QQ 号，因此确认的是持有码的官方机器人身份与本站账号的关系，不能声称平台核实了手填 QQ 号。旧 OneBot 数字绑定不能转换为官方 OpenID，必须重新验证。修改 QQ 资料仍使旧确认失效。

绑定事务复核已验签的配置是否仍启用、AppID/密钥/API 是否一致；事件和身份锁防重放冲突，宿主活跃账号锁防止合并后迟到写入。码、资料版本、OpenID 归属、确认和事件哈希同事务发布。被动回复使用原消息 ID，不自动重试。

## 迁移与停用

Goose 109 为官方配置增加 enabled（默认 false）和 revision；保留原密钥但不自动启用。升级停用 OneBot、其群审批提醒，失效 OneBot 有效确认及未使用验证码；保留数字绑定、群配置、事件及发送回执。旧 OneBot 管理 API 保留会话、当前管理员和 CSRF 检查后返回 410，公共回调也返回 410，不能继续收发或通过旧页面重新启用。

旧队列处理器保留识别历史任务，但停用配置不派发或发送 QQ 审批提醒。不自动恢复 QQ 审批提醒；现有游戏邮件提醒配置不变。建筑群提醒已经独立接入；Markdown 指定成员 @ 和 QQ 审批提醒需要后续按应用权限接入，不能以旧 NapCat 的真实验收替代。

保存新官方配置或存在官方绑定后 Down 拒绝；仅空白、未使用的开发环境允许移除新增字段。不要回退忽略新配置版本、绑定来源或历史回执的程序。此轮不登录普通 QQ、不启动 NapCat、不删除历史证据。

官方依据：[接入凭据](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/access-token.html)、[消息收发与时效](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)。本轮核对 token 的字符串/数值有效期，避免字符串 `7200` 被错误降为 60 秒；凭据/缓存快照在重配时一致失效，HTTP 不跟随重定向。

公开握手仅接受正整数的规范十进制时间戳和最多 1024 字节的非空挑战，拒绝以 JSON 对象开头的挑战；不允许将握手作为普通回调事件的签名入口。回调请求必须为单个 JSON 文档。
