## 边界与调用

SeAT 将独立客户端 [Eseye](https://github.com/eveseat/eseye)、[EsiClient 接口](https://github.com/eveseat/services/blob/master/src/Contracts/EsiClient.php)和[同步基类](https://github.com/eveseat/eveapi/blob/master/src/Jobs/EsiBase.php)分开。本项目对应如下：

| 层 | 实现 | 职责 |
| --- | --- | --- |
| 业务接入服务 | `eve.ESIService.Request` | 公开或角色授权请求；返回缓存到期、内容变化时间、可信截止与分页元数据；调用方不接触原始令牌 |
| 凭据服务 | `AuthorizationService.currentToken` | 凭据行锁、scope/身份/代次核对、刷新、轮换提交、并发复用 |
| HTTP 客户端 | `eve/internal/esiclient` | 固定 ESI 主机、兼容日期、响应解析、加密缓存、ETag/304、共享限流与请求观测 |
| 同步业务 | `SyncService`、各资源 worker | River 调度、数据范围、分页断点、租约/fence 与业务发布 |

旧内存缓存请求分支已移除。基础资料、合同及公开名称请求使用同一个 Request 入口；授权快照在接入服务内部组合公开信息和私有职务请求，先核对凭据，复用同一刷新重试机制。ESI HTTP 与限流代码不再和角色/合同业务混在一起，SQL 仍是 eve 模块私有数据。

调用方按需定义 `Request(context.Context, eve.ESIRequest, any) (eve.ESIResponse, error)` 接口，由宿主注入 `AuthorizationService.ESI()`。`ESIRequest` 包含 Method、Path、Body、CharacterID、Generation、Scopes、ExpectPages、LimitTrust；公开请求省略角色、代次和 scopes。私有请求必须全部提供，代次来源于可信的角色同步任务。当前仅支持 GET/POST，固定 Tranquility ESI 主机，不支持任意绝对 URL。

接入服务不授予本站数据权限。业务调用方仍须验证有效绑定、目标对象、军团来源和业务范围；缓存命中不替代检查。公开响应按请求共享，私有响应按角色和授权代次加密隔离。军团来源选择与固定物品复用仍由合同业务负责，不把两个角色的令牌混用。

## 令牌生命周期与错误

- 每次获取凭据在角色行锁内重新读取，10 秒预算保持不变；访问令牌距到期不足 1 分钟时按需刷新，未使用的角色不因令牌过期而单独发起刷新。
- 轮换后的令牌、有效期和刷新成功观测同事务提交，再抓取 ESI 数据；业务发布仍在网络请求之后的独立事务中进行。
- ESI 401 最多触发一次有依据的刷新重试。如果其他任务已经提交新令牌，复用它；每次请求仍经过共享限流，不能用刷新绕过预算。
- ESI 403 记录资源拒绝，不刷新或删除令牌。缺少 scope、身份不匹配及明确授权失效由既有规则阻断或要求重新授权。
- 刷新失败后释放原事务，再用最多 2 秒的独立事务保存精简失败信息；再次检查授权代次，旧失败不能污染新授权。进程崩溃或数据库持续不可用时不能保证记录落盘，日志只写角色 ID、代次、错误分类及记录是否保存。
- CCP 已轮换但数据库提交结果不确定时记录 `rotation_commit_uncertain`，不得伪装为刷新成功；观测不提供凭据恢复保证。

## 管理视图与统计口径

`/sync?view=tokens` 需要独立 `eve.sync.manage` 权限或本站管理员身份。接口为 GET `/api/v1/eve/sync/tokens` 与 GET `/api/v1/eve/sync/tokens/{id}/events`，每次检查当前权限。`access.manage` 不替代该权限。只读页面不会解密凭据、触发刷新或调用 ESI。

列表每页 30 个角色，支持名称/ID 与状态筛选。显示有效期、最近刷新成功、scope 数量、实际请求/缓存次数；详情展开显示复用、刷新成功/失败、最近请求、精简错误及最近 20 条记录。每 30 秒刷新本地数据，后台标签页不轮询。

| 状态 | 含义 |
| --- | --- |
| `valid` / 有效期内 | 本地已知到期时间超过未来 1 分钟，不表示实时探测过 CCP 撤权状态 |
| `refresh_due` / 待刷新 | 即将到期或已到期，下次有请求时刷新；不等于需要重新登录 |
| `refresh_failed` / 刷新异常 | 最近刷新尚未恢复，优先展示故障 |
| `reauthorize` / 需重新授权 | 凭据已被既有生命周期规则标为失效 |
| `unknown` / 尚未观测 | 历史凭据尚无新观测，有效期不得填零或推测成功 |

- `reuse_count` 是凭据获取时复用已有访问令牌的次数，可能用于缓存读取，不能当成实际网络请求数。
- `network_requests` 统计发起 HTTP 的尝试，包括没有获得响应的网络失败；`cache_hits` 是新鲜缓存直接命中。304 属于网络请求。
- `rate_limit_waits` 包括本地预算阻止请求及上游 420/429；等待不累计 `request_failures`，不得宣称这些计数都是 CCP 拒绝次数。
- `last_request_status=0` 表示没有 HTTP 响应，如本地缓存、等待或网络失败。公开请求没有使用角色令牌，不计入该角色统计。
- 指标从观测开始累计，重新 SSO 授权后按新代次清零；事件保留原代次以便跨授权排查。它们不是固定日统计或全站流量汇总。
- 不保存或显示令牌值、前后缀、指纹、Authorization 请求头、原始错误正文，也不对外显示凭据密文或 owner hash。

## 迁移与保留

Goose `00018_eve_token_observation.sql` 新增元数据与事件表。升级沿用 `npm run db:migrate`（含 Goose 与 River 两条线），再部署兼容 API/前端；无新增环境变量、scope 或可分配权限。

历史凭据只补空观测行，不解密回填或主动向 CCP 请求。下一次使用会补齐有效期，新的授权和刷新开始形成事件；不伪造以前的刷新记录。解绑级联删除观测数据和事件。控制扫描每轮最多清理 500 条超过 30 天的令牌事件，当前代次聚合计数保留到重授权或解绑。

回退优先保留新表恢复兼容旧应用；Down 删除观测数据，不删除凭据。Goose 20 的逐笔预算见下节；外部报警、Prometheus 和自动轮换多角色来源仍未实现。


## ESI 限流令牌桶与接口消耗（Goose 19）

`/sync?view=rate-limits` 是“令牌桶”页签；原 `/sync?view=tokens` 改称“登录令牌”。前者统计 ESI 请求配额，后者观察 SSO 凭据生命周期，两者不是同一种令牌。

依据 [ESI 官方限流文档](https://developers.eveonline.com/docs/services/esi/rate-limiting/)，同一个 group 与调用身份共享滑动窗口预算。当前部署使用单一应用和出口，私有桶按角色、公开桶按公共出口隔离；授权代次或 token 刷新不产生新桶。更换应用或多出口部署时需要相应扩展分区键。

| 指标 | 来源与含义 |
| --- | --- |
| 最近剩余、容量、窗口 | 剩余只来自 `X-Ratelimit-Remaining`；容量与窗口优先响应配置，无观测时用兼容日期 OpenAPI，并返回 `policy_source`；不推断实时余额 |
| 接口累计/最近/平均消耗 | 只累计合法 `X-Ratelimit-Used`，平均值分母为有合法计费头的响应数；缺失、负数或异常格式标为未计量，不按状态码补值 |
| 请求 / 缓存 | HTTP 尝试数（包括网络失败）/ 新鲜本地缓存命中；304 仍发请求，其消耗读实际响应头 |
| 等待 / 限流 | 本地预算拦截 / ESI 420、429 响应，分别计数 |
| 本地可用 / 下次配额恢复 | 数据库按逐笔有效消耗和预留计算剩余；显示最早一笔恢复时刻，不是整桶补满，也不是 CCP 实时余额 |
| ESI 重试时间 | 429 的合法 `Retry-After` 秒数或 HTTP 日期；缺失时留空，不用本地最小等待代替 |

通常 2xx/3xx/4xx/5xx 消耗为 2/1/5/0，429 是例外；展示值始终以实际响应头为准。Goose 20 起，只展示官方目录声明或合法响应头明确给出的分组；无声明且无分组头的请求不创建桶，历史 unclassified 不再对外展示或继续累计，仍按原保留规则清理。无新桶不代表没有旧错误限流或游戏内部限流。快照超过一个窗口标记过期，不声称已自动获得新的官方余额。

GET `/api/v1/eve/sync/rate-limits` 支持 `search`（分组、角色名称或 ID，最多 80 字）和 `after`（桶 ID），每页 30 桶。GET `/api/v1/eve/sync/rate-limits/{id}/routes` 展示指定桶中按模板归一化的接口计数，`after` 为上页返回的接口模板，最多 300 字节，每页 30 项。两者需要当前全局 `eve.sync.manage` 或本站管理员；不存在的桶返回 404，参数无效 400，存储失败 503。查询不访问 CCP、解密凭据或更改限流预算。

Goose `00019_esi_rate_observation.sql` 新增独立桶和接口聚合表，使用模块私有 SQL。请求完成后以最多 2 秒的独立事务尽力记录，失败只留脱敏日志，不把观测写入失败转换成业务重试。仅存规范化路由（数字 ID 替换为 `{id}`），不保存查询参数、body、Authorization、token、源 IP 或应用密钥。并发晚到记录只增加计数，不覆盖较新的快照。

计数从该桶首次观测开始累计，不是当前窗口消耗；累计指标不随重新授权清零。每轮维护删除最多 100 个超过 30 天未活动的桶并级联接口统计，持续活动的桶累计保留；读取页面不会延长保留期。升级无历史回填、主动请求或强制刷新，不新增 scope/配置/可分配权限。升级仍用 `npm run db:migrate`；应用回退可保留表，Down 会删除本项观测历史。Goose 20 的预算算法见下一节。

官方规范与已完成适配见[限流调研](esi-rate-limits.zh-CN.md)。当前目录窗口均为 15m，但运行时读取各组配置，不把窗口写死。

## 官方目录与逐笔预算（Goose 20，2026-09-15）

- `catalog.json` 嵌入兼容日期 `2026-08-18` 的 233 项 method/path 元数据，包含 46 个新桶分组及各接口缓存 TTL。生成器验证日期、分组一致性和数值，并保存来源与 SHA256；请求链不临时下载规范。更新时运行 `node scripts/update-esi-catalog.mjs`，审查差异、测试后重新构建。
- 合同列表/物品/出价按组共享预算；角色独立，SSO 代次与刷新不改变桶。现部署只支持单应用、单出口分区。合法响应分组覆盖目录；容量/窗口在桶内由后续响应校正。
- PostgreSQL `eve_esi_charges` 保存请求预留及消耗到期时间，不含凭据。短事务先锁公共错误保护行，再锁桶；网络在事务外。已知桶先预留 5，收到合法 Used 后替换为实际值，重复结算不重复计费；并发预留和重启均不能绕过预算。
- 每笔在结算时刻加该组窗口后归还，后来请求不会推迟旧笔到期。丢失响应/Used 时保留 5 的保守估算，观测中仍标为未计量；进程中断留下的预留保留窗口加 30 秒 HTTP 最长期限。HTTP 服务已有更短超时的继续生效。
- Remaining 只收紧可用量：上游快照比本地更低时，记录差额债务并保留一个窗口，不让乱序较高快照增加预算。外部消耗缺少原时间，因此本地仍是保守估算；不承诺复刻 CCP 的实时余额。每轮维护最多清理 10,000 条过期账目。
- 429 按有效 Retry-After 等待，不再强制至少 60 秒；旧错误窗口的 Reset 单独用于公共出口保护。无有效时间才使用一分钟后备等待，原 200ms 平滑节流保留。
- 缓存和配额分别计时：HTTP 缓存头优先，缺失时用目录 `x-client-cache-ttl`；未知路由后备 5 分钟。尊重 Age、已过期 Expires、no-cache 和 no-store。ETag 优先，缺失时用 Last-Modified 条件验证。新鲜缓存不预留配额；304 有真实网络消耗。
- 管理字段 `policy_source` 为 `response`、`openapi` 或 `unknown`，只说明容量/窗口来源，不说明余额已计量。`local_recovery_at` 是下一笔恢复时间。页面用配额条和接口累计消耗图，最多比较本页前 10 项，并支持完整本页明细；不伪造时间趋势或把未计量画成零。

升级：停止全部旧 API/worker，备份数据库和加密配置，执行 `npm run db:migrate` 至 `00020_esi_sliding_budget.sql`（继续维护 River 迁移），再启用匹配代码。迁移将未到期的旧预算转为一笔保守债务，保留原到期时间；不清空预算、改任务到期时间或主动刷新 ESI。

新代码持续写兼容的聚合预算快照，便于停止服务后回退旧应用。不要并行运行两个算法。回退后再次启用新算法，必须停止旧 worker，并等待全部旧预算/保护窗口到期，或按备份恢复及迁移流程重新转换旧预算；不能直接复用回退期间已过时的逐笔账目。Down 删除账目但保留聚合预算，必须在停止新 worker 后进行。

### 观测验证时间

ESIResponse 新增 `ValidatedAt` 与 `Cached`，供在线采样区分上游验证与本地缓存读取。200/304 表示本次验证；缓存命中返回已有更新时间且 Cached=true。`ContentUpdatedAt` 保持内容变化口径。详情见[在线采样](attendance.zh-CN.md#在线时长口径)，业务不能用缓存点击次数制造在线时间。

## 配装写入

仅允许具备令牌的 POST /characters/{id}/fittings/ 使用 Mutation 标记。共用配额预留/结算和观测，跳过响应缓存读取、条件请求及缓存持久化，201 且有效 fitting_id 才确认成功。网络不确定结果由 fittings 保存并禁止盲目重发；授权仍检查本人归属和写 scope。见[配装指南](fittings.zh-CN.md)。
