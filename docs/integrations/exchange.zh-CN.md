## 合同自动交付与申请取消（2026-09-20，本地）

成员提交后只能申请取消，状态为 `cancel_requested`，继续占用果壳币与库存。当前站点管理员可驳回（回到 pending），或核实未交付、游戏合同已取消/不存在后勾选确认并批准。只有批准取消才同事务退款、按奖励内容版本恢复库存和写审计；重复提交不会重复退款。已发放终态不支持取消，前端和 API 均移除手动标记发放。

管理员在兑换列表查看接收角色、展开原奖励内容，复制页面显示的合同结算 ID，使用绑定在管理员本站账号下的 EVE 角色，在游戏中创建 **价格为零、支付奖励快照 ISK 金额（如有）的物品交换合同**。接收人为订单指定角色，描述必须仅包含该单号；一单一合同。ESI 不创建合同。本轮读取接收角色已有授权的个人合同缓存，因此必须保持该角色有效绑定与合同同步；不扩大军团数据权限，不新增 scope。

共享 River 每分钟扫描、每批最多 100 单，单据核对时钟持久化，每次约 5 分钟重查。实际更新还受 ESI 官方缓存和原同步队列影响。严格核对完整描述、订单后创建、管理员发放角色、指定接收人、明确为零的价格、全部物品类型/数量（包含原配装快照与额外物品，不读取后来修改的配置）。请求物品、蓝图拷贝、缺明细、数量不符均不能自动完成。无现金奖励时缺少 reward 按零处理；包含现金时必须有精确金额证据，不能以价差抵扣。price 缺失不冒充零价格。混合/纯现金合同的真实游戏证据仍待 FUL-01 验证。只有 `finished` 且实际领取人为接收角色、完成时间有效时标记 fulfilled，不重复扣币。未接取显示等待领取，异常显示原因和合同 ID；在游戏修正后等待再次同步核对，无人工强制通过入口。

## 吉他奖励核价（2026-09-20，本地）

## 管理员配置

1. 在“PAP 集结分比例”设置每分果壳币和兑换方式：`manual` 手动（Goose 26 默认）或 `automatic` 自动。`pap`（军团 PAP）与 `alliance_pap`（联盟 PAP）是独立来源，管理员可分别配置比例；联盟 PAP 支持管理员按月手动兑换及同步增量自动兑换，首次角色/月快照仅建立基线。支持 0.01–1,000,000 币/分，两位小数。首次比例为 0（未配置），不默认 1:1；手动模式允许先发 PAP，实际兑换前必须配置比例。自动模式发币时若未配置比例，PAP 与币一起回滚。
2. 在“果壳币价值”设置每币对应的 ISK 估值，整数 1–1,000,000,000,000。此值只用于奖励定价，不是自动 ISK 转账或可提现承诺。
3. 添加奖励：从本地 SDE 搜索物品，设置每份数量、每份 ISK 价值、库存及上架状态。数量 1–1,000,000，每份价值 1–1,000,000,000,000，手动可用库存 0–1,000,000 份。创建后类型与每份数量固定，换规格需新增并下架旧项。

币的最小单位为 0.01，存储与 API `*_minor` 均使用整数。例如 `minor_per_unit=250` 表示每 PAP 发 2.50 币。奖励所需最小单位 = `ceil(每份 ISK 价值 × 100 / ISK 每币)`，最低 0.01 币。例如每币 100 ISK，价值 401 ISK 的奖励需要 4.01 币。使用整数计算，按 0.01 币向上取整，无浮点余额运算。

## PAP 手动与自动兑换

PAP 保留考勤统计，不因兑换扣减。每个活动-角色分别记录已兑换单位数、首次实际兑换比例和有效币额；同账号多开汇入同一钱包。

- 手动：发 PAP 或加分不自动发币。站点管理员进入已结束且已发分的活动，在“兑换果壳币”预览已兑/待兑积分、角色数和本次币额，填写说明后统一兑换该活动全部待兑积分。普通成员、仅有考勤权限的组织者不能操作此兑换。
- 自动：发分事务只为新增 PAP 发币；保留既有权益的原比例。切换模式不扫描或补兑历史积分；自动模式下管理员仍可手动补兑待兑部分。例：手动阶段每角色已有4分、仅兑换2分，切自动后加到5分，只自动兑换新增1分，剩余2分仍待兑。
- 首次实际兑换使用当前比例，此活动-角色后续补兑/自动增加/冲正保持该比例；改价只影响尚无实际兑换比例的权益。预览包含比例版本和权益快照，变化后提交返回409，需重新核对。已发币不会因切换模式重复入账。
- 减分/撤销时，两种模式均将已兑换单位数限制到有效PAP上限，按原比例冲正超额币；尚未兑换的积分减少不扣币。消费后可形成欠额，阻止继续消费；不删除流水或订单。

历史无币记录及旧0比例占位可由管理员明确补兑，不自动补发。迁移保留已有币额与比例。停用exchange后不新增发币，仍保留既有权益减分/撤销的冲正；重新启用不扫描补币。

手动兑换沿用活动锁、排序币账号锁、比例共享锁和权益行锁；幂等键、原账号归属、报价指纹、当前管理员及军团对象权限均由后端核对。每个事务同时发布已兑换数量、币流水和操作审计；任一步失败全部回滚。PAP本身不被兑换操作改写。

## 奖励订单

一次申请一份，可选本人当前有效绑定角色接收；钱包属于本站账号，换主角色、解绑或换绑不会转移历史币与订单。可用币 = 来源当前有效入币 − 待发放占用 − 已发放消费，也等于该账号全部币流水的净额。

申请在同一事务核对币价/物品版本、库存、上架、当前绑定和币余额，并写入订单、负向占用流水及扣减库存。`pending` 为待发放，`fulfilled` 为已发放，`cancelled` 为已取消。游戏内实际交付由管理员创建合同，系统核对完成后标记已发放，此时不再次扣币。本站不通过 ESI 移动物品、创建交付合同或转账。

本人可对自己的待发放订单申请取消，管理员审核原因及交付状态后决定；批准取消才原子退币、退库存。终态不能重复处理，已发放退款待后续需求。订单永久保存原物品、数量、接收角色、币值、ISK 价值及所需币数；下架或调价不修改已有订单。库存表示当前未预留份数，取消可能增加库存。

## 权限、模块与接口

会话、资料完整度、CSRF 由宿主强制检查。新权限 `exchange.self` 是业务入口，普通用户只能操作本人对象；所有比例/物品配置、SDE 搜索、发放及全部订单读取逐次检查当前站点管理员。军团考勤、游戏职务、access.manage 不能代替；不新增可委托配置能力。

宿主注册已交付来源为 `pap`（军团 PAP）和 `alliance_pap`（联盟 PAP）；两者比例独立，联盟来源支持按月手动及增量自动兑换，首次快照不补发历史币。未知来源拒绝，不给浏览器提供“任意加币”接口。attendance 通过注入的事务业务回调提供权益快照，不导入 exchange 私有 store。将来新模块需提供稳定权益引用、旧/新单位数量、原账号归属及同事务生命周期；宿主显式接线、迁移来源配置后才开放，不是运行时脚本插件。

表归属：`exchange_shop_settings`、`exchange_rewards`、`exchange_redemptions`、`exchange_shop_audit`、`exchange_source_rates`、`exchange_source_awards`、`exchange_coin_ledger`。PAP 先锁活动、按序锁 PAP 账号，再按序锁币账号、锁来源比例及权益；兑换锁有效绑定、币账号、估值设置、奖励；处理锁币账号、订单，取消再更新奖励。无网络抓取进入写事务。配置/处理审计与业务同事务；交易幂等、防并发超卖及欠额检查由后端实施。

API 前缀 `/api/v1/exchange`，契约见 [OpenAPI](../../api/openapi.yaml)：

- `GET /context`：本人接收角色、已注册来源比例。
- `POST /sources`：配置来源比例和 `mode=manual|automatic`，需要 `id`、`minor_per_unit`、`version`、UUID `request_key`；旧客户端省略 mode 时保留原模式，`alliance_pap` 强制 manual。
- `GET /api/v1/attendance/events/{id}/conversion`：管理员预览本活动待兑积分、币额及 token。`POST` 同路径以 `version`、`request_key`、`token`、`reason` 确认兑换；只接受服务端已发 PAP，不接受任意成员或金额。
- `GET/POST /api/v1/attendance/alliance-pap/conversion`：管理员按当前联盟快照预览并确认手动兑换；`unit_scale=100` 表示内部按 0.01 PAP 保存，重复同步和重复请求不会重复入账。
- `GET /wallet?before=`：本人币流水，最新 30 条；来源入币/冲正、兑换占用、取消退回。
- `GET /rewards?after=`：本人余额与奖励，管理员含下架项，奖励每批 30。
- `POST /rewards/rate`、`POST /rewards/items`：币值与奖励配置。
- `GET /rewards/types?q=`：当前 SDE 物品 ID 或中英文名称字面子串，2–80 字符，最多 30 项，无 ESI 请求。
- `POST /rewards/claim`：指定本人接收角色、一份奖励和当前报价版本。
- `GET /rewards/orders?scope=mine|all&before=`：本人或管理员全部订单，每批 30。
- `POST /rewards/orders/{id}`：申请取消/审核取消、版本、说明与幂等键。

写入需 CSRF、UUID 幂等键与版本。同键同内容可重放，改内容或旧版本 409；币不足 `insufficient_coins`，不可兑换 `reward_unavailable`，未授权对象 404。网络结果不明时用同键同内容重试；过期报价关闭表单刷新后重新确认。配置和订单列表可分页，流水不依赖 PAP 报表时间过滤。
