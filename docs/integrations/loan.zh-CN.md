# 贷款模块

状态：统一贷款池改造已在本地完成，待随下一次前后端版本发布；生产当前仍是首期贷款池实现。贷款以游戏 ISK 为单位，全站只有一个统一贷款池，个人或军团可以提交出借额度；借款方是本站成员账号，一个账号的多个绑定角色共用贷款责任。

采用固定总利息、按期等额分期。本金和利息以 ISK 最小单位整数保存，每期分别保存两项，最后一期吸收舍入差额。出借额度提交后先处于待入金状态；出借方必须向配置的统一托管角色或军团创建完成的纯 ISK 合同，本站核验金额、方向、接取角色和物品为空，并取得全局合同占用后才进入池内现金。贷款审核通过不等于已经放款，放款前还要锁定池余额，放款核验后扣减池余额。

信用资料由管理员维护评分、总责任额度、无担保额度和规则版本。评分、额度、担保覆盖和抵押覆盖均在审批事务中重新检查；未配置额度、规则或池边界时不能批准。担保由担保人主动确认，抵押必须提交可核验的 EVE 合同及物品快照，管理员批准前保持待处理状态。模块不会自动扣款、自动处置抵押物或把钱包余额当作付款事实。

统一贷款池 `config` 至少应配置 `min_principal_minor`、`max_principal_minor`、`max_installments`；启用抵押审批时还必须配置 `collateral_haircut_bps`。池还要配置个人托管角色或军团托管主体，不能把网站余额或未核验的承诺额度当作现金。抵押覆盖额不能超过估值乘以该折扣，提交值和管理员配置不一致时拒绝审批；这些键没有隐式默认值。

付款接口使用现有 EVE 合同缓存服务。放款合同要求完成状态、完整金额和借款人收款角色匹配；还款合同允许部分金额，服务按最早未清分期分配并保留本金/利息明细。一个游戏合同只能被一个交付模块占用，重复核验返回冲突，不重复入账。

## 接口与权限

- `GET /api/v1/loan/context`：当前账号可见贷款池与信用摘要。
- `GET /api/v1/loan/contributions`、`POST /api/v1/loan/contributions`：查看并提交统一池个人/军团出借额度。
- `POST /api/v1/loan/contributions/{id}/deposit`、`POST /api/v1/loan/contributions/{id}/cancel`：核验入金合同或取消待入金记录。
- `GET /api/v1/loan/cases`、`GET /api/v1/loan/cases/{id}`：本人参与的贷款；管理者可读取其负责的贷款池。
- `POST /api/v1/loan/pools`：管理员配置唯一统一贷款池的托管角色/军团和规则；托管军团要求 `corporation.loan`。
- `POST /api/v1/loan/applications`：成员提交申请，保存固定条款和分期快照。
- `POST /api/v1/loan/cases/{id}/review`：出借方或军团贷款管理者审核，禁止借款人自审。
- `POST /api/v1/loan/cases/{id}/payments`：提交放款或还款合同并立即执行缓存核验。
- `POST /api/v1/loan/cases/{id}/guarantees`、`POST /api/v1/loan/guarantees/{id}/decision`：担保邀请与担保人确认。
- `POST /api/v1/loan/cases/{id}/collateral`、`POST /api/v1/loan/collateral/{id}/decision`：抵押登记与管理审批。
- `PUT /api/v1/loan/credit/{account}`：管理员维护评分与授信。

军团池的待审申请同时作为 `loan` 来源进入审批中心；审批中心只读聚合并复用本模块的审核接口，个人出借池继续留在贷款页内处理。

管理员进入贷款页后可在“统一贷款池配置”面板设置唯一托管角色/军团、规则和信用授信；任何成员可提交个人出借额度，军团额度要求对应军团管理权限。只有入金合同核验完成的额度才显示为可放贷余额；成员在存在开放统一池和有效授信后才能提交申请。

写请求由宿主会话鉴权和 CSRF 保护；业务服务继续检查贷款对象、出借方、借款方、绑定角色和合同范围。数据库迁移为 Goose 70，模块只有在 `MODULES` 启用 `loan` 后才显示页面。

首期仍需用真实 EVE 合同验证方向、金额、部分还款、重复占用和授权失效边界；生产部署和入口启用不代表真实合同闭环已验收。
