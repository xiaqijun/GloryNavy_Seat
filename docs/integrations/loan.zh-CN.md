# 贷款模块

## 单一个人额度（2026-10-16）

系统只有一个对成员展示和用于审批的个人额度，即最近有效评估快照的 `total_limit_minor`。收入、消费、评分和个人资产的测算公式不变；`unsecured_limit_minor`、`asset_support_limit_minor` 等保留为历史评估组成与接口兼容字段，不是第二道借款门槛，旧快照不重写。

剩余额度 = max(0, 个人额度 − 已占责任)，所需保障 = max(0, 本次本金 − 剩余额度)。已占责任沿用未结清贷款的完整本金（approved/funding/active/defaulted）与本人为他人已接受/生效的担保；结清或取消后释放，部分还款不提前释放整笔本金占用。例如剩余 10B，申请 12B，只需为超出的 2B 提供保障。该案件 accepted/active 担保与 approved/held 抵押可组合覆盖；邀请、待交付和未批准抵押不计入，其他案件的保障不可复用。信用状态 active 且快照新鲜时，额度为 0 的借款可由足额保障覆盖；缺失、过期或暂停信用仍不能批准。

`POST /api/v1/loan/cases/{id}/review` 的权限、非本人审批、状态和版本规则不变。批准事务依次执行活跃账号防合并检查、贷款私有账号额度锁（账号排序）、共享池行锁、案件行锁，再读取信用与已占责任并复核资金池可用现金和本单覆盖。接受担保也锁定担保人与借款人的额度并重读快照；担保人只能使用其未占用个人额度。批准与不可变评估快照、`credit_coverage_checked` 审计原子提交，审计保存 `model=single-credit-v1`、个人额度、已占责任、本金、所需及有效覆盖金额。没有新迁移，Goose 88 不变。前后端一起发布；回退旧审批代码会恢复旧双额度限制，新规则审批不能用旧规则追溯重算。

2026-10-16 个人资产抵押（Goose 88）：先从本人有效绑定角色的个人资产选择物品，保存 `loan_collateral_requests` 待交付记录，再完成游戏个人物品交换合同。宿主经 EVE 资产服务与 SDE 名称服务注入候选，不跨模块读取私有 store；沿用资产授权、凭据代次与快照校验。只开放机库顶层物品，装配及容器内容整体交付，排除蓝图复制品；每次至多 100 个顶层选择、展开至多 500 项，必须同地点。保存时重新读取权威快照，账号/案件锁与角色资产事务锁防止并发超选；保存来源角色、接收角色、数量和快照时间，不产生估值或授信覆盖。

- `GET /api/v1/loan/cases/{id}/collateral-assets?character_id=...`：仅借款本人读取其有效绑定角色资产，返回数量/可选余量与内容物；管理权限不能代替本人选择权限。
- `POST /api/v1/loan/cases/{id}/collateral-requests`：请求 `{"character_id":"111","items":[{"item_id":"501","quantity":"3"}]}`（本地示例 ID），仅 submitted/awaiting_acceptance 案件可创建。返回带 `LNC` 编号的 awaiting_delivery 记录。
- `POST /api/v1/loan/collateral-requests/{id}/cancel`：请求 `{"version":1}`，仅本人取消未登记交付的记录；版本冲突或已交付返回 409。案件撤销同事务取消待交付记录并释放选择数量，保留审计。
- 现有抵押登记接口新增可选字符串 `request_id`；新页面始终携带它。要求个人合同来源角色与冻结来源一致、接取人为冻结且仍配置的贷款专员，完成时间不早于保存记录，已完成且物品缓存完整，收取与支付均为 0，类型/数量多重集合完全相同，无索取物品、额外物品或蓝图复制品。事务内再次核对当前绑定、合同缓存、状态与版本，取得全局合同占用后登记 proposed 抵押并把请求改为 delivered，审计失败全量回滚。之后由非借款本人管理者批准才形成抵押覆盖。旧合同登记接口保留兼容。

详情新增 `collateral_requests`，权限沿用案件读取边界；请求归属通过 case_id 跟随账号合并，预览包含请求数量，首次原始归属保留于案件。取消、驳回或结清不删除交付证据或历史合同占用，也不代表游戏物品已退还。已有待交付记录后禁止回退忽略请求的程序；Goose 88 Down 在有记录时拒绝删除表。真实资产与游戏合同交付仍须联调，自动扫描抵押合同不在本次范围；成员显式选择已同步的完成合同核验。

2026-10-16 申请撤销：`POST /api/v1/loan/cases/{id}/cancel` 请求体为 `{"version":1}`，只允许案件当前借款账号撤销 `submitted` 申请；管理权限不授予代撤销能力。无效参数返回 400，非本人 403，状态或版本冲突（含重复提交）409。会话与 CSRF 沿用宿主保护。事务先检查活跃账号，再锁案件并复核归属、状态和版本，更新为 `cancelled`，将 invited/accepted/active 担保及 proposed/approved/held 抵押标为 released、递增各自版本，并写 `application_cancelled` 审计；任一步失败全部回滚。新增担保/抵押也在案件锁内复核状态，防止撤销后的迟到写入。已批准、放款或还款中的贷款不可走此接口。撤销不改现金/付款账本，不删除记录或历史合同唯一占用；额度释放不代表游戏抵押物已退还，实物仍需与管理者另行安排。审批中心从来源状态识别为历史记录，旧待审操作由版本保护拒绝。无新增迁移。

办理表单使用短选项和分组布局，详细计息规则按需展开；手机贷款记录直接显示详情与撤销入口，中英文同步。

2026-10-16 还款方式扩展：借款可选择按期限到期一次还清（1–365 天，页面预设 30/90/180/365 天）、指定日期一次还清，或分期。按期限仍从放款核验时起计算；分期间隔仍为 1/3/7/14/30 天。指定日期通过 `repayment_date=YYYY-MM-DD` 提交，要求单期且不同时提交非零间隔，可选北京时间明天至 365 天后的日期，截止时间为当天 23:59:59。Goose 87 新增 `requested_due_at` 保存约定日期，`first_due_at` 仍在核验放款后生成。指定日期申请冻结年利率，并按申请日至到期日的日历天数显示预计利息；放款时读取已核验合同完成日，按北京时间日历日差（至少 1 天）确定最终利息，不超过申请预计值，保存最终期数/金额与审计。合同完成时间必须不早于申请、不晚于核验时刻且早于到期截止；晚同步不会顺延约定日期。其他贷款利息保持申请快照。已存在指定日期贷款后禁止回退忽略该字段的程序，Down 会拒绝删除其日期。

状态：统一贷款池已发布。贷款以游戏 ISK 为单位，全站固定只有一个统一贷款池，个人或军团可以提交出借额度；借款方是本站成员账号，一个账号的多个绑定角色共用贷款责任。

利息采用现实贷款常见的年名义利率固定单利：管理员在风控设置中配置年利率 bps（100 bps = 1%），申请提交时按 `本金 × 年利率 × 期数 × 间隔天数 ÷ (10000 × 365)` 计算一次，按 ISK 最小单位四舍五入；本金和利息以整数保存，每期等额分摊，最后一期吸收舍入差额。申请同时冻结年利率快照，之后修改规则不会重算已有贷款；指定日期的利息在放款时按本页规则确定。贷款放款/还款合同按 0.01 ISK 精确核验，以便结清带小数的利息；出借、管理员入金与担保仍使用整数 ISK。普通成员出借额度提交后先处于待入金状态；出借方必须向配置的统一托管角色创建完成的纯 ISK 合同，本站核验金额、方向、接取角色和物品为空，并取得全局合同占用后才进入池内现金。站点管理员也可以直接登记一笔入池资金，该登记直接写入贷款流水账本，不创建或核验游戏合同。贷款审核通过不等于已经放款，放款前还要锁定池余额，放款核验后扣减池余额。

信用资料由系统根据本人历史贷款履约记录评估，评分、个人额度和规则版本均为系统产物，管理员不能手工修改。个人基础授信会读取当前账号有效绑定角色的个人钱包快照，在可配置观察窗口内分别汇总收入能力和消费能力，不计算净收入。两项能力各自按收入/消费授信比例和授信期限测算，再按收入能力权重（默认 70%）与消费能力权重（默认 30%）合成基础授信；权重可在风控设置中调整，不再设置个人授信硬上限。样本不足、数据过期、数据不可用或收入与消费均无有效记录时均按钱包证据不足处理，默认暂停个人授信，也可在风控设置中明确切换为回退到已核验本金池评分。钱包授权只控制证据是否可用，不作为评分因子。最终申请额度仍同时受统一池可用现金限制。当前 `system-v2` 权重为履约 55、负债压力 20、担保/抵押履历 10、PAP 评分 5、资产规模评分 10；授权状态和账号持续时间完全不进入评分。PAP 评分拆为两项：近一年已结束军团活动的活动集结率计 3 分，近 6 个月完整联盟 PAP 月快照中达到联盟月度门槛的月份占比计 2 分；两项按比例取整并分别封顶。缺少活动记录、联盟快照缺失或同步未完成时保持中性，不把不可用证据当作零分。资产规模评分已启用：读取当前账号所有有效绑定角色的个人 `esi-assets.read_assets.v1` 资产清单，使用 ESI 全服平均价表估算总资产，军团资产和钱包余额不计入。总估值低于 1 亿 ISK 为 0 分，达到 1 亿、5 亿、10 亿、50 亿、100 亿 ISK 时分别为 2、4、6、8、10 分；只跳过没有有效均价的物品，已成功读取且有均价的个人物品继续计入，部分角色读取失败会在证据中记录错误，完全没有可估值物品时保持中性。资产证据保存估值时间、快照标识和未估值物品数量，授权只控制能否读取/刷新证据。完整个人资产估值还按配置的资产 LTV 计入同一个个人额度，默认 1000 bps（10%）。系统按已结清贷款、已还分期、当前责任、逾期分期和违约记录计算评分；存在违约时信用状态暂停。额度由后台每 24 小时周期性评估并保存快照，页面、担保、抵押和审批只读取最近快照；无快照或快照过期时不能新增授信业务。个人额度测算以统一池已核验入账的实际现金余额作为本金池基数，按当前信用分动态计算；待核验出借承诺和网站余额不计入本金池。每次审批保存不可变信用评估快照，评分、额度、担保覆盖和抵押覆盖均在审批事务中重新检查。担保邀请金额同时受贷款本金比例和担保人当前可用总责任剩余额度限制，担保人确认时在事务内重新计算总责任剩余额，确认后才占用额度；抵押必须提交已完成的物品交换合同，后台读取并冻结物品快照，管理员批准前保持待处理状态，贷款结清后释放。模块不会自动扣款、自动处置抵押物或把钱包余额当作付款事实。

统一贷款池是固定单例，不提供池创建、切换或额度边界配置入口；模块迁移会按当前军团角色快照自动建立一个开放的军团池，贷款设置由有权限的贷款管理者从所有有效绑定的 EVE 角色中选择个人角色作为合同处理人，不再限制为管理者自己的角色。合同处理人只用于出借、放款和还款合同的收款方向；系统拒绝同一角色给自己交付合同。站点管理员可直接登记入池资金，登记记录带有操作审计，不依赖游戏合同。已核验的贷款流水和管理员登记仍是可放贷余额的账本来源，钱包快照不作为付款事实。未配置有效处理人时禁止对应合同核验。不能把网站余额或未核验的承诺额度当作现金。抵押覆盖额仍不能超过估值乘以已发布规则的折扣，提交值和规则不一致时拒绝审批。

贷款管理权限属于本站权限角色；配置合同处理人的 EVE 角色不会自动授予贷款管理权限。应先在权限管理中给账号授予 `corporation.loan`，再由有权限的贷款管理者选择有效的个人 EVE 角色。

付款接口使用现有 EVE 合同缓存服务。放款合同要求完成状态、完整金额和借款人收款角色匹配；还款合同允许部分金额，服务按最早未清分期分配并保留本金/利息明细。一个游戏合同只能被一个交付模块占用，重复核验返回冲突，不重复入账。

## 接口与权限

申请与付款写入的角色 ID 在服务和私有 store 之间保持 `int64`，SQL 金额加法显式使用 `bigint`，避免驱动编码或 PostgreSQL 参数推断失败。2026-10-16 修复不改变 HTTP 字段格式，无新增迁移；提交申请保存待审记录及利息快照，尚不生成还款日期、放款或增加池内现金。

- `GET /api/v1/loan/context`：当前账号可见贷款池与信用摘要。
- `GET /api/v1/loan/contributions`、`POST /api/v1/loan/contributions`：查看并提交统一池个人/军团出借额度。
- `POST /api/v1/loan/settings/custodian`：由贷款管理者设置接收合同的个人 EVE 角色；角色必须仍绑定到有效本站账号。
- `POST /api/v1/loan/settings/funding`：由站点管理员直接登记统一贷款池资金；金额写入贷款流水账本，不创建或核验游戏合同。
- `POST /api/v1/loan/contributions/{id}/auto-verify`、`POST /api/v1/loan/contributions/{id}/cancel`：按当前账号最近同步的完成合同自动核验，或取消待入金记录。
- `GET /api/v1/loan/cases`、`GET /api/v1/loan/cases/{id}`：本人参与的贷款；管理者可读取其负责的贷款池。
- `POST /api/v1/loan/applications`：成员提交申请，保存固定条款和分期快照。
- `POST /api/v1/loan/cases/{id}/review`：出借方或军团贷款管理者审核，禁止借款人自审。
- `POST /api/v1/loan/cases/{id}/payments`：提交放款或还款合同并立即执行缓存核验。
- `POST /api/v1/loan/cases/{id}/guarantees`、`POST /api/v1/loan/guarantees/{id}/decision`：担保邀请与担保人确认。
- `GET /api/v1/loan/guarantees`：读取当前账号收到的担保邀请。
- `GET /api/v1/loan/guarantees/candidates`：读取可邀请的有效绑定角色；服务端发送邀请时再次解析角色归属，列表不授予担保责任。
- `POST /api/v1/loan/cases/{id}/collateral`、`POST /api/v1/loan/collateral/{id}/decision`：抵押登记与管理审批。
- `GET /api/v1/loan/credit`：读取当前账号的系统信用评估结果；没有人工授信写入接口。
- `GET /api/v1/loan/settings/policy`、`POST /api/v1/loan/settings/policy`：贷款管理者读取或按版本更新收入授信策略，普通成员只能读取当前策略。
- `GET /api/v1/loan/evaluations`：读取当前账号的不可变信用评估快照列表。

军团池的待审申请同时作为 `loan` 来源进入审批中心；审批中心只读聚合并复用本模块的审核接口，个人出借池继续留在贷款页内处理。

贷款页面拆为两个导航页：`/loans` 是“贷款看板”数据看板，只展示统一池概况；`/loans/operations` 是“贷款办理”，承载申请、出借、担保、抵押和贷款记录，并在同页提供贷款看板、贷款办理、风控设置、评估记录四个标签。贷款办理标签的分页切换栏下方显示当前账号的信用评分和个人额度，不展示评分因子。风控设置仅对贷款管理者开放，可配置年利率、收入观察窗口、收入负债率、授信期限、评分系数、个人资产授信比例、收入样本门槛、证据有效期、担保/抵押覆盖上限，并设置合同处理人；评估记录展示当前账号不可变的周期与审批评估快照，只显示一个个人额度。统一池固定为单例，提交出借、提交借款、邀请担保和登记抵押均通过按钮打开弹窗；担保从有效绑定角色选择，抵押先从本人个人资产选择并保存待交付记录，再关联已完成物品交换合同，合同所有者和合同 ID 不再手填。分期申请间隔固定提供 1、3、7、14、30 天；一次性还款的期限与日期规则见本页开头；首期还款时间在实际放款合同核验后按放款时间加所选间隔生成，剩余分期按相同间隔生成。抵押估值使用池配置的固定折扣，覆盖金额由估值和折扣自动计算，后台仍按合同快照和收款方向核验。出借记录以列表展示并由接口直接返回出借角色名字，点击单条记录后才打开详情弹窗。待核验详情只展示创建合同所需的贷款专员角色名字、支付金额和合同备注复制字段；角色 ID 保留在接口和后台用于校验，名称暂不可用时页面才回退显示 ID。合同类型与无物品要求作为说明。合同完成并同步后由系统自动核验，不提供核验按钮；只有入金合同核验完成的额度才显示为可放贷余额。出借角色和收款角色从当前账号已绑定角色的昵称下拉框中选择，提交时由系统使用对应 ID；页面不要求用户记忆角色 ID。借款申请提交成功后刷新列表。信用评分和授信额度由系统根据履约记录、军团活动集结率、联盟 PAP 满足情况自动评估，页面不展示评分因子；资产规模评分按个人 ESI 总估值分档，不能用钱包余额替代，资产证据不完整时保持中性。任何成员可提交个人出借额度，军团额度要求对应军团管理权限；审批事务读取最近信用快照并复核资金、担保和抵押条件；没有新鲜快照时不能审批。贷款业务页面提供进入贷款办理的明确入口；贷款办理页始终显示“我的担保邀请”区域，担保人在这里查看贷款本金和担保金额并接受或拒绝邀请；接受前重新检查当前总责任额度。

写请求由宿主会话鉴权和 CSRF 保护；业务服务继续检查贷款对象、出借方、借款方、绑定角色和合同范围。数据库迁移为 Goose 70–73、79–82，模块只有在 `MODULES` 启用 `loan` 后才显示页面。

首期仍需用真实 EVE 合同验证方向、金额、部分还款、重复占用和授权失效边界；生产部署和入口启用不代表真实合同闭环已验收。
