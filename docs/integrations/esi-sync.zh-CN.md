## 1. 范围与入口

基础同步包含两项数据：`profile` 保存公开名称、军团与联盟；`authorization` 将角色归属、四组军团职务、军团名称/CEO/联盟组合成授权事实。网页读取本地数据，不直接调用 ESI。军团职务只是游戏事实，不能授予游戏内职务，也不会自动成为本站管理员。

“我的角色”详情卡显示资源状态、最近成功时间和图标操作。管理员进入 `/sync`，按名称/角色 ID、状态筛选，查看最近 20 条执行记录或重试。每页 30 项，按目标 ID 游标翻页。只展示精简错误分类，不返回令牌或 ESI 原始响应。

普通成员仅访问本人仍绑定的角色；本站管理员可 GET 其他成员有效绑定角色的同步状态，POST 本人刷新保持独立归属检查；管理入口要求独立的全局权限 `eve.sync.manage`。`access.manage` 本身不包含该能力，本站管理员保留全局管理权。管理写操作和本人刷新均校验 Origin、CSRF 和后端权限。新权限已加入已交付功能目录。

## 2. 调度与一致性

River 0.47.0 使用 PostgreSQL，宿主启动一个运行时：`eve_control` 并发 1，每 30 秒扫描到期目标；`eve_characters` 并发 2；合同扩展使用独立 `eve_contracts` 并发 1；SDE 使用独立 `eve_sde` 并发 1（15 分钟业务预算），不会按角色重复派发。扫描器启动时执行，持久化的 `next_due_at` 才是业务调度依据。队列载荷仅含目标 ID 与授权代次，任务名带 `.v1`。目前是可信编译时模块注册，没有运行时安装插件。

凭据保存、代次推进、目标初始化和 `InsertTx` 同事务提交。活动任务按参数去重，已完成任务不阻止下一轮入队。目标使用 90 秒租约、递增 fence、授权代次和已完成任务 ID；正常抓取预算 55 秒，River 超时 60 秒。网络请求位于业务写事务之外，最终发布重新校验凭据归属、代次和租约。队列至少一次执行，通过业务幂等防止重复或旧任务覆盖。

关闭时先停止接单并等待 worker，超时取消，再关闭数据库池。进程中断后 River 救援未完成任务；业务扫描可恢复丢失的调度触发。重授权使旧任务失去写入资格；解绑级联删除凭据、目标、缓存及快照。人工操作审计独立保留。

## 3. 缓存、刷新与限流

ESI 请求现由独立客户端与无令牌业务接入服务统一处理，旧内存回退路径已移除。`/sync` 新增令牌页签，查看凭据有效期、刷新和请求观测；Goose 18、管理权限、统计口径及异常边界见[接入层与令牌观测](esi-client.zh-CN.md)。原有调度、缓存与限流约束继续适用。

- 公开缓存按请求共享；私有缓存额外按角色和授权代次隔离，使用 `EVE_TOKEN_KEY` 加密。缓存键包含兼容日期 `2026-08-18`，遵守 `Expires` 和 GET 的 ETag/304。
- 最近尝试、最近成功、内容变化时间分别保存。相同 200 或 304 不改变内容变化时间。缓存命中不延长其验证时间；授权缓存信任上限 2 小时，过期事实不会无限续期，权限快照另有 5 分钟有限宽限。
- Token 刷新使用角色凭据行锁，锁内预算 10 秒，重新读取后再决定是否刷新；先提交轮换令牌，再抓取业务数据。401 最多触发一次有依据的刷新。403 仅阻断该资源，不删除 refresh token。明确失效或 scope 丢失才要求重授权。
- Goose 20 使用兼容日期路由目录、持久化并发预留、实际 Used 结算和逐笔到期恢复；Remaining 只收紧预算，缺失计量保守留额。429/旧 420 分别遵守重试与公共错误保护，保留 200ms 平滑节流。详见[客户端算法与升级](esi-client.zh-CN.md)。
- 网络/5xx 指数退避并加抖动；连续 5 次失败标为失败，1 小时后探测。限流与换团等待不累计失败。人工刷新只排队，不能越过缓存或限流等待。
- 检出换团时先删除旧职务事实，持久化等待旧缓存到期的屏障，再取得新军团事实；重授权不能绕过屏障。

单响应上限 1 MiB；缓存总量上限 10,000 项/64 MiB，写入串行核对配额。每次扫描最多清理 500 项：缓存过期一天后清理，成功执行记录保留 14 天，其他已结束记录 30 天。River 自身任务清理由其维护服务负责；人工操作审计没有自动删除策略。

## 4. 配置与迁移

沿用 `.env` 中的 `DATABASE_URL`、`MODULES`、EVE Client ID/Secret、`PUBLIC_ORIGIN` 和 `EVE_TOKEN_KEY`。启用 `eve` 且配置登录时必须提供密钥，即使关闭 `access`。可设置 `ESI_USER_AGENT=GloryNavy/0.1.0 (contact: admin@example.com)`，部署前替换为真实运维联系方式；默认只含应用名和版本。私钥和连接密码不要写入前端配置。

升级顺序：停止旧 API/轮询 worker → 备份数据库及加密密钥 → `npm run db:migrate` → 构建并启动新 API → 检查同步服务与任务状态。该脚本先运行 Goose `00010_eve_sync.sql`，再运行 `cmd/jobs-migrate` 的 River 自有迁移；两条迁移线相互独立。API 不自动迁移数据库。新迁移按原到期时间为现有凭据创建两个目标，保留已失效凭据的阻断状态。

回退优先停止新 worker 并保留新增表，再恢复兼容的应用版本；不要让旧轮询器和 River 同时运行。需要回退数据时，停机恢复同一时点数据库与密钥，单独验证备份。Goose Down 会删除同步数据，不应作为日常回退步骤。

## 5. 接口与故障处理

接口前缀 `/api/v1/eve`，完整结构见 [OpenAPI](../../api/openapi.yaml)。

| 方法与路径 | 用途 |
| --- | --- |
| GET `/sync/characters/{id}` | 本人或管理员查看有效绑定角色状态 |
| POST `/sync/characters/{id}/refresh` | 本人排队，JSON 可指定 `resource` |
| GET `/sync/targets` | 管理查询，`search`、`state`、`after` |
| GET `/sync/targets/{id}/runs` | 精简执行记录 |
| POST `/sync/targets/{id}/retry` | 管理重试 |

202 的 `queued`、`already_pending`、`deferred` 都不是同步成功。`blocked` 返回 409，需要重新授权、检查游戏权限或处理身份问题；不能不断重试。服务未启动返回 503，并通过状态接口 `available=false` 展示。正常健康检查不代替 worker 就绪检查。

已覆盖真实 PostgreSQL 隔离测试：事务回滚、重复派发、重启恢复、fence、代次、并发刷新、轮换后 ESI 失败、403 保留凭据、换团隔离、缓存 304、共享限流、越权和 CSRF。浏览器测试使用模拟数据验证桌面/手机状态与重试。CCP 刷新成功但数据库提交结果丢失无法保证恢复，只能按凭据实际状态重试或重新授权。

## 6. 后续扩展

新增资源在 eve 模块登记版本化 worker、所需 scopes、独立目标/数据表、缓存与重试策略及测试，再开放对应功能权限。其他模块通过公开服务注入协作，不导入 eve 私有 store。未来需要独立 worker 进程时复用运行时装配并重新核定总并发，不能把每实例并发当成全局上限。

本期未接入资产、钱包、全军团成员采集、报表、SDE 导入或独立通用事件总线。SDE 沿用接入方案，另行实施。

## 同步历史清理性能（Goose 46，2026-09-23 已发布）

历史清理仍随 30 秒控制调度执行，每批合计最多 500 条；成功完成记录保留 14 天，其他完成记录保留 30 天，未完成记录不清理。Goose 46 为成功/其他完成记录分别建立 (finished_at,id) 部分索引。候选查询先对各分支取最多 500 条，再合并为全局最早完成的 500 条（同一时间按 id）；取代按 id 排序的全表扫描。删除时再次检查保留期，保持发布 fence/缓存/业务审计边界不变。

迁移使用非事务的 CREATE INDEX CONCURRENTLY，失败重试会先删除本迁移拥有的同名索引，避免跳过 INVALID 索引。升级应先完成 Goose 46 再发布查询；索引不会删除历史数据，Down 仅移除这两个索引。运行旧程序仍正确但清理可能恢复旧性能，新程序缺失索引也可能慢；回退程序可保留索引，无需 Down。迁移工具当前两分钟超时，超时须先检查索引状态并重试，不得把失败当作已完成。

应用侧慢查询日志配置与可见范围见[数据库性能观测](../database-performance.md)。本地模拟 184 万条未过期历史对照：旧候选 SELECT 394.107 ms，新清理语句（删除 0 行）0.475 ms；不等同于生产保证。

2026-09-23 生产验证：后端 v0.1.0-sync-retention-observation-20260923、两个索引有效；无过期候选时查询执行约 1.059ms，后台控制调度及同步继续运行。
