# 提醒与游戏内邮件

## 普通邮箱提醒（已发布）

普通邮箱与游戏内邮件是独立渠道；管理员在提醒页面配置 SMTP 地址、端口、TLS/STARTTLS、发件账号、发件邮箱和授权码，并选择提醒类型。授权码由服务端使用 EVE_TOKEN_KEY 派生密钥加密，只写且不返回；默认关闭。仅支持经过证书验证的 TLS，禁止明文认证。更换服务器或发件账号时，需重新填写授权码。

邮箱配置表单在更换服务器或发件账号时明确提示重新填写授权码；启用中的配置缺少授权码时不能保存。该提示修复在前端实现，后端的凭据保留和版本冲突规则不变。

成员在“我的角色”填写收件邮箱并以单次验证码验证，验证码有效期十分钟、每账号一分钟最多发送一次、最多五次错误尝试；验证后可启停个人邮箱提醒。邮箱变更以新验证码确认，账号合并保留目标账号自身的邮箱设置并保留原回执。邮箱发送使用独立回执及每账号五分钟限制，复用游戏邮件的已授权事件和正文；每封最多五项，发送前重新检查当前账号、邮箱配置和来源权限。明确失败可由管理员请求重试，未知结果不自动或手动重发。隔离数据库和模拟页面测试通过；生产默认关闭，真实 SMTP 及登录页面仍待联调。

Goose 111 新增邮箱配置、个人验证状态和独立回执；使用数据后禁止 Down，回退前先停用并取消 `reminder.email-scan.v1` / `reminder.email-send.v1` 作业，保留配置与回执。邮箱地址、验证码和授权码不写入日志。

首版待审批来源包括：福利申请与取消、兑换取消、军团贷款，以审批中心实时来源返回的可操作事项为准，排除本人申请。页面 `/reminders` 位于系统管理，仅当前站点管理员可配置与读取游戏邮件发送记录。旧 OneBot 和 QQ 审批提醒保持停用。

## 官方 QQ 群建筑提醒（已发布）

Goose 110 新增独立群建筑监测，默认关闭，不改变游戏邮件配置。站内“提醒”页面的“QQ群建筑提醒”区域由当前站点管理员选择已接入军团、填写官方群 OpenID 和启停推送，并查看当前军团最近 50 条发送记录。群 OpenID 必须来自该官方机器人的群事件，不能使用数字群号或历史 OneBot 标识。启用时复核操作者、军团建筑对象权限和当前机器人配置；更换 AppID 后必须填写新机器人收到的群标识。修改使用 revision 防并发覆盖，不修改配置时不重建基线；实际修改后保留旧回执并重新建立基线。

配置接口为 `GET/PUT /api/v1/community/qq/structure/settings`，发送记录为 `GET /api/v1/community/qq/structure/deliveries`；均要求当前管理员，写入需 CSRF，记录还需当前军团对象权限。保存与后台监测要求数据库连接池至少 3 个连接，不满足时保存返回服务不可用。保留历史记录，旧版本未发送记录在页面显示为已失效，超过两分钟仍为 sending 的记录显示为结果待确认；均不自动重试。系统因 QQ 40034105 停用时同时推进 revision，避免旧页面覆盖。生产发布前后端需配套；不能把不确定或已发送记录直接改成 pending。

每分钟读取建筑管理的有效本地快照，首次观察只建立状态基线；后续比较已观察建筑和已观察服务的状态，缺失不视为摧毁或离线。燃料 72 小时、24 小时内及耗尽、已知的未来拆除时间分别提醒，POS 沿用页面估算。发送前再次核对当前建筑与燃料／拆除条件，过期告警不发送；每条消息最多 5 项。来源依赖 ESI 采样，不能保证捕获两次采样之间短暂出现后恢复的状态，也不把快照时间当成实时事件时间。

2026-10-31 已发布：新生成的 QQ 建筑提醒分别列出快照中的建筑名称、建筑类型和星系，并以北京时间显示已知的燃料到期及计划拆除时间；POS 燃料耗尽时间注明为估算。没有建筑名称时使用编号并附可用类型，缺失时间不猜测。已发送及已生成的历史记录保持原样，监测配置、基线和去重规则不变。标注为测试的示例消息已被 QQ 平台接受，真实建筑事件的客户端显示待验收。

本地未发布：建筑类型调整为单独一行；名称不可用时显示未知及可用的类型 ID。

通知在发送前持久认领；已发送、明确拒绝、结果不确定和已过期分别留存。网络超时或进程中断产生的不确定结果不自动重试；平台拒绝主动发送并返回 40034105 时停用该群监测，待管理员解决权限后处理记录并重新启用。仅 QQ 平台接受请求不等同于客户端已读。已建立配置或记录后禁止 Goose 110 Down；回退前停用监测并取消 `community.qq-structure-scan.v1` 队列作业，保留监测配置、基线和回执。

## 可选提醒（Goose 98）

共 20 类，来源模块启用后才可选择；新增类型不会因升级自动勾选或发送。原发件角色、授权与总开关保留。按个人账号发送到当前主角色，邮件包含对应业务明细、操作提示和页面链接，见下方“邮件正文”。

| 提醒 | 收件人与触发条件 |
| --- | --- |
| 待审批提醒 | 当前可审批人，沿用审批中心权限并排除本人申请 |
| 福利申请进度、兑换进度、贷款进度 | 单据所属账号，需补充资料、批准、完成、拒绝、取消等最新阶段；兑换为完成/取消 |
| 待领取合同 | 当前有效绑定角色的个人待接取合同，精确指定该角色、未过期、当前授权代次与两小时内成功同步；不推送军团公共合同 |
| 待处理担保、待交付抵押 | 担保人处理邀请/追偿/争议，借款人交付已选抵押物；终结贷款排除 |
| 待放款提醒、出借到账 | 当前资金池处理人处理已批准/放款中贷款（排除本人借款）；出借人收到已核验入金进度 |
| 贷款即将到期、贷款逾期 | 已放款贷款的借款人；到期前三天、逾期未付，每个分期与截止时间分别去重，不把未放款计划当欠款 |
| PAP 未达标、PAP 变动 | UTC 月末七天内，当前月完整且 24 小时内同步的联盟 PAP 小于已配置目标；变动通知读取本人军团 PAP 流水。未知数据不按零分处理 |
| 果壳币变动 | 本人的新币流水，包含入账、消费、退款与冲正 |
| 角色授权失效 | 当前本人绑定及 owner 匹配的重新授权状态，按角色/授权代次去重 |
| 建筑燃料与拆除 | 沿用建筑页面的当前军团范围与权限；剩余 72 小时、24 小时、已耗尽及已知拆除时间。POS 使用现有估算；燃料截止日和等级去重，不按每次采样秒差重复 |
| 数据同步异常 | 仅当前站点管理员；当前代次至少连续失败三次，最后成功已超过一小时。普通重试、授权失效和旧代次排除；恢复后新失败可再次提醒 |
| 预警服务异常 | 本人 Sentry 密钥 sync_error 持续至少 15 分钟，按该次错误状态更新时间去重；不在提醒扫描中访问远端 |
| 反馈回复与进度、待处理反馈 | 申请人收到其他人的回复/状态变更；当前站点管理员处理尚未关闭的他人反馈 |

新增/重新启用类型建立起始时间。进度和流水只读取启用后、最近 30 天内的变化，不补历史；当前仍待处理的事项可在首次启用时通知。通知读取本地已提交事实，每分钟采样最新阶段，不保证发出一分钟内每个短暂中间状态。每类按账号独立去重，来源读取失败不清除该类回执，其他正常类别继续处理；各类按最久未尝试顺序轮换，共享每账号五分钟一封的限制。

除审批重入阶段外，同一事件参考不会因数据暂时不可见、权限变化或配置停用后恢复而重发；新分期、状态、流水、授权代次、故障恢复后的新事件独立计数。收件与来源权限在实际发送前再次核对。去重使用原有不含业务正文的引用，明细另经授权投影读取；SQL 留在来源私有 store，reminder 不修改单据、付款、币账或原始 ESI 数据。

迁移新增所选类型、各类起点及回执类型，保留既有审批回执。新版前后端同时发布；使用新类型后 Goose 98 Down 拒绝。回退旧版前必须先关闭发送、取消 reminder 队列未结束任务，并保留 Goose 98 和多类型回执，不能运行会跨类型清理回执的旧发送逻辑。


## 邮件正文

20 类提醒使用各业务模块在当前权限下读取的临时明细。标题为对应提醒名称；正文按“事项／单号 → 业务字段 → 下一步操作 → 查看详情”排列，默认中文。发件人和收件主角色沿用现有配置，不新增手动指定收件人的配置。

| 业务 | 正文内容 |
| --- | --- |
| 待审批 | 申请类型、单号、申请人、事项、领取角色、申请时间，以及已有明确单位的金额；取消审核与普通申请分开标明 |
| 福利、兑换进度 | 单号、项目或奖励、领取角色、当前结果、处理意见、处理时间；有记录时显示核准 ISK、奖励 ISK／果壳币及实物摘要。兑换取消标明退回果壳币 |
| 贷款进度 | 编号、资金池、本金、本息合计、处理意见、更新时间及已确定的首期日期；待确认条款明确提示下一步 |
| 到期／逾期 | 贷款编号、资金池、期数、扣除已还部分后的本期剩余本金／利息／应还金额和到期时间 |
| 担保／抵押 | 担保对应借款人、金额、当前邀请／追偿／争议；抵押交付编号、交付与接收角色、物品种类和游戏合同交付提示 |
| 放款／出借 | 借款人、收款角色、资金池、贷款本金及处理意见；出借记录、已核验到账金额、角色、合同 ID 与到账时间。放款链接进入贷款页，支持个人资金池 |
| 个人合同 | 合同 ID、标题、类型、领取角色、价格、报酬、抵押金（如有）、截止时间；要求在游戏内核对后接取 |
| PAP／果壳币 | 活动与参战角色、带正负号的变动量、原因和发生时间；PAP 月目标显示月份、当前、目标、差额、截止时间和数据时间 |
| 授权／建筑／同步／预警 | 具体角色、建筑／军团／星系或密钥名称；授权状态、燃料／拆除时间、同步项目／连续失败次数／上次成功、受控原因与处理入口；不输出令牌、密钥或原始远端错误 |
| 反馈 | 编号、BUG／功能需求类型、标题、当前状态；提交人及内容摘要，或回复人、回复摘要、该次状态变更与发生时间 |

ISK 与果壳币用整数最小单位格式化，保留两位小数、正负号和千位分隔，不经浮点换算或 M/B/T 缩写。所有邮件时间明确标注 UTC。角色优先显示本地已缓存名称，缺少名称时回退角色 ID；缺失的业务字段不虚构；原始备注、反馈等按文字转义，长内容显示省略号，完整内容进入详情页查看。

每封同类邮件最多 5 项，沿用每账号五分钟一封与分类轮换。只占用本封实际列出的事件回执，剩余事项后续继续发送；不把正文未列出的事项标为已通知。转义后的正文不超过 9,500 字符，保留完整标签与详情链接。明细缺失、重复键或读取失败时不发送简略兜底邮件，保留明确未发出的失败记录供管理员重试。

模块经宿主注入 `ReminderDetails`，只在模块自己的授权事件键范围内查询私有 store；审批复用实时来源，建筑复用原已鉴权快照。明细仅在内存构建，不写入提醒表、作业或日志。读取明细之后再次检查配置版本、当前主角色、发件授权和来源权限／事件集合；旧接收人或已失去权限的明细不得发送。既有去重键、数据库结构、授权 scopes 和发送开关不变。实际游戏客户端排版与收件仍需真实验收。

## 配置

在 `MODULES` 中启用 `reminder`，同时启用 `identity,access,eve,approval`；Goose 93 默认关闭发送，发件角色为空。管理员在 EVE 开发者应用允许的权限中加入 `esi-mail.send_mail.v1`，然后在提醒页面选择**本人已绑定角色**，点击“授权发信”，完成同一角色的 SSO 后返回页面，选择提醒类型，勾选“启用推送”并保存。

普通登录仍使用既有 57 项 scopes（fittings 启用时 58 项）。只有显式 `POST /api/v1/eve/characters/{id}/reauthorize?purpose=reminder-mail` 请求在基线上增加发信权限；额外权限由服务器固定，浏览器不能自选 scopes。开始与回调都核对当前管理员、会话、绑定和指定角色，flow 保留 scopes 快照并校验实际授权。此授权不自动开启发送，之后普通重新授权可能移除发信 scope，需要再次授权发信。另一管理员可暂停原发件角色；启用或更换时须选择自己已授权的角色。

授权失败时，提醒页显示具体恢复提示；角色不符会显示需选择的发件角色。回调日志只记录固定失败原因、请求 ID、预期/返回角色 ID，不记录授权码、令牌、Cookie、完整查询串或 SSO 原始响应。日志用于诊断，不代表授权已保存。

## 发送与权限

- 每分钟扫描，按账号使用独立 River 作业，载荷仅账号 ID。发送给收件账号的当前主角色，一封邮件包含同类事项的个人业务明细与入口链接，不发送给整军团、联盟或邮件列表。
- 宿主注入 `approval.PendingNotificationKeys`、当前主角色、有效绑定、管理员校验与 EVE 发信网关。提醒私有 store 仅维护配置、去重回执与发送历史，不复制审批状态，不访问来源私有 SQL。
- 发件角色必须持续属于配置账号，该账号仍是站点管理员，授权的 owner 与 generation 必须有效。发送前再次核对配置版本、主角色、待办与当前来源权限；来源读取失败不当作无待办清空回执。
- 复用 ESI 共享刷新、授权代次、限流与 POST 非缓存通道。`approved_cost=0`，不授权 CSPA 费用；收费或上游拒绝会失败，不自动花费 ISK。
- 每账号最多每 5 分钟尝试一封。当前待审阶段首次启用也会提醒，持续不变不会重复；已观察到阶段结束、随后重新进入时可再次提醒。设置修改、换发件角色、进程重启不会清空去重。
- 发送前先持久化占用；网络超时、无有效邮件 ID、5xx 或进程中断按 `unknown`，不自动重发。5 分钟后仍为 `sending` 转 `unknown`。明确拒绝等 `failed` 可由管理员点击重试，重新核对当前事实并遵守频控。`sent` 表示 ESI 返回邮件 ID，客户端收到仍需真实验收。
- 配置变更与远端发信无法构成原子事务；发出请求前完成最终检查，已提交到 ESI 的请求无法撤回。保存停用不撤销已在途邮件。

## 数据、合并与恢复

Goose 93：`reminder_settings`、`reminder_audit`、`reminder_receipts`、`reminder_deliveries`。活动回执持续保留；非活动回执与非发送中历史默认保留 90 天，配置/重试审计保留。独立 `reminder` 队列并发 1；模块关闭时不新增周期任务，已入队作业休眠，不访问远端。

合并参与方无论模块是否启用都注册：历史归到目标账号并保留首次 `original_account_id`，去重回执保守合并；来源账号作为发件人时暂停配置，不转移管理员权限或发送同意。Goose Down 在已有审计/发送记录或配置启用时拒绝。回退不支持本模块的程序前停用发送、取消 `reminder.scan.v1` / `reminder.send.v1` 未结束任务、从 `MODULES` 移除 reminder，并保留 Goose 93 和回执；有合并数据时不得回退到遗漏参与方的程序。

接口见 [OpenAPI](../../api/openapi.yaml)，页面规范见 [提醒页面](../ui/reminder.md)。官方依据：[ESI OpenAPI，兼容日期 2026-08-18](https://esi.evetech.net/meta/openapi.json?compatibility_date=2026-08-18)，`POST /characters/{character_id}/mail`，scope `esi-mail.send_mail.v1`，共享 `char-social` 桶 600/15 分钟。

实现、测试与生产状态以[项目状态](../project-status.md)为准；实际发件人授权与游戏客户端收信见 REMINDER-01。
