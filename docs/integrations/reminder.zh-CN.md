# 提醒与游戏内邮件

首版待审批来源包括：福利申请与取消、兑换取消、军团贷款，以审批中心实时来源返回的可操作事项为准，排除本人申请。页面 `/reminders` 位于系统管理，仅当前站点管理员可配置与读取发送记录。QQ 保持暂停，不读取 QQ 绑定，也不恢复旧机器人。

## 可选提醒（Goose 98）

共 20 类，来源模块启用后才可选择；新增类型不会因升级自动勾选或发送。原发件角色、授权与总开关保留。按个人账号发送到当前主角色，邮件只有类型、数量和对应页面链接。

| 提醒 | 收件人与触发条件 |
| --- | --- |
| 待审批提醒 | 当前可审批人，沿用审批中心权限并排除本人申请 |
| 福利申请进度、兑换进度、贷款进度 | 单据所属账号，需补充资料、批准、完成、拒绝、取消等最新阶段；兑换为完成/取消 |
| 待领取合同 | 当前有效绑定角色的个人待接取合同，精确指定该角色、未过期、当前授权代次与两小时内成功同步；不推送军团公共合同 |
| 待处理担保、待交付抵押 | 担保人处理邀请/追偿/争议，借款人交付已选抵押物；终结贷款排除 |
| 待放款提醒、出借到账 | 当前资金池处理人处理已批准/放款中贷款（排除本人借款）；出借人收到已核验入金进度 |
| 贷款即将到期、贷款逾期 | 已放款贷款的借款人；到期前三天、逾期未付，每个分期与截止时间分别去重，不把未放款计划当欠款 |
| PAP 未达标、PAP 变动 | UTC 月末七天内，当前月完整且 24 小时内同步的联盟 PAP 小于已配置目标；变动通知读取本人军团 PAP 流水。未知数据不按零分处理 |
| 果壳币变动 | 本人的新币流水，包含入账、消费、退款与冲正 |
| 角色授权失效 | 当前本人绑定及 owner 匹配的重新授权状态，按角色/授权代次去重 |
| 建筑燃料与拆除 | 沿用建筑页面的当前军团范围与权限；剩余 72 小时、24 小时、已耗尽及已知拆除时间。POS 使用现有估算；燃料截止日和等级去重，不按每次采样秒差重复 |
| 数据同步异常 | 仅当前站点管理员；当前代次至少连续失败三次，最后成功已超过一小时。普通重试、授权失效和旧代次排除；恢复后新失败可再次提醒 |
| 预警服务异常 | 本人 Sentry 密钥 sync_error 持续至少 15 分钟，按该次错误状态更新时间去重；不在提醒扫描中访问远端 |
| 反馈回复与进度、待处理反馈 | 申请人收到其他人的回复/状态变更；当前站点管理员处理尚未关闭的他人反馈 |

新增/重新启用类型建立起始时间。进度和流水只读取启用后、最近 30 天内的变化，不补历史；当前仍待处理的事项可在首次启用时通知。通知读取本地已提交事实，每分钟采样最新阶段，不保证发出一分钟内每个短暂中间状态。每类按账号独立去重，来源读取失败不清除该类回执，其他正常类别继续处理；各类按最久未尝试顺序轮换，共享每账号五分钟一封的限制。

除审批重入阶段外，同一事件参考不会因数据暂时不可见、权限变化或配置停用后恢复而重发；新分期、状态、流水、授权代次、故障恢复后的新事件独立计数。收件与来源权限在实际发送前再次核对。模块只暴露不含业务正文的引用；SQL 留在来源私有 store，reminder 不修改单据、付款、币账或原始 ESI 数据。

迁移新增所选类型、各类起点及回执类型，保留既有审批回执。新版前后端同时发布；使用新类型后 Goose 98 Down 拒绝。回退旧版前必须先关闭发送、取消 reminder 队列未结束任务，并保留 Goose 98 和多类型回执，不能运行会跨类型清理回执的旧发送逻辑。


## 配置

在 `MODULES` 中启用 `reminder`，同时启用 `identity,access,eve,approval`；Goose 93 默认关闭发送，发件角色为空。管理员在 EVE 开发者应用允许的权限中加入 `esi-mail.send_mail.v1`，然后在提醒页面选择**本人已绑定角色**，点击“授权发信”，完成同一角色的 SSO 后返回页面，选择提醒类型，勾选“启用推送”并保存。

普通登录仍使用既有 57 项 scopes（fittings 启用时 58 项）。只有显式 `POST /api/v1/eve/characters/{id}/reauthorize?purpose=reminder-mail` 请求在基线上增加发信权限；额外权限由服务器固定，浏览器不能自选 scopes。开始与回调都核对当前管理员、会话、绑定和指定角色，flow 保留 scopes 快照并校验实际授权。此授权不自动开启发送，之后普通重新授权可能移除发信 scope，需要再次授权发信。另一管理员可暂停原发件角色；启用或更换时须选择自己已授权的角色。

授权失败时，提醒页显示具体恢复提示；角色不符会显示需选择的发件角色。回调日志只记录固定失败原因、请求 ID、预期/返回角色 ID，不记录授权码、令牌、Cookie、完整查询串或 SSO 原始响应。日志用于诊断，不代表授权已保存。

## 发送与权限

- 每分钟扫描，按账号使用独立 River 作业，载荷仅账号 ID。发送给收件账号的当前主角色，一封邮件只包含对应类型、个人数量与业务入口链接；不含申请人、金额或业务明细，不发送给整军团、联盟或邮件列表。
- 宿主注入 `approval.PendingNotificationKeys`、当前主角色、有效绑定、管理员校验与 EVE 发信网关。提醒私有 store 仅维护配置、去重回执与发送历史，不复制审批状态，不访问来源私有 SQL。
- 发件角色必须持续属于配置账号，该账号仍是站点管理员，授权的 owner 与 generation 必须有效。发送前再次核对配置版本、主角色、待办与当前来源权限；来源读取失败不当作无待办清空回执。
- 复用 ESI 共享刷新、授权代次、限流与 POST 非缓存通道。`approved_cost=0`，不授权 CSPA 费用；收费或上游拒绝会失败，不自动花费 ISK。
- 每账号最多每 5 分钟尝试一封。当前待审阶段首次启用也会提醒，持续不变不会重复；已观察到阶段结束、随后重新进入时可再次提醒。设置修改、换发件角色、进程重启不会清空去重。
- 发送前先持久化占用；网络超时、无有效邮件 ID、5xx 或进程中断按 `unknown`，不自动重发。5 分钟后仍为 `sending` 转 `unknown`。明确拒绝等 `failed` 可由管理员点击重试，重新核对当前事实并遵守频控。`sent` 表示 ESI 返回邮件 ID，客户端收到仍需真实验收。
- 配置变更与远端发信无法构成原子事务；发出请求前完成最终检查，已提交到 ESI 的请求无法撤回。保存停用不撤销已在途邮件。

## 数据、合并与恢复

Goose 93：`reminder_settings`、`reminder_audit`、`reminder_receipts`、`reminder_deliveries`。活动回执持续保留；非活动回执与非发送中历史默认保留 90 天，配置/重试审计保留。独立 `reminder` 队列并发 1；模块关闭时不新增周期任务，已入队作业休眠，不访问远端。

合并参与方无论模块是否启用都注册：历史归到目标账号并保留首次 `original_account_id`，去重回执保守合并；来源账号作为发件人时暂停配置，不转移管理员权限或发送同意。Goose Down 在已有审计/发送记录或配置启用时拒绝。回退不支持本模块的程序前停用发送、取消 `reminder.scan.v1` / `reminder.send.v1` 未结束任务、从 `MODULES` 移除 reminder，并保留 Goose 93 和回执；有合并数据时不得回退到遗漏参与方的程序。

接口见 [OpenAPI](../../api/openapi.yaml)，页面规范见 [提醒页面](../ui/reminder.md)。官方依据：[ESI OpenAPI，兼容日期 2026-08-18](https://esi.evetech.net/meta/openapi.json?compatibility_date=2026-08-18)，`POST /characters/{character_id}/mail`，scope `esi-mail.send_mail.v1`，共享 `char-social` 桶 600/15 分钟。

实现、测试与生产状态以[项目状态](../project-status.md)为准；实际发件人授权与游戏客户端收信见 REMINDER-01。
