## 能力与边界

2026-09-17 本地新增技能点缺口：达标检查的每个角色及每项要求返回 `remaining_sp`（非负整数或 null），角色值为全部要求的缺口之和。按当前方案列出的技能计算，不自动添加额外前置技能。已达标为 0；未达标按 `ceil(250 × SDE skillTimeConstant × 2^(2.5 × (要求等级−1))) − 已观测技能点` 计算，已训练等级是当前点数的最低依据，扣除已训练的部分等级进度。倍率来自同构建 SDE 的 `typeDogma.jsonl`，乘倍率后再向上取整，不能先对 1 倍技能取整再乘倍率。

未分配 SP 不自动抵扣；不按当前时钟推算正在训练的 SP。已确认完成的队列仍按原观测规则合并，缺少结束 SP 时采用已确认等级的最低点数。缺授权、缺数据、等级冲突、缺失倍率或 SP 与目标等级矛盾时该项为 null；任意一项未知则总缺口为 null，已知分项仍可展开查看。历史快照可用，后台同步后直接替换结果。原等级达标状态及权限范围不变，无数据库迁移或新增 ESI 请求。

公式参考 [EVE 开发者文档](https://developers.eveonline.com/docs/guides/useful-formulae/#skillpoints-needed-per-level)；整数取整已核对本地真实 ESI 队列 `level_end_sp`，例如技能 20494 的 IV 级为 90,510 SP、16069 的 II 级为 2,829 SP。目录现在随 `scripts/skill-catalog.py` 同步提取 511 项技能倍率；更新名称库不会自动替换此固定构建目录。

- `/skills` 提供技能总览、训练队列、军团技能要求和逐角色达标检查。本人可切换有效绑定角色；站点管理员从成员页使用 `?member=<本站账号 UUID>` 读取成员数据。
- 军团要求是本站方案：维护名称、技能与最低等级（1–5），支持多个方案、版本冲突保护、删除及数据库审计。最多 100 个方案/军团、200 项技能/方案。
- `corporation.skills` 管理对应军团的要求，并查看该军团已绑定成员的要求检查结果；它不授予其他成员完整技能/队列读取权限。普通成员查看所属军团要求和自己各角色结果。多角色分开检查，不将小号等级相加。
- 不修改游戏训练队列，不分配游戏技能点，不购买或注入技能。本期不包含个人训练方案、训练时间优化和游戏内技能计划写回。

## 官方 ESI

2026-09-15 核对 [Tranquility OpenAPI](https://esi.evetech.net/meta/openapi.json?compatibility_date=2026-09-14)，返回版本 `2026-08-18`；参考 [ESI 说明](https://developers.eveonline.com/docs/services/esi/overview/)。

| 路由 | Scope | 本期使用 |
| --- | --- | --- |
| `GET /characters/{character_id}/skills` | `esi-skills.read_skills.v1` | 技能等级、生效等级、技能点、总 SP 和可选未分配 SP |
| `GET /characters/{character_id}/skillqueue` | `esi-skills.read_skillqueue.v1` | 队列位置、目标等级、可选起止时间与 SP |

两项 scope 已在现有登录授权基线内，未扩充登录 scope。旧授权缺少某项时对应目标显示缺少授权，需用户自行重新授权；本站权限不能替代 CCP 授权。

当前官方元数据两路均为事件驱动缓存、客户端 TTL 60 秒，限流组 `char-detail`（600 tokens / 15m）。实现复用统一客户端及其官方响应头、缓存和令牌桶观测，不另设硬编码的轮询配额。River 约每 30 秒扫描已到期目标；实际更新时间受 Expires、共享限流、失败退避及队列负载影响。页面每 60 秒读取本地快照，刷新按钮仅重新读取本站，不绕过 ESI 缓存。

`skills` 同步由 `skills` 或 `fittings` 任一模块启用；每角色只有一个技能目标。`skillqueue` 仅由 `skills` 启用；`fittings` 的开关不再控制技能管理。继续使用当前授权代次、有效绑定、lease/fence 和事务发布，后台载荷不含凭据。

## 离线训练与准确性

2026-09-16 修复：同一角色、同一 owner hash 且前后连续持有所需 scope 的正常重新授权，在保存凭据的事务中将上一授权代次的技能/队列快照保留至当前代次，原 `observed_at` 和内容不变，对应目标 `valid_until` 清空。页面保留已有数据，不提示“待更新”，新同步成功后直接替换。API 仍返回 `stale`，军团要求也可使用这些历史观测计算结果，不能把保留的数据当作新观测。

仅保留紧邻上一代次且未撤权的快照；跨 owner、曾移除相应 scope、撤权、解绑或更早代次不恢复旧数据，个人配装快照不在此例外内。保留不依赖模块 UI 开关；读取仍核对有效绑定和当前权限。旧后台任务的 generation/fence 不提升，不能发布覆盖新数据。此修复无需独立迁移，已发布生产；同批账号合并功能将生产数据库升级至 Goose 30。

官方说明：离线完成训练后，`skills` 可能要等角色登录游戏才更新，必须参考队列已完成条目。本站保留原始快照，展示时叠加队列已确认完成的等级和可用结束 SP；未分配 SP 缺失显示 `—`，不当作零。

- 只确认结束时间不晚于队列实际观测时间的条目。队列观测早于技能观测时不覆盖更新的技能快照；等级冲突的对应要求显示待确认。不会仅凭浏览器时钟将过期队列的未来条目升级为已完成。
- 已训练与生效等级分开保留：Alpha 限制、专家系统等可造成差异，完成队列不擅自提升生效等级。军团要求按已训练等级检查。
- 技能和队列均有当前允许读取的观测时，`ready`/`stale` 都按最近记录计算已达标或未达标；过期仅触发后台刷新，不清空结果。检查每 60 秒重读本站数据，成功获取新快照后重新计算，保留真实观测时间。
- 缺授权、首次待同步、缺失观测内容/时间或记录冲突时，检查仍显示待确认，不判为零级未达标。历史结果不代表实时游戏状态；普通队列进度是按起止时间的估算，不是额外的即时游戏观测。
- 无起止时间的条目显示已暂停/未排定时间；已过预估结束但尚无新观测的条目等待完成确认。

## 存储、权限与接口

Goose 28 扩展 EVE 私有 `eve_fitting_snapshots` 的资源白名单，加入 `skillqueue`；表名为兼容 Goose 27 保留。`skills` 私有 `skills_plans` 与 `skills_plan_audit` 存本站方案及创建/修改/删除前后值。网络请求不进入方案写入事务。

宿主注入有效绑定、当前站点管理员判定、军团 RBAC、技能快照与 `StaticDataService`。各端点默认 `skills.self`，业务服务再检查目标对象；军团归属和管理权限以当前有效授权资料为准，资料过期时不放行军团数据。审计记录不含游戏令牌。

| 本站 API | 说明 |
| --- | --- |
| `GET /api/v1/skills/context?member=` | 本人或管理员的角色列表、调用者可见军团及管理标记 |
| `GET /api/v1/skills/catalog` | 技能选择目录和 SDE 构建号 |
| `GET /api/v1/skills/characters/{id}` | 本人或当前管理员读取完整技能、队列、独立新鲜度 |
| `GET /api/v1/skills/plans?corporation_id=` | 查看可见军团的要求 |
| `POST /api/v1/skills/plans` | 创建；`request_key` UUID 支持重试去重 |
| `PUT /api/v1/skills/plans/{id}` | 修改；必须匹配 `version`，不可跨军团迁移 |
| `DELETE /api/v1/skills/plans/{id}` | 删除；同样验证军团和版本 |
| `GET /api/v1/skills/plans/{id}/check?member=&after=` | 本人或管理员查看目标账号同军团角色，返回 `items/next_cursor` |
| `GET /api/v1/skills/plans/{id}/check?scope=corporation&after=` | 有对应军团管理权限时批量检查，每页最多 50 个角色 |

`member` 与军团检查范围不能同时指定。所有 ID、版本及游标使用十进制字符串。写操作需要当前会话、Origin 和 `X-CSRF-Token`；400 参数错误、404 不存在/不可访问、409 版本/重试冲突或军团方案上限、503 服务不可用。完整字段见 [OpenAPI](../../api/openapi.yaml)。

## 静态目录与升级

名称优先经 StaticDataService 读取当前本地 SDE 中文/英文。技能选择及服务端类型校验使用官方 SDE `3503375` 中已发布 `categoryID=16` 的 511 个类型和中文技能组；缺失名称以固定官方目录后备，不为页面逐项请求 ESI。该小型目录独立于前端 Dogma 包，也不是全量 SDE 数据集自动导入。

更新目录：下载并核验官方 JSONL 包后运行 `python scripts/skill-catalog.py <official-sde-jsonl.zip> --build <build>`，同步校验目录构建号和本指南，重新构建后端。数据库自动 SDE 名称更新不自动替换这个编译时类别白名单。

本地升级：备份数据库和 `.env`，执行 `npm run db:migrate`（Goose + River），在 `MODULES` 保留原有模块并追加 `skills`，执行 `npm run build` 并重启服务。Goose 28 已先在本地验证，后随 2026-09-15 配装库生产版本上线（生产 Goose 29），7 个角色技能与队列同步完成。降级会删除技能方案、审计与队列快照，不能当作无损回滚。

## 从装配方案生成

军团配置库提供“创建技能方案”，按固定 SDE 合并最低前置技能并预填共用编辑器；可修改等级、增删技能，再通过本模块既有版本/权限/审计接口保存。保存后支持立即编辑及 `/skills?plan=<id>&corporation=<id>` 定位，URL 不代替权限检查。详见[配装指南](fittings.zh-CN.md)。

同步管理和角色页已补齐 skillqueue 响应校验与手动刷新，避免训练队列导致整个同步列表读取失败；见[同步指南](esi-sync.zh-CN.md)。
