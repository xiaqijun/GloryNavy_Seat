## 当前出勤关联要求（2026-09-16）

军团补损（`srp`）新增出勤关联门槛：同一军团活动中，必须存在同账号、同角色、同击毁报告的已确认损失，且该角色记为出勤。候选或已拒绝的损失、缺席记录、其他账号历史及手填活动编号均不满足。无需活动结束或已发 PAP。PVP补损（`solo`）不要求出勤；联盟补损继续暂停新申请。

列表批量读取考勤关联，未关联仅显示“可申请PVP补损”，详情不额外显示未关联出勤的说明文案。服务端在提交和批准事务内锁定并复核关联，管理员手动录入同样受限。申请的活动 ID 由服务端写入，批准时须仍为原关联；关联被撤销/改为缺席会返回 HTTP 409 `welfare_attendance_required`。历史缺少有效关联的待审军团补损不能直接批准，需撤销后按已确认损失重新提交；已批准历史金额不重算。不增加自动补偿、自动确认损失或规则配置门槛。

当前申请仅提供军团补损和 PVP补损。联盟补损暂停新建，后端拒绝 `action=apply, kind=alliance`；历史联盟单据仍参与进度展示和同 KM 防重。客户端也过滤旧缓存中的联盟选项。

历史类型键保留 `srp`、`alliance`、`solo`；当前新申请范围及门槛以上文为准。

## 官方数据与生命周期

已核对 [CCP OpenAPI（兼容日期 2026-08-18）](https://esi.evetech.net/meta/openapi.json?compatibility_date=2026-08-18)。个人接口 `GET /characters/{character_id}/killmails/recent/` 返回近 90 天的击杀和损失引用，需要已在登录清单中的 `esi-killmails.read_killmails.v1`；ID/hash 再调用 `GET /killmails/{killmail_id}/{killmail_hash}/` 获取明细。静态缓存标注分别为 300 秒、2,592,000 秒，实际运行遵守响应缓存、ETag/304 和共享限流。手动同步仅请求排队，不绕过缓存。

启用福利后创建 `killmails` 角色目标，River kind 为 `eve.character-killmails.v1`，复用 `eve_characters` 队列。引用按页持久化，每次发布处理一个新明细，中断从剩余引用继续；旧引用按角色/游戏所有者/hash 去重。页数变化或后续页 404 时重启遍历，完成整轮后按缓存到期调度。失败明细不标为已处理，沿用现有退避、租约/fence 与授权代次。

仅受害角色等于授权角色的报告展示为损失；参与击杀只保存内部去重标记。保存 KM、舰型、损失时军团、时间、星系及物品掉落/损毁数量和槽位路径，不返回发现 hash，不伪造 ESI 未提供的估价。名称批量经 StaticDataService 解析，优先 SDE 中文、英文及已有名称缓存/ID。

页面只读本地数据，已保存损失增量保留，刷新或空列表不清历史。同游戏所有者重授权保留记录；缺 scope、令牌失效或游戏所有者变化后不开放旧证据。解绑删除凭据时原始记录级联删除，已经提交到福利的独立证据快照仍保留。账号合并移动绑定，不复制报告或刷新补损资格。

## 读取与补损

当前采用人工审核。有效绑定角色可提交 PVP补损，军团补损另需有效出勤关联，不要求预先配置规则、生效日期、身份核验、配装或技能方案。损失时不属于当前军团的历史记录仍可提交 PVP补损，由审核人判定；当前账号归属、有效绑定及军团访问范围仍检查。缺少授权时不能读取 ESI 证据，不能伪造同步记录。

舰船损失页移除补损资格和规则入口。状态显示可申请、待审核/交付等实际进度，仅完成交付显示已补损；已处理或处理中隐藏重复申请。列表和详情的 reimbursement 由福利私有表在原始损失鉴权后批量关联，普通成员仅看本人账号，管理员限已授权角色范围。未来时间的报告显示损失时间异常，不再检查旧政策日期。提交后刷新本地缓存。

GET /api/v1/welfare/losses 要求 corporation_id、character_id；每页 30 条，before 翻页，killmail_id 读取详情。列表不包含物品，详情才返回。服务器从本地报告重建证据，发布前重查角色、凭据、所有者及 scope。synced_loss=true 缺证据时拒绝，不能静默降级手填。管理员手动录入仍限本人绑定角色，不开放代录。

审核人直接填写核准补损金额（0.01–1,000,000,000,000 ISK），不再自动计算比例、纪律折扣、PVP 上限或日限，也不强制联盟已确认不补。损失原因、联盟结论、配装及金额合理性均人工核对。保留同 KM 唯一主补偿、本人不得审核/交付自己申请、交付凭证与审计。成长、旗舰的规则与身份/历史资格保持不变。

历史补损规则不删除，但新申请不读取。未批准单据按当前人工方式核价，已批准金额和历史流水不自动重算。手填历史证明不因有 KM ID 就视为已验证；无自动付款、KB 估价或官方发现窗口之外的回补；仅按已确认考勤损失精确关联，不自动确认候选。
