## 使用流程

1. 登录要保留的本站账号，在“我的角色”点击“合并账号”。
2. 通过 EVE SSO 验证另一个已经绑定本站的账号中的有效角色。普通登录和“添加角色”仍拒绝抢绑，不会自动启动合并。
3. 查看迁入账号、保留主角色、全部迁入角色、PAP、果壳币净余额及订单数，确认后执行。验证只生成预览，不迁移身份；验证有效期 10 分钟，绑定原目标会话。
4. 双方其他会话退出，当前目标会话保留。迁入角色今后登录同一个目标账号。取消、过期和角色身份异常不执行合并；资料变化时刷新预览，角色集合/主角色/归属变化需重新验证。

## 数据规则

- 迁入源账号全部角色，而非仅 SSO 选择的那个角色；两账号合计最多 100 个角色。每个角色必须身份有效，来源角色 owner hash 与本轮 SSO 相符。未知角色不能借此创建或抢占账号。
- 目标主角色、QQ/KOOK、社区确认和本站 RBAC 保持原样。来源资料、手工权限、管理员标记及原审计保留在停用的来源账号，不相加、不复制。来源账号的官方 QQ openid 绑定和未使用绑定码会被移除，不会复制到目标账号；目标账号需要重新生成绑定码。账号合并不等于转移游戏角色所有权；不处理 owner hash 异常。
- PAP 出勤归属、PAP 积分与流水、币权益/流水/订单、个人配装草稿及保存游戏的幂等记录迁入目标账号。原账号标识保存到 `original_account_id`，多次合并始终保留首次归属。流水 ID、金额、时间、原操作者、兑换比例和订单状态不重写，不创建补发流水。
- 果壳币按净余额合计，包括待发放占用、已消费和欠额；不会清零欠额或释放库存。原订单可以按既有规则取消退款，PAP 更正仍按原比例冲正；历史未兑 PAP 不因合并自动兑币。
- 活动舰船/损失依附出勤记录，随合并后的出勤读取；活动和配置方案的创建者及操作审计保留原标识，军团对象权限仍独立核对。完整账号合并表示同一成员，因此保留角色在线样本；与单独换绑角色清除原在线样本的规则不同。
- 角色 ESI 凭据和快照保留；用于验证的来源角色会按正常授权流程更新凭据。既有后台任务继续核对绑定、授权代次和 fence。合并不发起游戏资产转移或奖励交付。
- 存在 `sending` 游戏配置写入时暂不合并，等待结果后重新预览；账户级幂等键冲突会整体回滚，不删除冲突记录。不存在自动拆分或自助撤销。

## 事务、权限与扩展

`identity` 管理已验证请求、绑定原会话、角色列表指纹、预览指纹、有效期与完成记录。宿主注入各模块的 `MergeAccountTx`，模块 SQL 留在私有 store，即使业务 UI 停用也必须迁移其已有账目。新增账号级数据时须扩展迁移参与者和测试。

角色 advisory 锁按 ID 排序，随后锁两账号及原会话；重读角色和预览。参与模块在同一 PostgreSQL 事务中更新当前归属、保留原始归属，最后迁移角色、撤销会话/授权 flow、记录合并映射及审计。失败全部回滚；成功后的同会话同指纹确认可重放，不重复入账。预览自身只存确认元数据。

模块自有表使用 identity 的数据库活跃账号检查契约；写入时锁账号并拒绝向已合并源账号写新数据，防止旧请求在合并之后产生孤立账目。外部 ESI 请求不进入合并事务；相关模块的操作审计也阻止旧会话的在途写入。遇到并发锁冲突可重新预览后重试。

接口：`POST /api/v1/eve/accounts/merge` 发起 SSO；`GET /api/v1/identity/merges/{id}` 预览；`POST` 同路径携带原预览 `token` 确认；`DELETE` 同路径取消。全部需要当前会话，写请求需要同源 Origin 和 CSRF；proof UUID 不构成访问授权，其他会话不能预览或确认。详细格式见 [OpenAPI](../../api/openapi.yaml)。不新增可委托的管理员代合并权限。
