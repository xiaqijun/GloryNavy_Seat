# Item appraisal

> Status index (2026-09-23): this business capability is deployed; remaining extensions and live verification gaps are tracked in the [backlog](../backlog.md). See [current project status](../project-status.md) for versions. Dated/Goose introduction notes describe their historical stage, not today’s release state. Apply current repository migrations, not only the initial module version.

2026-09-20 local addition: **Appraise a contract** selects an accessible personal or corporation source, searches/paginates outstanding, unexpired item-exchange/auction contracts, and prices either offered or requested items separately. Courier, accepted and expired contracts are excluded. This reads synchronized local contracts, not a public universe-wide search, and never accepts or delivers a contract.

`POST /api/v1/market/estimate-contract` accepts `{owner_kind, owner_id, contract_id, side}` with decimal-string IDs and `included|requested`. The host injects EVE `ReadContract`, retaining current binding/administrator or corporation-contract object checks and in-scope filtering. The server requires complete items and sends actual type IDs/quantities to `EstimateItems`, never browser-provided items or amounts. Maximum 2001 rows, 1–1 billion per row. Incomplete items, empty side, blueprint copies or excessive input return 409 without truncation. Access, eligibility and content fingerprints are checked again after pricing: revoked access returns 404, changed terms return 409. Missing market quotes retain complete=false and known subtotals.

Results identify the contract and side; pasted input survives and failures can be retried. Jita 4-4 prices and the existing global ratio apply. Contract price is not treated as market value or approved reimbursement. No migration, scope or new synchronization job; subsequently deployed; current verification boundaries are in project status.

2026-09-19 bilingual data update: business requests send `Accept-Language: zh-CN|en`; the server selects presentation language in request context and returns `Content-Language` and `Vary: Accept-Language`, retaining private-response `no-store`. Local SDE type/system names prefer the requested language, with the other language, existing type-name cache or ID as fallback. Generated contract summaries and registered server messages follow the locale. Player names/notes/descriptions, business IDs, permissions, prices, content tokens and ESI caches remain unchanged. No new migration, scope or SDE import; local only. See [interface language](../ui/language.en.md).

PVP reimbursement now reuses `EstimateItems` with trusted type IDs and loss quantities, the same pricing engine and configured ratio/version. Welfare persists its own review snapshot; market does not read welfare-private data. Standalone pasted estimates remain ephemeral. See [welfare](welfare.en.md).

Local first release, Goose 36; not deployed to production. Enable `market` alongside existing MODULES; dependencies are identity/eve/access. Run `npm run db:migrate` for Goose and River.

Paste name + Tab + quantity (later columns ignored), `name × quantity`, `name x quantity`, or a name with implicit quantity 1. Limit: 100 non-empty lines, 32 KiB, integer quantities 1–1 billion with optional grouped commas. Resolve exact Chinese/English names against active SDE; ambiguous/unrecognized names are not guessed. Duplicate types reuse one lookup while preserving input rows.

Use orders physically located at Jita 4-4 (region 10000002, station 60003760): highest positive buy, lowest positive sell, and their midpoint. This is a top-of-book reference, not a depth/minimum-volume execution estimate. Excludes other locations, ranged regional orders elsewhere, taxes and shipping. A missing side produces no midpoint. Full per-type pagination is required; changed page counts or failed pages publish no partial quote.

One global ratio, shared by all three prices: default 100%, range 0–1000%, step 0.01%. Current site administrators may save versioned settings; conflicting edits return 409. Settings and actor audit commit together. This does not modify PAP/coin exchange rates. Decimal-string ISK uses rational arithmetic and rounds final amounts to cents. Results carry their ratio and source content timestamp. Missing quotes remain null, never fabricated zero; partial output is labeled a known subtotal. The 25-second request budget may require a retry; completed requests reuse shared ESI cache.

Host injection supplies EVE exact SDE resolution and `ESIService.JitaPrices`; market never imports EVE's private store. Public `/markets/{region_id}/orders/` uses the shared gateway/cache/rate budget, at most 20 pages/type. No character token, new scope or polling loop. Respect response expiry; the endpoint normally caches five minutes. [CCP market orders guidance](https://developers.eveonline.com/blog/market-orders-rate-limit-rolls-out-on-february-24-2026).

`market.self` is authenticated access to public appraisal only; POST requires CSRF. Administrator configuration is checked separately and is not role-delegable. GET `/api/v1/market/settings` returns settings and administrator status; POST to the same path accepts `{ratio_bps,version}` (10000 = 100%); POST `/api/v1/market/estimate` accepts `{text}` and returns lines, totals, adjusted totals, ratio_bps and complete. Line statuses: ready, invalid_quantity, unknown_type, unavailable, missing_orders; money is a decimal string or null. Invalid requests: 400; unauthenticated: 401; denied: 403; version conflict: 409; storage unavailable: 503. Partial appraisal returns 200 with complete=false.

Only global settings/audit are persisted in market; pasted lists and standalone estimates are not stored. No account-owned balance/data merge participant is needed; audit actor identity remains historical. Disabling the module preserves settings. Appraisal does not approve or pay welfare awards; PVP now stores its own review snapshot through the injected pricing service, as described in the welfare guide.
