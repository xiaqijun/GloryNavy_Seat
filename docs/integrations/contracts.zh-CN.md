## 1. 数据范围

同时接入角色合同与军团合同列表、非快递合同物品、拍卖出价。个人 scope 为 `esi-contracts.read_character_contracts.v1`，军团 scope 为 `esi-contracts.read_corporation_contracts.v1`；两者均已在现有 57 项登录清单中，无须新增应用 scope，但缺少实际同意的角色仍须更新 EVE 授权。

官方 OpenAPI 将接口描述为本人／军团作为发布人、接受人或受让人的合同，时间范围为最近 30 天及 `in_progress` 合同；但不能据此断言军团响应只包含军团自身业务。[CCP 当前 OpenAPI](https://esi.evetech.net/meta/openapi.json)

2026-09-14 生产核对：修复前军团列表 14,260 份中，14,038 份的 assignee_id 指向当时所属联盟；同一军团接口第一页的加密响应缓存包含 1,000 份，其中 996 份指定给联盟，确认来自军团 ESI 响应而非个人列表误合并。这是该次真实观测，不代表所有军团或所有时期都能读取完整联盟合同。此批联盟指定合同的 availability 为 personal，不能单靠 availability='alliance' 识别。同步来源与业务归属自 Goose 17 起分开处理。

### 军团自身业务过滤

用户已明确排除与军团无关的联盟合同。军团合同只有满足任意一项才进入业务范围：`for_corporation=true` 且 `issuer_corporation_id=当前军团`；或 `assignee_id=当前军团`；或 `acceptor_id=当前军团`。因此，军团以自身名义发布给联盟的合同仍保留；成员个人发布、个人接受或仅向联盟开放且军团未参与的合同排除。`availability` 不作为归属判定依据，个人合同范围不受此过滤影响。

Goose 17 增加由原始参与方字段计算的 in_scope 存储生成列和部分索引。列表在 SQL 分页前过滤；详情、物品和出价入口统一拒绝范围外对象（404），站点管理员也不绕过该业务范围；CSV 复用列表，自动遵守相同筛选。已有军团对象权限检查保持不变。

ESI 列表仍完整分页核对，保留返回的基础元数据，避免跳页并支持某份联盟合同后来由军团接受后进入范围；未对其宣称“完成物品同步”。范围外合同不再创建物品／出价任务，已有明细置为 out_of_scope 并提升 fence，旧任务在令牌读取及网络请求前退出；业务状态统计不计入这些明细。原始合同及已抓取物品没有物理删除。重新进入业务范围时恢复应有明细调度，固定且已成功的物品继续复用。

军团合同不是全体成员个人合同的合集。个人与军团范围可以重叠，例如个人向军团指定的合同；成员之间的纯个人合同不会仅因军团成员身份进入军团列表。管理员查看成员个人合同仍走个人范围，不能用军团列表替代。

本地按 `owner_kind + owner_id + contract_id` 隔离个人与军团记录。上游未返回某份旧合同，不删除历史、不推测为取消或完成；只按实际返回的状态更新。合同原始字段保存为 JSONB，金额不经过 Go float64；拍卖金额使用 PostgreSQL numeric。物品保留数量、包含/要求方向、单件标记及 raw_quantity（包括蓝图原件/复制品标记）。合同 ID、角色与地点 ID 使用整数存储。

### 合同类型

2026-09-14 直接核对 [CCP 当前 OpenAPI](https://esi.evetech.net/meta/openapi.json)：个人和军团列表的 `type` 枚举均为 `unknown`、`item_exchange`、`auction`、`courier`、`loan`，本站不得新增或推断游戏类型。当前游戏提供物品交换、拍卖与快递运输，参见[官方市场与合同帮助](https://support.eveonline.com/hc/en-us/sections/201141732-Market-Contracts)。[Retribution 官方补丁说明](https://www.eveonline.com/news/view/patch-notes-for-retribution-1)明确借贷合同已从游戏移除；ESI 保留 loan 不代表当前可创建。前端将 loan（借贷历史）和 unknown（未知类型）归入“兼容数据”，后端继续保留官方枚举及原始数据。`trade_direction` 是本站展示推导值，出售／求购／交换／运输不作为新合同类型；CSV 的类型列与交易方向列分离。

### 合同状态

2026-09-14 直接核对同一官方 OpenAPI，个人与军团合同 `status` 均为以下十项；中文是本站展示翻译，不是 CCP 提供的中文枚举。

| ESI 原值 | 中文显示 |
| --- | --- |
| outstanding | 未完成 |
| in_progress | 进行中 |
| finished_issuer | 发起方已完成 |
| finished_contractor | 接受方已完成 |
| finished | 已完成 |
| cancelled | 已取消 |
| rejected | 已拒绝 |
| failed | 已失败 |
| deleted | 已删除 |
| reversed | 已逆转 |

同步、查询与筛选使用原值；列表、详情和 CSV 共用一份翻译。`outstanding` 不一概称为待接受，以免套用到拍卖等场景；`reversed` 不解释为发起方主动撤回，官方 schema 未描述具体触发条件。单方完成保留各自状态与进行中的视觉提示，只有精确 `finished` 使用整体完成样式，未知原值也不能因 finished 前缀显示完成。不会根据本地时钟或到期时间新增 `expired`，也不将明细 pending／ready 同步状态混入合同状态。页面状态悬停可查看 ESI 原值，未识别的响应值原样显示。

## 2. 任务与分页

每个角色新增 `character_contracts`、`corporation_contracts` 两个列表目标，首次到期为迁移或首次授权时刻，不继承旧职务同步的等待时间。仍由 30 秒扫描器派发。独立 `eve_contracts` 队列并发 1，列表优先级 1、明细优先级 3（数字越小越先执行），原角色队列并发 2 保留；总请求仍经过同一数据库限流器。

列表每个 worker 执行一页，页码、总页数、最早缓存到期时间与授权代次持久化。每页合同及后续明细任务同事务提交，只有列表全部分页完成才记录该资源成功。分页数量变化时从第一页重新核对，未完整读取不宣称完成。上限为 10,000 页，每页最多 1,000 份合同；单响应仍受 1 MiB 限制，超过限制明确报错。

物品与出价使用独立 River 任务和独立状态、租约/fence。物品成功后视为合同固定内容保存；快递合同不抓取包裹内物品，已删除合同不新建明细任务。军团出价接口单独分页，按 bid_id 幂等保存；重复执行不会复制出价或物品。发生撤权或重授权时，旧代次不能再发布列表或明细。

重新授权或更换军团来源时，已成功抓取的固定物品继续保持 ready；来源和授权代次更新，已有物品及其成功时间保留。尚未成功的明细重新进入正常调度，出价不按固定物品处理。Goose 16 修复旧版遗留的“已有物品但 pending／failed”状态，只处理有成功记录且无有效租约的物品；不解除 blocked，不伪造成功时间，重复执行安全。

任务历史里的“继续同步后续分页”是一次列表抓取的页级进度，最后一条“成功”表示列表整轮完成，不代表所有物品／出价均已完成。限流等待由独立明细任务继续重试；大军团初次明细积压可能跨多个窗口。网页刷新只重读当前本地结果，反复重新授权会推进授权代次并产生替代任务，不是加速同步的手段。

缓存保存 `X-Pages`，缓存命中和无分页头的 304 都沿用原页数。到期时间读取 Expires，并支持 Cache-Control max-age/Age；典型官方缓存为列表 300 秒、物品 3600 秒、个人出价 300 秒、军团出价 3600 秒，以实际响应为准。大量明细还受共享保守限流预算影响，初次全量可能跨多个限流窗口，不能承诺几分钟内全部完成。[CCP 当前 OpenAPI](https://esi.evetech.net/meta/openapi.json)

## 3. 军团来源与权限边界

同一军团选择具有有效归属快照、所需 scope、可用凭据且未阻断的最小角色 ID 作为同步来源。其他角色显示“共享同步”，不会重复抓取同一军团列表。选中来源被 ESI 拒绝或解绑后，后续调度可使用其他合格来源；不要求操作者手动复制令牌。

每次发布军团数据前重新检查来源归属和选择结果。已检测换团、职务快照过期、重授权代次变化时不发布旧请求；事实仍受 ESI 缓存延迟限制。本站管理员身份不能替代 EVE scope 或游戏侧访问许可。403 仅阻断失败的数据项，保留凭据及无关职务事实；明确凭据失效则撤销全部私有同步资格。

角色解绑或检测到 owner 变化时删除该角色的个人合同历史；军团历史仍按军团保存，不转移给原角色的其他军团。军团合同查询重新实施军团范围权限，不能因数据来源角色曾经属于某军团就开放历史。

## 4. 合同查看与接口

新增工作台入口 `/contracts`，支持个人／军团切换、绑定角色或军团选择、标题及 ID 搜索、类型和状态筛选、分页列表、合同详情、物品与拍卖出价。URL 保留选择与分页，详情返回不丢失筛选。页面记录见 [合同 UI](../ui/contracts.md)。

路由准入能力为 `eve.contracts.read`，只表示允许进入查询流程。每次列表、详情、物品及出价请求都重新检查对象权限：个人允许当前账号有效绑定角色或本站管理员读取其他成员的有效绑定角色；军团按 `corporation.contract` 策略检查服务器解析且未过期的军团资料。沿用 SeAT 的本军团 CEO／Director／Contract_Manager 映射和本站手工军团／联盟过滤授权；同步来源不要求这些职务。权限目录本次只新增已交付的“军团合同”。`eve.sync.manage` 不授予合同内容访问权。

- `GET /api/v1/eve/contracts/owners`：默认返回本人角色与可查看军团；管理员可带 `?member=本站账号UUID` 选择该成员的有效角色，非管理员或不存在的成员返回 404。管理员从 `/members` 选择角色进入合同；列表／详情／物品／出价均逐次检查当前管理员身份和目标有效绑定。
- `GET /api/v1/eve/contracts/{kind}/{id}`：每页 25 份，按合同 ID 降序；`q` 为标题字面子串或精确合同 ID，`type/status` 筛选，`before` 为排他游标。
- `GET /api/v1/eve/contracts/{kind}/{id}/{contract}`：详情及物品／出价同步状态。
- 同路径下 `/items?after=`、`/bids?before=`：每页最多 100 条，物品按 record ID 升序、出价按 bid ID 降序。

所有响应均禁止 HTTP 缓存；ID、金额及物品数量以字符串返回，未提供的金额为 null。未知／越权对象统一返回 404，参数错误 400、未登录 401、资料未补全 403、服务不可用 503。DTO 不返回 token、原始 JSON 或同步凭据。数据访问仍受 ESI 缓存导致的事实延迟限制；没有新鲜军团资料时不开放军团历史数据。

合同通过注入的 `StaticDataService.TypeNames` 统一读取名称；物品优先使用本地 SDE 中文名，中文缺失取 SDE 英文；类型缺失时使用已有 ESI 名称缓存，再回退 ID。名称语言由 `name_language` 标识，物品列表不会逐项请求 ESI，见[SDE 导入](sde-names.zh-CN.md)。其他公开实体按最多 100 个 ID 批量调用 `/universe/names/`，共享缓存／限流、一天名称缓存及 3 秒补充预算；失败不阻断合同读取。玩家建筑解析见下节，物品图标来自 EVE Image Server。查看和刷新不触发合同重同步。

列表和详情增加 `summary` 与 `trade_direction`，不修改原始 ESI `title` 或同步载荷。只有空白描述生成摘要：按完整物品明细（items 状态为 ready）合并同方向同 type_id 的数量，单种显示“名称 × 数量”，多种显示“首种名称等 N 种物品”，双向显示“提供 … · 换取 …”；快递使用起点 → 终点。名称批量读取本地 SDE／已有名称缓存，缺失回退 #ID，数量保持十进制字符串精度。明细不完整不生成物品摘要，前端回退合同类型并单独显示合同 ID；搜索仍仅匹配原始描述或合同 ID。

`trade_direction` 以发起方为视角：物品交换／拍卖仅提供物品为 `sell`（出售）、仅要求物品为 `buy`（求购）、同时提供和要求为 `exchange`（交换），快递为 `transport`（运输）。缺失或未完成明细、空物品及不支持的类型为 `unknown`（待确认）。接收人列复用现有 acceptor／assignee：实际接受者优先，其次指定对象，公开且均为空时显示公开；详情仍分别保留两者。方向不依赖描述、价格或名称解析成功，不代表当前查看角色的收支。按已授权的 owner_kind + owner_id + contract_id 批量读取，无新增权限、迁移或同步请求。

原 `/account` 和 `/sync` 仍仅返回同步元数据，列表成功与明细完成分开显示。人工同步刷新仍只安排列表；出价和物品由同步流程派发，详见前文。当前不提供创建／接受合同或报表；合同列表 CSV 导出已实现。

加载性能：URL 指定 owner 的页面在登录确认后可并行请求 owners 与列表／详情，两条 API 各自执行原有对象权限校验，前端只有范围确认后才呈现数据。默认 owner 仍由 owners 返回值确定。详情支持用户指针进入或聚焦入口时预取；预取与正常读取共享用户、范围、对象和筛选查询键及既有 30 秒新鲜期，未增加 API、权限或缓存寿命。此次优化未修改同步、SQL 和 ESI 名称补全的缓存与超时。

### 列表导出

前端沿用已有受保护的列表 API，按当前 owner 与 q/type/status 从第一页顺序读取全部匹配合同，再在浏览器生成 CSV。管理员通过成员入口选择的角色沿用相同对象检查；每一页均由服务端重新授权，没有新增“导出全部成员”能力、权限配置项、HTTP 端点、数据库迁移或私有同步任务。名称与摘要复用列表响应及 SDE 优先规则。

最多 10,000 条；超过、游标异常或任意一页失败时终止，禁止交付部分文件。支持取消；切换账号、对象、筛选和离开列表会中止请求及下载。分页读取期间同步数据可能变化，这不是数据库事务快照。

CSV 为 UTF-8 BOM、当前界面语言的表头（默认中文）、CRLF 行结束；逗号、双引号和换行按 CSV 转义，公式类字段加文本前缀。类型/状态显示名随语言切换，原始描述、名称和服务端摘要保持原文。ID 和金额直接写原始字符串，不经过 JavaScript Number，时间保留接口 ISO 8601 格式。用 Excel 导入时将 ID／金额列设为文本，可避免 Excel 自动识别带来的精度损失。导出包含合同列表字段、独立原始描述、摘要标题和接收人；不包含物品／出价行、令牌或原始 ESI JSON。

## 地点名称（2026-09-17）

合同地点名称现在区分 NPC 空间站与玩家建筑。空间站与参与方分开批量解析；批量失败时对未解析 NPC 空间站使用 `/universe/stations/{station_id}/` 回退。玩家建筑使用 `/universe/structures/{structure_id}/`，需要既有 `esi-universe.read_structures.v1` scope 及游戏建筑 ACL。个人合同使用该角色，军团合同只使用当前选定的军团合同同步来源，不遍历其他成员令牌。请求前后核对有效绑定、游戏所有者、授权代次与军团来源；成功响应复用共享 ESI 加密缓存，按角色／代次隔离，绝不写入公开名称表。名称补充共用 3 秒主预算，每类地点最多 3 个并发，短限流等待遵守服务返回时间；403/404 在本进程按角色／代次／地点退避 1 分钟（最多 512 项），不是权限或成功名称缓存。无权访问、无来源或请求失败时保留原始 ID，不推测建筑已被摧毁。列表、详情、快递摘要和 CSV 共用解析结果；不改合同同步节奏、无新增迁移。

接口已核对 [CCP OpenAPI](https://esi.evetech.net/meta/openapi.json).
