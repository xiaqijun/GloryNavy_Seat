# 通用 UI 设计规范

基准确认日期：2026-09-13；规范职责整理：2026-09-14；卡片与列表布局补充：2026-09-20。

用户已同意以 Corporate Clean 强制提示词为视觉基准，并由本机 UI Skill 补充工程与交互要求。本文记录项目采用的规则及适配，不是原提示词逐字副本。

来源：[StyleKit Corporate Clean 强制提示词区域](https://www.stylekit.top/zh/styles/corporate-clean#style-prompts)。仅采用该区域的 Hard Prompt，不合并同页后续 Design Spec、示例 CSS 等内容中的矛盾要求。网页后续变化不自动变更本项目规范。

## 视觉基准

- 专业、清晰、一致的企业管理界面；默认简体中文，支持英文切换，采用浅色主题。
- 保留品牌识别与适量装饰。精简的是重复文字和无效信息，不要求页面只剩白卡片与按钮；装饰仍服从统一主题与操作层级。
- 主色为 blue-600/700，页面使用 slate-50 或 gray-50，白色卡片配灰色细边框及轻阴影。
- 主要组件采用 rounded-lg 或 rounded-xl；保持舒适间距，不采用无圆角的视觉方案、渐变按钮或花哨正文字体。
- 卡片内边距以 p-6 为基准，布局间距以 gap-4/gap-6 为基准；表格行使用轻微灰色悬停背景。
- 成功、警告、错误分别使用绿、琥珀、红色；文字按标题、正文、辅助信息建立灰阶层级。
- 控件动效使用 150ms ease-out，卡片使用 200ms ease-out；不超过 200ms，不引入弹簧动画。
- 按钮悬停轻微上浮并增强阴影，按下缩放至 0.98、取消上浮并恢复轻阴影。
- 卡片保留轻微悬停上浮与阴影，图标容器采用品牌色悬停及轻微放大，图标转白。
- 键盘焦点采用清晰的 2px 蓝色环及 2px 偏移；交互文字采用中等或半粗字重。

## 明确适配项

2026-09-23：公开军团首页采用用户单独批准的方案 1，深空首尾、真实舰船素材和 GSAP 展示动效仅适用于 `/`，详细参数见 [首页](ui/homepage.md)。后台、登录页继续各自既有规范；该例外不重定义全站主题或动效时长。

### 语义颜色变量

组件使用 shadcn/ui 的语义变量，例如 bg-primary、text-primary-foreground、bg-background、bg-card，而不是到处硬编码 blue/gray 类名。主题变量映射到上述视觉基准的具体颜色，并明确悬停色。

这是对原提示词字面类名要求的适配。验收检查实际颜色与状态，不要求组件保留原始类名。不要直接沿用与 Corporate Clean 不一致的 shadcn 默认主题。

### 减少动态效果

当 prefers-reduced-motion: reduce 生效时，关闭悬停和按压的位移、缩放及图标放大，保留颜色、边框和焦点反馈，必要时使用即时状态变化。此项是对强制动效要求的明确例外。

### 静态卡片与性能

普通模式保留卡片悬停效果。静态卡片不得仅为配合动效而添加 pointer 光标、tabIndex、按钮角色或点击行为；实际可点击的元素应有语义、键盘操作和明确标识。

允许基准要求的小范围阴影和颜色过渡，作为 Skill 中“只动画 transform/opacity”建议的局部适配。只过渡实际需要的属性，避免 transition-all，不动画宽高或布局定位属性。transform 上浮本身不导致文档流重新排版。

### 范围与补充

- 当前只确认浅色主题；Skill 对深色模式的通用建议不自动扩展本期范围。
- Skill 可补充响应式、键盘操作、语义标签、对比度、加载/空/错误/禁用状态与表单验证；不得因此重新选风格。
- 表格和小屏布局允许按内容适配间距；原提示词的大区块留白不机械套用到每个后台表格单元格。
- 焦点类名不等于自动满足可访问性要求；实现后检查实际背景上的可见性、对比度及是否被遮挡。

## 内容密度与排版约束

- 规则配置入口归属对应业务页面，弹窗只列该页面负责的项目；不从无关页面跳入其他业务规则。保存后刷新受影响的状态与可执行操作。入口按权限显示，权限检查仍由服务端执行。

本节描述跨页面适用的原则。页面展示哪些业务字段、采用几列、某卡片宽多少，属于页面需求与实现记录，不属于通用规范。

2026-09-13 根据用户对首版文字过多的反馈补充。以下是本项目新增的实施约束，不是外部 Hard Prompt 的逐字要求。

- 页面默认只放一个当前语言的主标题和当前操作；不添加装饰性英文眉题、口号或复述标题的副标题。确需解释操作时，补充一句短说明。
- 页面优先展示实际数据、状态与可执行操作。开发阶段、技术实现说明、交付清单、未来计划留在项目文档，不能作为工作台填充内容。
- 状态卡默认只有“名称＋结果”，不为每个结果再附一段同义说明。异常原因与处理提示在异常时展示，必要诊断信息保留可访问入口。
- 同一环境标识在公共布局中只显示一次。扁平导航不增加重复面包屑；正文保留主标题以支持页面识别和辅助技术。
- 空状态使用一个标题、最多一句必要说明及一个已可用的操作；不罗列尚未开放的功能，不放无法操作的按钮。
- 标题、正文/数据、辅助信息三个视觉层级为常用上限。桌面主标题 28px、移动端 24px，区块标题 18px，正文 14–16px，辅助信息不小于 12px。
- 桌面页面内边距 32–40px、区块间距 24px、卡片内边距 24px。移动端页面内边距 20–24px，状态卡可适配为 16–20px 内边距的紧凑横行，不将桌面大卡片逐张等比例堆叠。
- 文本精简优先通过删除重复内容和调整层级完成，不缩小字体、强制截断关键状态或隐藏错误来减少占用。支持换行和窄屏，数据含义不能为缩短文案而改变。
- 错误消息、连续英文名称和长编号也必须在内容容器内换行；错误旁的重试操作不能被挤出视口，长说明与操作按顶部对齐，不靠裁切错误适配小屏。
- 无数据时允许合理留白，不添加占位说明卡片来填满屏幕。验收至少检查桌面与 375px 手机上的信息顺序、操作可见性和横向溢出。

## 分组、对齐与信息密度

- 按业务对象与操作关联分组：属于同一对象的身份、属性和状态可共用容器，用留白或细分隔线建立次级层级；只有独立任务或独立交互区域才增加外层卡片。
- 导航入口较多时按业务划分两级折叠组，默认展开当前页面所在组；组先按权限和启用模块过滤，空组不显示。手机提供显式菜单开关，展开和选中状态均可被键盘与辅助技术识别。具体分组和排序记录在页面文档。
- 同组同类选择项保持一致的尺寸、头像位置、内容起点与操作对齐。高度应容纳最长内容并协调同行/同组项，不能为了等高裁掉名称、状态或错误。不同用途的详情区不强制等高。
- 容器宽度服从信息长度与阅读路径。名称、数量、状态等相关信息保持邻近；同组数据按列对齐，操作有稳定位置。通过合理分列利用可用空间，不把短内容无限拉长。
- 留白用于分组，不用于撑满屏幕。外壳与内容只由一层负责外部内边距；组内间距应小于组间间距，避免重复边框、重复标题和卡片套卡片。
- 中等信息密度：主要数据、关键状态和常用操作可直接发现；低频长信息可渐进展开，并保留明确入口。不能用堆砌说明补足空白，也不能仅靠缩小字体压缩页面。
- 一个任务区域有清晰的主要操作，其余操作在视觉上从属；操作靠近其作用对象。相同操作在不同状态下保持名称、位置与反馈一致。
- 已选中、待处理、失败等含义必须有文字、图标或形状提示配合颜色，不能仅靠颜色区分。

### 卡片与列表布局

- 先判断内容形态，再决定宽度与列数。独立奖励、人物摘要等短对象卡片可限制单卡宽度；连续记录列表的外层容器与页头、工具栏使用一致的内容区边界。表单和长文详情可以按阅读需要限宽，不把同一个宽度上限套到所有区域。
- 多条相互独立、字段较少的记录，在宽屏优先评估两列或多列网格，利用右侧空间；需要横向比较字段的表格、时间轴和长详情保留适合其阅读方式的布局。不能把“桌面两列”作为所有页面的统一要求。
- 处理留白时，先检查列数、信息分组、重复标题、重复图标和内外间距。不要只收窄整个主列表，导致右侧出现大片无用途空白；也不要仅为填满页面把单个短对象卡片拉宽。
- 卡片高度由内容决定，组内间距小于组间间距。删除重复的内容标题与上下层图标，数量靠近对象名称；地点、时间与状态可合并为一组，空间不足时自然换行。保留必要名称、状态、错误和至少 44px 的操作区域，不靠缩字或裁切提高密度。
- 列数依据实际内容区宽度变化，计入侧栏和容器内边距；窄屏减少列数直至单列。网格按从左到右、从上到下排列，视觉顺序与 DOM、键盘顺序一致。同类项对齐，最后不足一行时保留正常列宽，不强制拉伸末项，也不伪造占位卡。
- 合理留白可以保留：空数据不补装饰性内容，单项奖励不必占满整行。验收同时看卡片内部和整个页面，确认主要内容、筛选与操作形成清楚的排列，不能只检查是否溢出。

具体列数、断点、卡片宽度和间距记录在对应页面说明。当前示例见[舰船损失两列布局](ui/welfare.md)及[奖励卡片布局](ui/exchange.md)，不将这些页面参数升级为全站固定值。

## 文案与术语

- 固定界面文案使用统一词表，中英文同步维护，包含辅助技术标签、状态和弹窗；英语长度增长时允许换行，不靠缩字或裁剪关键状态适配。原始业务数据保持原文，日期格式跟随语言，业务时区保持原约定。语言入口与开发规则见[界面语言](ui/language.md)。

- 标签命名对应用户理解的业务对象；同一个词不能在同一上下文中同时指游戏人物和系统权限身份。内部字段名称不直接决定前端标题。
- 标题只标识分区，状态只表达当前结果，操作用简短动词。删除复述标题、状态或流程的描述，不增加装饰性英文。
- 缺失、未配置、加载中、无权限、失败和零值分别表达；不得把未核实状态展示为成功，不编造默认权限或数据。
- 必要错误说明应包含可执行的恢复方式；有退出、移除或重新确认后果的操作在操作时说明。Tooltip 不能替代必读信息。

## 响应式与状态完整性

### 弹窗一致性

- 表单弹窗复用 `components/ui/dialog.tsx` 的 `Modal`，操作确认复用 `ConfirmDialog`；既有特殊认证流程可保留 Radix 结构，但外层必须使用同一 `ui-dialog-overlay` / `ui-dialog-surface` 样式，不复制遮罩、圆角、阴影和定位规则。业务删除确认不使用浏览器 `window.confirm`。
- 外层统一白色语义背景、12px 圆角、灰色细边框与阴影、同一遮罩浓度和层级；标题统一 18px/600。宽度按内容选择紧凑或表单尺寸，不能把所有弹窗强制拉成同样宽度。
- 标题、可滚动内容、底部操作分工明确。长编辑表单保留可见标题与提交操作，滚动只发生在内容区；不让关闭或提交按钮被长列表挤出视口。桌面内容内边距 24px，手机 20px，至少保留 16px 视口边缘。
- 标准编辑弹窗使用统一关闭图标；确认弹窗优先聚焦“取消”，危险操作用统一 destructive 按钮。保存期间阻止重复提交和意外关闭，失败在弹窗内保留输入和重试入口。
- 支持焦点约束、关闭后返回触发按钮、Esc 退出；下拉展开时第一次 Esc 只关闭下拉。浮层层级允许下拉位于弹窗之上，不能被滚动区域裁切。认证/合并等已有更严格关闭策略继续保留。

### 布局与异步状态

- 侧栏导航样式限定到侧栏，不能用无作用域的 `nav` 选择器影响业务标签栏。标题图标、标题、筛选和操作按职责分组，长标题在图标旁换行。
- 指标金额作为完整读数排版；空间不足先调整列数与标签位置，再在既定字号层级内适配，不任意拆开数字或省略精确值。统计卡同组保持一致尺寸。
- 默认文字按钮允许多行并随内容增高，最小点击高度保持 44px；图标按钮保持原尺寸。弹窗底部操作可换行，正文滚动不能遮住提交和关闭入口。

- 自定义下拉使用统一可访问组件：触发器与展开面板保持同一视觉体系，选中态同时有颜色和勾选标记；支持键盘定位／选择、Esc 关闭及焦点返回。长选项可换行，长列表可滚动，浮层避让视口边缘，不能因卡片 overflow 被裁切。采用组件时保留业务原值和可访问标签，不自行改动选项语义。

- 根据内容可用宽度重排，先换行或改列数，再考虑次要信息折叠；保持语义阅读顺序与键盘顺序一致，不用 CSS 视觉顺序掩盖 DOM 顺序问题。
- 用户名称、ID、状态、日期在窄屏、字体放大和长内容下保持可读；不出现页面级横向溢出。确需横向滚动的数据表必须有明确边界。
- 普通、悬停、焦点、选中、禁用、加载、空、失败、成功状态完整。异步失败保留当前输入和恢复入口，防止重复提交。
- 为异步内容保留合理空间，减少布局跳动；失败时保留与该对象有关、仍可使用的操作。

## 设计验收

- 首先看主要任务能否完成，再检查同组尺寸与对齐、信息顺序、字号与对比、留白和操作层级；不能只以“构建通过”判断设计完成。
- 至少检查桌面、375px、320px，以及短/长名称、一个/多个对象、空/加载/失败/成功状态。多列列表另查断点前后、奇数/偶数记录、末行与中英文长度变化，确认列宽、行高、对齐及页面右侧空间合理。涉及选择列表时检查整组排列与切换后稳定性。
- 验证键盘操作、焦点可见、44px 操作区域和减少动态效果；文字放大时不遮挡关键内容。涉及权限与外部数据时检查异常状态不误导。
- 页面改动同步记录截图或可验证的布局证据、相关行为测试及未覆盖边界，演示数据不能当成真实联调结果。

## 图标优先

根据用户要求，含义明确的常用操作优先使用图标：刷新、搜索、筛选、编辑、删除、导出、关闭、返回等。统一使用 Lucide 图标，不用 Emoji 或混合图标库。

- 图标操作复用 `IconAction`：44×44px 点击区域、明确的中文无障碍名称、鼠标悬停和键盘焦点提示；提示可通过 Escape 关闭。
- 加载时用明确的等待图标、禁用状态及 `aria-busy` 反馈，减少动效模式下也能区分状态。
- 已有明确图标的辅助入口可省略可见按钮文字；导航名称、业务对象、数值、日期、关键状态和错误原因保留必要文字，避免用户猜测图标含义。
- Tooltip 补充操作名称，不能承担必读说明或唯一的错误提示。复杂业务操作仍使用短文字标签。
- 新页面沿用此规则，既有 Corporate Clean 配色、圆角、焦点和动效约束继续适用。

## 图表、报表与数据组件


用户已明确要求图表等组件符合整体样式。此规则覆盖图表、统计卡片、报表表格、筛选栏、图例、提示框、导出按钮及加载/空/错误状态。

- 适合比较、占比或趋势的数据优先用图表呈现，操作与状态用统一图标辅助；保留必要名称、数值和明细入口。不为减少文字把未知数据画成零，也不在没有时间序列时虚构趋势线。

- 统一主题：ECharts 负责绘制，视觉由项目主题决定；不直接沿用其默认调色板、字体、提示框或工具栏皮肤。数据表格与图表外壳共用页面组件和样式变量。
- 配色：主要数据使用品牌蓝色；多序列采用集中定义且可区分的 chart 语义色，同一指标跨页面保持同色。成功、警告、错误保留业务含义，不任意用于普通分类。不为统一而把所有序列画成难以区分的蓝色。
- 字体：标题、图例、坐标轴和提示框沿用全站中文字体及文字层级。轴标签和图例不小于 12px，关键指标使用全站数字样式；统一日期、百分比、千分位及 ISK 单位格式。
- 容器：复用白底、灰色细边框、rounded-lg/xl、shadow-sm 和统一内边距；绘图区透明并融入卡片，避免重复套卡片或叠加厚重阴影。
- 图形：采用二维图表、克制的线条及浅色辅助网格；柱条圆角与全站风格协调。禁用装饰性 3D、霓虹、发光和高饱和度彩虹主题。
- 提示框与图例：提示框使用全站浮层的背景、边框、圆角、阴影及字体；图例用颜色标记配合文字，间距和选中状态统一。数据提示框不套用按钮按压缩放规则。
- 操作区：日期范围、筛选、刷新和导出使用项目表单及按钮组件。图表工具操作也封装为统一工具栏，不直接显示另一套默认图标和交互皮肤。
- 动效：控件反馈 150ms ease-out，图表数据过渡最多 200ms ease-out；不使用弹簧、长时间入场或循环装饰动画。减少动态效果开启时关闭图表动画；大量数据或频繁刷新时可关闭数据过渡，保障读数稳定。
- 状态：统一加载骨架、无数据说明、失败重试和统计更新时间。零值与无数据明确区分；加载时保留容器尺寸，避免页面跳动。
- 可读性：除颜色外，还用系列名称、标记或线型区分数据；提供可访问的数据摘要或明细表。触屏和键盘用户也应能获得关键读数，不依赖鼠标悬停。

实现时建立共享图表主题、配置生成函数和容器组件；页面只提供数据、指标名称、单位及必要的业务配置。Canvas/SVG 的颜色和字体从统一主题解析为绘图库可用的值，不在各页面重复写固定色值。维护主题时同步更新图表配置。

验收在真实页面中检查图表与表格、筛选栏及卡片是否一致，覆盖多序列、长中文标签、小屏和各类数据状态。当前已在令牌桶观测实现共享 ECharts 柱状比较组件与主题；其他图形与多序列图表在对应业务交付时验收。

## 冲突处理

1. 遵循用户当前明确要求；可复用原则更新本文，页面需求与参数更新对应页面记录。
2. 视觉执行本文记录的 Corporate Clean 基准与明确适配。
3. 本机 Skill 补充未规定事项，其自动搜索结果仅作为建议。
4. 新发现的实质冲突应明确说明并记录处理，不能声称同时严格满足互斥要求。

本项目不修改或卸载全局 Skill，也不因普通界面开发自动启动 Product Design 的三方案探索流程。技术组件选择继续以 `tech-stack.md` 为基线。
