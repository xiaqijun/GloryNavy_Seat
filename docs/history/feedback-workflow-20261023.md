# 反馈完整流程

用户先指出奖励配置按钮位置及状态办理不清楚，随后明确要求完整流程，并选择“完成后由提交人确认，可退回继续处理”。此前仅排版的方案未单独发布，本轮一起交付。

提交 → 管理员采纳/不采纳 → 开始处理 → 提交完成 → 提交人确认。待确认可由拥有者说明原因退回，完成可重开、关闭可重提；管理员不能代确认或办理本人反馈。通过原 messages API 的锁、版本和幂等检查合法跳转；普通回复不改变状态。首次采纳发币规则及冻结额沿用 Goose 104，不在重试、退回、重开、迁移或账号合并时重复发币。Goose 105 仅扩展状态约束，不自动更改历史 resolved 或现有奖励配置。

详情将当前进度和可操作按钮放在历史回复前；每个操作展开说明后确认，必填原因与结果由前后端共同检查。页头提交和奖励设置右对齐，手机单独换行。按原语言词表复用已有英文，新增固定文案同步翻译。退回、重开和重提使用稳定状态消息 ID 作为独立待办提醒引用，普通回复不新增该事件，不自动启用提醒类型。
