# 联盟 PAP 成员昵称修复（2026-10-20）

## 行为与原因

“成员联盟 PAP”列表的成员名称原由宿主直接注入 `identity.MainCharacterNames`，因此即使已在个人账户填写昵称，列表仍显示主角色名。

宿主现批量读取 `community.Nicknames` 并优先采用非空昵称，缺失或仅空白时回退主角色名。名称按当前账户资料读取，本月与历史月份一致；修改昵称后重新请求列表即可生效，不等待 PAP 同步。角色明细继续使用源快照中的游戏角色名。

仅修改后端名称装配；API 字段与前端结构不变，无数据库迁移，不改变账号归属、积分合计、达标判断或兑换流水。原管理员鉴权和角色有效绑定复核在名称读取前执行。SQL 保留在身份与社区各自私有 store 中。

## 影响与验证

- GitNexus 已重新建立索引；`attendanceHandler` 的直接调用方为 `app.New`，`app.New` 的生产直接调用方为服务器 `run`，影响分析均为 LOW。应用装配链包含多模块，使用接口测试、权限测试和完整服务端构建验证其兼容性。
- 在隔离 PostgreSQL 测试库中，新接口回归对未修改程序失败：昵称应为“舰队长”时返回 `Main Pilot`，确认复现原问题。
- 修复后接口回归通过：昵称优先、缺少资料/空白值回退主角色、本月/历史月、昵称修改后重读、多角色积分合计、角色原名保留、匿名/非管理员/撤权后拒绝。
- 隔离数据库中共 7 项定向测试通过（含 race）：5 项宿主接口/权限/连接/健康测试，2 项联盟成员绑定复核及历史月份兑换测试；`go vet`（app/attendance）与 `go build ./cmd/server` 均通过。
- 实际浏览器连接工具超时，不能将其写成登录后页面实测；前端仍直接使用接口 `member.name`，未修改布局或静态资源。
