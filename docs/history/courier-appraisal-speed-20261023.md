# 快递合同估价提速

2026-10-23 用户确认反馈的是快递页面估价。实际日志近期成功请求 2.5–20 秒，多次在 8 或 28 秒后 503。原客户端每次都 GET 首页取得匿名 XSRF Cookie，再 POST 报价；重复输入也完整重走两次请求。应用机旧源码实测同一合成清单（三钛合金 1 件）依次 12.94、4.32、3.20 秒；首次首页响应头 5.41 秒，报价响应头 7.53 秒。只读估价不会创建游戏合同或本站订单。

## 修改与边界

- 匿名服务方会话复用最多 5 分钟，尊重 Cookie 提前到期；收到明确 403 后下次重新取会话，不自动重放 POST。本站身份、Cookie 和 EVE token 不转发。
- 完整报价在进程内保存最多 60 秒／128 项，用首尾去空白后的 SHA-256 键，不持久化原清单。未知项目与失败结果不缓存，过期不兜底为旧价；修改清单或数量换键。
- 相同请求合并，其他请求仍最多两路，取消一个读者不影响同组其他读者。共享调用最多 28 秒；返回值深拷贝，防止读者修改共享缓存。上游首次查询仍会受网络和第三方行情速度影响。
- 保留原金额、体积、失败项目、Janice URL 验证和主站鉴权/CSRF。无迁移、配置或前端改动，回退只影响速度，不涉及账目。

GitNexus：Appraise 直接调用者仅快递 HTTP 处理器，LOW；Service 结构新增字段关联 NewService、宿主注册及启动，HIGH，已向用户说明并限定修改范围。未修改这些调用者。新 helper 尚不在索引中，手工核对仅被快递估价调用；提交前核对变更范围。

## 验证与发布

已通过 9 项快递模块测试（race），覆盖缓存隔离/上限/过期、会话失效、失败/未知项目、并发合并/取消、两路限制以及既有输入、代理、重定向和响应校验。宿主 `TestCourierSessionCSRFAndModuleBoundary`（race）通过，确认匿名拒绝、CSRF、模块关闭和依赖缺失边界；`go vet ./internal/modules/courier ./internal/app` 通过。宿主测试使用独立临时 PostgreSQL，不读取或写入生产业务数据。

同一应用机、相同代理配置和合成清单，最终修改实测首次 13.56 秒，随后两次服务层调用分别 58 和 19 微秒；后两次没有外部请求。这是服务层耗时，不是浏览器端到端时延。首次仍受上游耗时影响，不能据此承诺首次查询变快。不同清单复用会话、内容改变重新请求及并发合并由上述测试验证。
