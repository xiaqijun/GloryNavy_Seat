# 成员页请求时序检查（2026-09-25）

范围：登录后的工作台、审批、合同、钱包、兑换、考勤、福利、配装、技能、成员与同步页面。依据前端 React Query 的 `queryKey`、`enabled` 和页面挂载关系检查，不把源码审查当作真实用户网络瀑布或生产耗时测量。

| 页面 | 检查结果与本地处理 |
| --- | --- |
| 工作台、审批 | 已发布：审批上下文和工作台列表可并行，授权后预读审批分类及列表下一页；普通成员不预读管理数据。 |
| 兑换 | 果壳币流水从页面上下文等待中解开；订单和奖励列表并行读取。两类列表有游标时各预读一页。 |
| 钱包 | 钱包归属仍需先从授权范围取得；选定角色/分部后余额与记录并行。流水/交易页签预读另一页签的首屏，当前筛选的记录预读下一页。 |
| 合同 | URL 指定对象时，范围与列表/详情原已并行；默认对象需先取得授权范围。列表现按相同对象和筛选预读下一页，详情原有指针/焦点预读保留。 |
| 考勤 | 活动列表和军团 PAP 的当前结果分别预读下一页；活动、在线、联盟 PAP 仍按所选子页读取。 |
| 福利 | 军团范围由上下文决定；确定军团后，本人记录与军团规则上下文并行，管理员全部范围仍等权限上下文。记录按当前业务类型和范围预读下一页。损失详情的市场报价仍在选中报告后读取。 |
| 配装、技能 | 个人角色或军团方案 ID 来自已授权上下文，后续列表/快照必须等该 ID；搜索或展开时才读取的低频数据仍按需加载。 |
| 成员、同步 | 列表按筛选和分页按需读取；同步目标有短周期轮询，未增加后台预读以免和 ESI 任务/观测流量竞争。 |

这些 HTTP 调用原本就是浏览器的异步 `fetch`，但 React Query 的 `enabled`、父组件挂载和分页点击决定发起时机。所谓并行仅消除不必要的前端等待；每次请求仍由服务端同步执行原鉴权和查询，预读不是 River 后台任务，也不会绕过 ESI 缓存。预读仅当前已打开页面的一页，缓存默认 30 秒；筛选、用户、角色、军团不同使用不同查询键，操作失效仍须刷新。首次访问还受会话、权限、对象范围、CDN 链路与具体 API 耗时影响，需真实授权会话实测首屏和翻页。

验证：前端构建与 lint 通过。相关桌面/手机浏览器回归首次 154 项中 149 通过、1 跳过；4 项失败来自快速切页测试在合法弹窗打开时错误要求背景可点击，以及登录语言测试模拟了旧 `/eve/status` 而非当前 `/eve/login-status`。修正夹具后这 4 项与新增的“奖品列表延迟 500ms 时订单先发起”测试共 6/6 通过。未用模拟接口结果宣称生产真实耗时改善。

发布：`v0.1.0-member-page-prefetch-20260925` 已切至公网前端；正式域名和源站的首页、登录、工作台、审批、钱包、合同、考勤、福利、兑换及新哈希资源均为 200，匿名模块目录为 401。真实浏览器登录表单、SSO 跳转、CSRF 与匿名隔离脚本通过。后端与数据库未变；待用真实成员会话比较首屏和翻页时间。
