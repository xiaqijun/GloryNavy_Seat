## 登录后页面补测（代码已发布，真实成员测量待完成）

补测了生产前端静态资源对应的 12 个成员入口：工作台、审批、考勤、配装、技能、损失、钱包、合同、兑换、福利、奖励库与同步。浏览器只用**模拟会话和空/失败的业务 API** 验证前端代码下载、路由挂载及请求路径；没有读取真实成员数据，不能据此判断真实列表接口或大数据渲染耗时。生产资源中，各入口冷加载 JS 约 200–252 KiB；每个入口约发起 3 次会话请求，工作台还发起 2 次模块目录请求。所有入口均到达对应页面，模拟状态下没有页面异常或 50ms 以上主线程任务。

本地修订后，用生产构建版在相同模拟夹具下重测上述 12 个入口：每页仅发起 1 次会话与 1 次模块目录请求，页面正常挂载；仍保留每分钟会话续期及切回窗口时的会话复核，后端每次业务请求的鉴权不变。会话查询设置 30 秒新鲜期，避免页面内部重复观察者在挂载时重复读取；工作台与成员外壳共用同一个全站模块目录缓存键。开发模式的严格挂载初次进入可能多于一次，桌面/手机导航回归确认从工作台切到“我的角色”不会新增会话或目录请求。

审批中心列表原先随首屏加载福利和兑换详情表单；改为打开单据时才下载。相同本地预览、模拟空列表下，审批入口 JS 从约 243 KiB / 44 个文件降至 209 KiB / 30 个文件。这个数字是**本地构建前后**对照，不与上表公网冷加载耗时比较；详情首次打开会补载所需表单代码。最终构建、lint、入口/审批/权限的桌面与手机 54 项回归通过，包含列表分页、详情关闭及审核表单。

原 Edge 已登录页面快速切换卡顿未在故障浏览器中复现或定位。当前浏览器控制连接不可用，真实生产授权页面的 API 瀑布图、审批大量记录渲染与 Edge 交互仍列待验证；模拟测试不视为修复该故障。

后续已处理工作台钱包的请求扇出：原先先读范围，再对**每个**可查看角色分别请求余额和当月流水（至少 `2 × 角色数` 个后续请求，流水还可能继续翻页）；本地改为一条 `/wallet/summary` 请求，服务端在现有绑定/凭据/scope 过滤后批量读取本地余额和当月流水。所有角色仍参与合计，列表仍只展示前三。Go 数据库回归覆盖跨账号隔离、撤 scope、金额字符串及同一流水多版本只计最新；工作台桌面/手机 24 项浏览器回归通过。此处是请求数量与结构优化，**尚无真实生产账号的耗时 A/B**。工作台的审批、果壳币、联盟 PAP、钱包和最近兑换仍各自启动并按 30–60 秒轮询；钱包详情、合同和技能等页读取对象范围后再取所选对象，是权限边界所需的串行步骤。下一轮优先量测多角色工作台和大审批列表的真实响应时间及渲染成本。

## 首次进入未访问菜单

原侧栏仅在鼠标停留或键盘聚焦 180 毫秒后预载目标代码；直接点击此前未打开的菜单仍需等待页面 JS 分块下载与解析，然后再等待该页业务数据。新增登录且权限目录已确认后的空闲预热：仅按当前可见菜单，优先同组，一次加载一个页面代码分块，分块完成后间隔 250 毫秒；后台标签页暂停。指针按下或键盘确认时也立即启动目标预载。预热不调用未访问页面的业务 API，保留按需鉴权和 180 毫秒悬停策略，避免快速扫过菜单时并发加载大量代码。

本地 build、lint、91 项单元测试，以及桌面/手机权限与空闲预热浏览器回归通过。回归证明普通成员只预热可见页面代码，未加载管理员奖励库代码或未访问页面的目录数据。首次页面数据仍由实际打开的页面请求，真实网络下的首次业务加载时间尚未量测；Edge 历史卡顿也没有因此认定为已修复。

该前端调整已发布为 `v0.1.0-menu-warmup-20260924`，后端/Goose 未变。生产检查确认新页面分块可访问、五个入口返回 200、三个私有运维元数据接口匿名返回 401；本机 DNS 未能直接解析站点，因此该轮未跑生产真实浏览器登录检查。此前版本的登录检查结果不能冒充本次验证。

## 数据加载追加排查（2026-09-24）

生产应用已有按路由计时的 HTTP 日志。最近两小时样本中，审批队列 49 次平均 396ms/P95 491ms，在线统计 5 次平均 952ms/P95 2206ms；多数其他业务接口在服务端为几十毫秒。此处是应用层时间，不包含浏览器→CDN→公网机及反代→ZeroTier 建连。单独测量公网机本地反代到 API 的匿名请求 30 次，修改前首字节中位数 77ms、P95 1318ms、最大 2125ms；应用机本地同接口约 1ms。配置原为直接 `proxy_pass` IP，虽设置 HTTP/1.1 和空 Connection 头，但没有 Nginx upstream keepalive 池。启用 32 条空闲上游连接后，同口径 30 次中位数 41ms、P95 277ms、最大 282ms。公网首页及五个页面入口 200、匿名私有元数据 401；这证明了本次反代变更正常，但样本量小，不能推断所有成员页面的改善幅度。

前端成员区原先会话完成后先取模块目录，再根据模块目录决定是否读取 `/access/me`；两项受保护读取现并行启动，后端仍分别鉴权。桌面/手机权限回归覆盖目录延迟期间权限请求已发出、普通成员不可见管理菜单、只预热可见页面。生产前端为 `v0.1.0-data-firstload-20260924`，后端/Goose 未变。

剩余链路：本机通过 EdgeOne 域名访问并复用客户端连接时，匿名 API 首字节多次约 0.5–0.9 秒；直连公网机相同条件常见约 0.08 秒。本机的公网路径与真实玩家地区、浏览器、授权数据不同，不能据此给所有页面承诺耗时；仍需用真实成员会话量测各页面请求瀑布图，重点区分 CDN 往返、审批列表与在线统计的应用耗时。当前没有改 DNS/CDN 供应商配置，也没有缓存受保护业务响应。

随后发现空闲菜单预热可能与正在加载的当前页面争用网络：`v0.1.0-data-priority-20260924` 在 React Query 仍有活跃业务请求时暂停下一项后台代码预热，数据请求结束后恢复。桌面/手机 10 项浏览器回归覆盖阻塞当前页面数据时不会启动其他菜单分块；构建和 lint 通过。它是资源优先级调整，未测得真实玩家业务数据耗时降幅。

继续检查两台机器的 1Panel 与实际请求路径：公网机 1Panel OpenResty 承担站点反代，原本已有 HTTP/2、静态资源缓存、JS/CSS gzip 与上游 keepalive；应用机的本站服务直连 Go 进程和独立 `glorynavy-production-db-1`，并不经过应用机 1Panel 自带 OpenResty/PostgreSQL。公网机站点现增加不含 query/Cookie 的分段耗时日志和 JSON gzip，配置通过 `nginx -t` 并已备份；公开活动接口响应验证为 `Content-Encoding: gzip`，匿名私有接口仍 401。新日志中一次公开活动接口请求 `rt=8.037`、`uct=0.000`、`uht=8.036`，延迟发生在上游应用或其外部数据源，不是该请求的反代建连。该接口单次样本不能代表其他页面。ZeroTier 两端为直连、约 35ms，短时 ICMP 样本有丢包且公网 underlay 也有丢包；尚不足以证明 MTU 设置有问题，因此未调整 MTU、数据库内存或 CDN 缓存规则。下一步需结合真实成员请求、站点分段日志和应用路由日志定位慢查询及外部数据源。

2026-09-25 该站点迁入公网机 1Panel“网站”列表后，配置与分段访问日志改由 `zz-glorynavy-seat` 站点目录管理；旧手工配置已停用。`/api/` 反代随后拆入面板可识别的 `proxy/api.conf`。曾短暂试用直写 ZeroTier IP，公网机本地匿名 API 常见耗时由约 41ms 增至约 76ms，因此恢复 keepalive 命名上游，并把上游文件纳入同站点面板可读的“负载均衡”目录，唯一成员明确为 `10.233.53.209:18080`。该短样本不代表全部成员页面；网站仍为静态类型，因为 React 前端在公网机本地托管。当前仍需按分段日志与应用日志量测真实成员请求。
